**사전 진단 게이트는 실패했다.** 전체 20사례의 경로는 8/20으로, 여기에는 모델 호출이 전혀 없는 ES19·20의 결정적 일반 경로 2건이 포함된다. 현재 제품의 관찰된 위험 8사례 중 6건은 즉시 안전 우선 경로를 놓쳤다. 다른 출처의 관찰 위험만 있는 8사례 중 3건은 안전 우선으로 잘못 보냈다. 출처가 불명확한 ES17과 발생이 불확실한 ES18은 모두 안전 확인 대신 일반 접수로 갔다. ES10은 위험 주체 인용이 원문에 고정되지 않아 계약 오류로 거부됐으며, 안전 확인 경로로 처리됐다. 두 사건이 있는 ES06·15의 최종 경로는 1/2였다.

같은 20사례의 [v4 결과](nlu_safety_event_source_v4_exploration_result.md)는 경로 7/20이고 이번 조건은 8/20이다. 짝지어 보면 ES13 한 건이 오답에서 정답으로 바뀌었고, 기존 정답 7건은 유지됐으며, 12건은 두 조건 모두 오답이다. **1건의 차이를 정확도 개선율이나 1단계만의 인과 효과로 해석하지 않는다.** 이번 실행은 1단계를 제거하고 정답 사건·발생 상태를 공급했으며 모델 요청 수와 경로 결정의 입력도 달라졌다. ES06은 이번 조건에서 두 사건의 출처 관계와 경로가 맞았지만, 위험 주체 원문 구절은 두 사건 모두 검수 구절과 엄격 일치하지 않았다. 경로 일치가 모든 추출 근거의 일치를 뜻하지는 않는다.

2단계 출처 판단 자체에 남는 실패가 분명하다. ES01·03·04·05·07·08은 현재 접수 제품의 위험을 `other`로 분류했다. 반대로 ES11·12·15는 다른 출처 위험을 `current`로 분류했다. ES17의 출처 불명과 ES18의 발생 불확실 위험도 각각 `other`로 처리했다. 위험 주체 인용의 문자 단위 엄격 일치가 0/19였다. 유효 출력 18건의 인용 구절은 모두 검수 구절과 엄격 일치하지 않았고, ES10은 인용 계약 오류였다. 이 수치를 모든 출처 언급이 의미상 틀렸다는 의미로 해석하지 않는다. 출처 관계 오류와 원문 구절 경계 오류를 분리해 후속 후보를 설계해야 한다.

총 19회 요청했고, 요청 지연 중앙값은 7,380ms, 95백분위는 8,039ms다. 사례 전체 지연은 중앙값 7,347ms, 95백분위 8,039ms다. 무호출 사례 2건이 사례 지연 집계에 포함되므로 요청 지연보다 사례 중앙값이 낮을 수 있다. 모델 로드 시간은 포함하지 않는다. 1단계 요청과 모델 추론 일부를 생략한 조건이어서 v4의 종단 지연이나 실제 서비스 속도 개선으로 비교하지 않는다.
