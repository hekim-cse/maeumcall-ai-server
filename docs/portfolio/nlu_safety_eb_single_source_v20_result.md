# A/S 번호 근거 단일 질문 개발 대조 결과

[사전 방법](nlu_safety_eb_single_source_v20_method.md)의 코드는 `19743f0`, [프로토콜](../../evals/structured_nlu/data/ai_heldout/as-safety-eb-single-source-v20-protocol.json)은 `4874cc2`에 고정했다. 같은 Qwen2.5-1.5B-Instruct Q5에서 [v19](nlu_safety_eb_evidence_model_comparison_v19_result.md)의 정방향 네 요청과 비교했다. 원문 후보와 사건 E, 후보 B, 출처 번호 선택지는 유지했다. 사용자 지시의 범위와 응답 스키마 필드 수를 함께 바꿨다.

| 지표 | v19 세 질문 | v20 출처 질문 하나 |
| --- | ---: | ---: |
| 정답 출처 문장 후보 포함 | 1/1 | 1/1 |
| 정답 출처 문장 선택 | 0/1 | 1/1 |
| 출처 공란 정답에서 공란 유지 | 3/3 | 0/3 |
| 출력 계약 통과 | 4/4 | 4/4 |

v20은 네 후보에 모두 2번을 반환했다. PC01/P014의 출처 근거는 2번이고, 나머지 세 후보는 출처 근거가 공란이어야 했다. 2번은 네 요청 모두 사건 E가 들어 있는 문장이다. 이번 대조로 모델이 고정 숫자 2를 선호했는지, 사건이 나온 문장을 출처 판정의 근거로 혼동했는지는 구분할 수 없다. 출처 근거 항목만 채점했으며 배제·불확실성 근거와 관계 전체 점수는 평가 범위에 포함하지 않았다.

전송·계약 오류와 재시도는 0건이었다. 원시 응답을 저장소 밖에 보관하고 재생으로 해시 및 선택을 확인했다. [공개 저널](../../evals/structured_nlu/data/ai_heldout/as-safety-eb-single-source-v20-journal.v1.jsonl)의 SHA-256은 `2866d8b2138066b58d0bad1e08bfe0edd94da71554e9d4b44d8f91a0b6cbceb5`다.

사전 관문 미통과로 이 후보를 확대하지 않는다. 단일 질문은 기존 전건 보류를 바꿨지만 이번 네 사례에서 출처 구별은 회복하지 못했다. 고정 번호와 사건 문장 선택의 차이를 추가로 진단하려면 문장 내용과 순서를 유지하면서 표시 ID만 대조할 수 있다. 기노출 네 쌍의 결과이며 서비스 성능의 근거로 사용하지 않는다.
