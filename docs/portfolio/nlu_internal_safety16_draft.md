# 새 A/S 안전 표본 16건: 검수된 문장·방향

> **실모델 실행 전 AI 작성 안전 문장 검수 기록.** SS01–SS16은 고객센터 `A/S 접수`의 시작 상태 `greeting` 사례다. 사용자가 [SS15·SS16 교체 문장](nlu_internal_test80_independence_revision_review.md)과 SS13 공란 수정까지 채택했다. 이후 데이터 동결·원문 재검사·[실모델 평가](nlu_internal_test80_verified_result.md)를 완료했다. 아래 사람·제품·상황은 모두 가상이다.

## 위험의 발생 여부 또는 출처가 아직 불확실한 경우: SS05–SS08

## 평가 경계

- 사용자 검수에서 SS04의 호스는 접수 제품의 부위, SS03의 액체 누출은 직접 위험으로 채택했다. SS06·SS08처럼 불확실한 출처에 필요한 현장 안전 안내는 별도 평가 대상이다.
- SS09–SS12는 실제 위험 사건이 있더라도 **접수 대상의 사건**인지 따로 묻는다. 위험 주체가 다르다는 사실과 현장 전체의 위험성은 다른 판단이다.
- SS13–SS16은 미발생·부정 표현이 있어도 고장 접수 자체는 유지된다. `unknown`으로 일괄 처리하지 않는다.
- 기존 노출 안전 사례와 가까운 상황을 독립 검토에서 찾아 SS02·SS08·SS09·SS11·SS12·SS15·SS16을 교체했다. 교체 문장의 원문 일치·의미 근접도와 최종 데이터의 중복 점검은 [노출 점검 기록](nlu_internal_test80_exposure_audit_v1.md)에 남겼다. 정확 일치 검사는 의미상 가까운 바꿔쓰기를 배제하지 못한다. 평가 날짜에 따라 변하는 달력 날짜는 넣지 않았다.
- 사용자 문장·방향 및 전체 필드 검수, 중복·계약 재검사, 코드·데이터 동결 후에만 모델에 실행했다.
