# A/S 안전 출처 연결: 원문 근거 인용 개발 계획

## 검증할 가설

[기존 단일 개체 연결 진단](nlu_safety_entity_link_diagnostic_result.md)은 검수된 접수 대상과 위험 주체 구절을 입력해도 다른 출처 6건 중 1건만 분리했다. RE09·RE11은 별도 기기를 현재 제품으로 잘못 연결했고 V02·V06·V08은 관계를 확정하지 못했다. [계층별 감사](nlu_safety_layered_failure_analysis.md)에서는 이 오류 중 3건이 현행 선행 안전 가드 패턴과 겹쳤다. 다음 가설은 **관계 판단과 함께 두 구절의 연결을 뒷받침하는 원문을 인용하게 하면, 타출처를 확정하면서 현재 제품 위험을 보호할 수 있는가**이다. 인용이 원문에 있다는 사실은 관계의 의미적 정답을 증명하지 않는다.

## 개발 조건과 평가 경계

- 먼저 이미 여러 번 노출된 AI 작성·사용자 검수 RE/V 22건만 사용한다. 접수 대상과 위험 주체의 검수 구절·문장 번호는 모델에 제공하는 오라클 입력이며, 발생 상태·관계 정답·안전 경로는 제공하지 않는다. GB01–GB24는 후보 개발, 프롬프트, 테스트, 실패 분석에 사용하지 않는다.
- 출력은 유한한 관계 코드와 최대 두 개의 원문 근거로 제한한다. 서버는 문장 번호, 구절의 연속·정확 일치, 접수 대상과 위험 주체 구절이 근거에 포함되는지만 확인한다. 근거 형식이 성립하지 않으면 보류한다. **형식 검사는 소속 관계의 진실성을 판정하지 않는다.**
- 실행 저널에는 발화와 인용 본문을 저장하지 않는다. 인용 문장의 번호, 문장 안 시작·끝 위치와 인용 해시를 기록하고, 독립 검증기가 고정 입력에서 원문 구간을 재구성해 해시와 두 검수 구절의 포함 여부를 확인한다.
- 기존 Q5와 같은 사례·모델·요청 설정에서 개발 진단을 실시한다. 코드·입력·모델·요청 정책·사례 순서·검증기 해시를 첫 호출 전에 커밋과 실행 규약으로 고정한다. 사례마다 한 번만 호출하고 중단·오류를 자동 재시도하지 않는다. 원문·모델 응답 본문은 결과 저널에 저장하지 않는다.
- 이전 17/22와 나란히 보더라도 프롬프트와 출력 계약이 달라진다. 점수 차이를 근거 인용의 인과 효과나 정확도 개선율로 해석하지 않는다. 두 조건을 같은 설정으로 다시 실행해도 계약 차이는 남는다.
- 현재 제품 `current` 16건, 다른 출처 `other` 6건의 정확한 관계, 거짓 현재 제품 판정, 보류, 계약·통신 오류를 별도 집계한다. 현재 제품 중 관찰된 위험 13건과 V01/02·V05/06·V07/08 대비쌍도 따로 본다. 검수된 발생 상태를 사후 결합한 경로는 **오라클 파생 경로**로만 표시한다. 현행 선행 가드 패턴과 실제 서비스 그래프 실행은 이 모델 점수에 섞지 않는다.
- 사전 개발 게이트는 현재 제품 최소 15/16, 관찰된 현재 제품 위험 13/13, 다른 출처 6/6, 세 대비쌍 모두 올바른 반전, 호출·계약 오류 0/22다. 한 조건이라도 실패하면 후보를 기각하고 GB를 실행하지 않는다. 통과하더라도 검수 구절 없이 원문에서 직접 추출하는 별도 개발 과제를 통과해야 GB로 넘어갈 수 있다.

이번 단계는 포트폴리오의 공식 정확도나 개선율을 만들기 위한 평가가 아니다. 개발 후보의 원문 근거와 실패 이유를 재현 가능하게 남기는 단계다.
