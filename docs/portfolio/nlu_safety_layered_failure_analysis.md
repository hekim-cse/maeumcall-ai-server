# A/S 안전 출처 오류의 계층별 분석

## 범위

[기노출 RE/V 22건의 Q5 개체 연결 진단](nlu_safety_entity_link_diagnostic_result.md)과 현행 서비스의 [선행 위험 문구 가드 감사](../../scripts/audit_as_safety_pre_model_guard.py)를 ID로 결합했다. 이 결합은 새 모델 호출이나 실제 LangGraph 실행이 아니다. 모델 진단에는 사람이 검수한 접수 대상·위험 주체 구간이 입력됐으며, 그 경로는 검수된 발생 상태를 사후 결합한 **오라클 파생 경로**다. 선행 가드 패턴의 일치는 확인했지만 각 발화가 실제 서비스에서 가드 적용 상태에 도달하는지는 측정하지 않았다. GB01–GB24는 이 분석에 사용하지 않았다.

재현 명령은 저장소 루트에서 `.venv/bin/python -m scripts.audit_as_safety_layered_failure`이다. [결합 감사 코드](../../scripts/audit_as_safety_layered_failure.py)는 입력·가드 코드·고정 저널의 SHA-256을 출력하고, 기존 독립 검증기로 모델 저널의 순서·분모·해시·오류 상태를 검증한 뒤 결합한다. **모델 저널은 실행 전 프로토콜로 고정했지만, 가드 정규식은 이 사후 감사 시점의 코드로 다시 실행했다.** 출력 해시는 그 버전을 식별하며 이전 모델 실행 당시의 실제 가드 호출을 증명하지 않는다.

## 관찰된 두 실패 층

| ID | 접수 대상 ↔ 검수된 위험 주체 | Q5 관계 판단 | 선행 가드 패턴 | 구분 |
| --- | --- | --- | --- | --- |
| RE09 | TV ↔ 오래된 멀티탭 | `other → current` | 일치 | 다른 기기를 현재 제품으로 잘못 연결 |
| RE11 | 세탁기 ↔ 욕실 전등 | `other → current` | 일치 | 다른 기기를 현재 제품으로 잘못 연결 |
| V02 | 공기청정기 ↔ 가습기의 전원선 | `other → unknown` | 일치 | 별개 기기 관계를 확정하지 못함 |
| V06 | 제습기 ↔ 선풍기 본체 | `other → unknown` | 불일치 | 별개 기기 관계를 확정하지 못함 |
| V08 | 믹서기 ↔ 전기레인지 바닥 | `other → unknown` | 불일치 | 별개 기기 관계를 확정하지 못함 |

다섯 건 모두 검수 정답은 **다른 출처의 실제 위험**이며 접수 제품의 A/S 기대 경로는 일반 접수다. 모델 관계 오류 5건 중 3건(RE09·RE11·V02)이 선행 가드 패턴과 겹친다. 기존 32건 가드 감사의 패턴 일치 5건은 이 22건에도 모두 포함되며, 그중 RE09·RE11·V02의 접수 제품 경로를 즉시 안전 상태로 강제하면 기대 경로와 어긋난다. V01·V05는 현재 제품의 실제 위험으로 기대 경로와 맞는다.

모든 22건이 가드 적용 상태였다고 **가정**하고, 일치 건은 선행 가드가 즉시 안전 상태로, 미일치 건은 이번 Q5 오라클 파생 경로로 보낸 가상 조합에서는 직접 경로 오판 3건, Q5 진단 경로 대비 변경 1건(V02), 오라클 파생 경로 일치 17/22다. 직접 경로 오판 3건은 Q5만으로도 직접 경로였던 RE09·RE11 **2건**과, 가드 가정을 더할 때 새로 직접 경로가 된 V02 **1건**이다. 이는 실제 서비스 성능이 아니다. 실제 그래프의 가드 적격 상태와 미일치 건의 서비스 추출 결과는 이 조합에서 실행하지 않았다. RE09·RE11의 모델 오분류와 가드 패턴 일치를 같은 원인이나 두 건의 독립 오류로 더해 세지 않는다.

## 다음 설계의 판단 근거

현재 서비스는 위험 문구를 감지하면 출처 판단 전에 `safety_status=safety_issue`로 바꾸고, A/S 일반 진단·접수를 중단하는 상태로 이동한다. 다른 기기에서 실제 위험이 발생했다면 그 기기에 관한 안전 안내는 필요할 수 있다. 그러나 그 사실만으로 **접수 대상 제품**의 A/S 절차를 중단해야 하는지는 별도 판단이다. 다음 후보는 이 두 결정을 구분해 설계해야 한다.

우선 원문에서 접수 대상, 위험 사건 주체와 **동일 지시·소유·부품 관계의 근거 구절**을 함께 추출하는 작은 계약을 개발 사례에서 시험한다. 모델이 적은 관계 코드만으로 현재 제품 여부를 확정하지 않고, 서버가 인용 구절의 원문 앵커와 관계 근거를 검사한다. 근거가 불명확하면 접수 대상 관계는 보류하되, 실제 위험에 대한 일반 안전 안내를 별도 처리하는 설계를 검토한다. 이 방향은 아직 구현·검증한 서비스 정책이 아니다.

다음 실험도 먼저 기노출 RE/V에서 현재 제품 관찰 위험의 즉시 보호, 다른 출처의 A/S 오분기, 출처 불명의 확인, 계약 오류, 대비쌍 반전을 **각각** 기록한다. 정답 구간을 입력으로 주는 오라클 하위 과제와 원문만 주는 추출 과제는 별도 분모로 평가한다. 개발 게이트를 통과한 후보가 생기기 전에는 검수된 GB 24건을 모델에 실행하지 않는다. 이 분석의 5/22 오류와 조건부 조합을 공식 전체 정확도나 개선율로 쓰지 않는다.
