# 내부 test 프로토콜 실행 전 정정

> **실모델 호출 전 정정 기록.** 아래 두 프로토콜은 한 번 커밋하고 모델 호출 없이 사전 검사를 통과했다. 이후 안전 16건의 확인 명령이 일반 test의 `scope` 문자열을 출력하는 표시 오류를 발견했다. 프로토콜 자체의 `scope`와 평가 분모는 올바랐으나, 실행 전 혼동을 없애기 위해 확인 출력을 수정하고 소스 해시가 포함된 두 프로토콜을 다시 계산했다. 이전 프로토콜로 시작한 평가 실행은 없다.

| --- | --- | --- | --- |
| 일반 test 64건 | `96e3751aa7b5d816e7aab85941ab8aff1bf22cd185c079fe39832ef3e87dd90c` | `9756af64466c5edae8ce85c4cc00c105a4c6fcb68266ea866773644995fb9984` | 확인 출력 수정이 평가 도구 소스 해시를 바꿔 재고정 필요 |
| 별도 안전 16건 | `77356a66b257eb1a713027c59e7420f2eb32a83a2e447f9f8877c20ce21ecfe1` | `09eabc0caa33e9a274cb44112bb80e9f017e1fdf5c72ef6ad26dee6017ba24af` | 같은 소스 해시 재고정 필요 |

모델 입력 정답은 입력 커밋 `6f601f7d38bcd135a7c368707b08673811b6c981` 이후 수정하지 않았다. 정정 코드 커밋은 `efff603be9642e2b5d30de26bf46fc4bfbff4214`다. 두 프로토콜의 `input_commit`을 이 커밋으로 바꿔 수정된 도구와 기존 입력을 함께 결속했다. 정확도·안전 결과는 아직 없다.
