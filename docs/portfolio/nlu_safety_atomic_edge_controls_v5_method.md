# A/S 위험 주체 추출 양성·음성 대조 진단 설계

> 2026-11-21 실행 전 설계. AI가 작성한 두 문장을 사용자 검수 후 사용하는 **개발 진단**이다. 공식 정확도, 정확도 개선율, 일반화 성능 또는 서비스 안전 경로 성능을 산출하지 않는다.

## 질문과 근거

첫 E→B 진단에서 비공란 B 일치는 0/18이었고, 보류 문구 변경과 주체 단독 요청도 선택한 다섯 ES 사례의 전건 `unresolved`를 바꾸지 못했다. 반면 스키마를 제거한 비교에서는 비공란 문자열이 나왔지만 구절 객체 계약이 5/5 깨졌다. 이 결과만으로는 Q5가 **명백한** 주체조차 현재 두 필드 스키마에서 낼 수 없는지, ES 문맥에서만 주체 연결에 실패하는지 구분할 수 없다.

## 고정 대조군과 요청

- [PC01·NC01 원문·정답](../../evals/structured_nlu/data/ai_heldout/as-safety-eb-controls-v5-cases.json)은 모델 호출 전 사용자 검수로 확정한다. PC01은 선풍기 모터에서 연기가 난 명시적 위치 양성 대조군이고, NC01은 타는 냄새는 관찰했으나 출처를 모르는 음성 대조군이다. 둘 다 AI 작성 개발 사례이며, ES/TX/GB 평가 분모에 섞지 않는다.
- PC01의 정답은 B 원문 구절 `선풍기 모터`와 `location`이다. NC01의 정답은 B 공란과 `unresolved`다. 위험 발생 상태는 둘 다 `observed`다. 타는 냄새의 발생과 **출처 확정**은 별개다.
- Q5에 보낼 입력은 원문·검수된 접수 제품 A·위험 사건 E·발생 상태뿐이다. B·종류 정답과 `gold_*` 필드는 요청에 넣지 않는다. 프롬프트와 두 필드 JSON 스키마는 v4의 주체 단독 조건을 그대로 사용한다. 생성 설정·모델 파일·이미지·자원·로컬 전송 제한도 v4와 동일하게 유지한다.
- PC01, NC01 순서로 각 한 번씩 호출한다. 재시도하거나 부분 실행을 이어 붙이지 않는다. 호출·계약 오류도 해당 행에 기록한다. 두 건의 순서는 조건 비교가 아니라 기능 대조를 위한 고정 순서다.

## 실행 전 고정과 재검증

코드·이 문서·검수 완료된 사례 파일을 먼저 커밋한다. 깨끗한 작업 트리에서 모델 SHA-256과 고정 의존 소스·입력 해시를 확인하고, **정확한 요청 본문 두 개의 SHA-256과 호출 순서**를 프로토콜에 기록해 별도 커밋한다. 그 뒤에만 모델을 호출한다. 실행기는 로컬 Docker 컨텍스트·소켓과 컨테이너 이미지·모델 마운트를 확인한다.

공개 저널에는 원문·프롬프트·응답을 넣지 않는다. 원시 응답은 저장소 밖 권한 제한 폴더에 보관한다. 독립 검증기는 고정 입력에서 두 요청을 재구성하고 프로토콜·저널·원시 응답의 해시·순서·출력 계약을 대조한다. 저널 파일 전체와 검증기 파일의 SHA-256은 결과 문서에도 따로 남긴다. 리뷰 이후 코드를 고친다면 **실행 당시 코드와 사후 재검증 코드**를 구분한다.

## 사전 지정 지표와 판단

건별 전송·종료 오류, 두 필드 출력 계약, PC01의 계약 유효 비공란·원문 인용 유효성·B 구절 정확 일치·종류 일치, NC01의 유효한 `unresolved`·공란, 근거 없는 비공란 확정을 별도로 보고한다. `모터` 같은 부분 구절이 나와도 사후에 정확 일치로 승격하지 않는다. 정확 불일치만으로 주체를 전혀 찾지 못했다고 단정하지 않고 실제 구절 오류를 제한된 비공개 감사에서 분류한다. 계약 오류는 의미 정답으로 채점하지 않는다. 요청 지연은 기술 기록으로만 남기고 토큰 사용량은 전송 계층에서 수집하지 않는 한 추정하지 않는다.

PC01에서 계약에 맞는 **비공란** B가 나오면, 정확성 여부와 별개로 현재 인터페이스가 비공란을 낼 수 있다는 형식 신호로 본다. PC01의 B 구절 정확성과 종류 일치는 각각 별도의 의미 신호로 보고한다. NC01의 유효한 `unresolved`·공란은 안전한 보류 신호다. PC01이 유효한 비공란이고 NC01이 유효하게 보류하면, PC01의 B나 종류가 틀렸더라도 정답을 보지 않고 원문에서 후보를 만들고 후보 포함률·모델 선택 성능을 분리하는 **새 개발 프로토콜을 설계할 수 있다**. 틀린 B·종류는 그대로 실패로 기록하며 서비스 후보 관문은 통과하지 못한다. PC01이 보류하거나 계약을 어기면 다음 후보 선택 실험으로 넘어가지 않고 비공란 출력을 막는 요인을 추가로 분리한다. NC01에서 근거 없는 비공란을 확정하거나 계약을 어기면 안전 대조 실패로 보고 다음 단계로 넘어가지 않는다. 어느 결과도 스키마·프롬프트·모델 중 하나의 단일 원인을 확정하지 않는다.

이 두 건은 표본 추정이나 기존 19건 개발 관문을 대체하지 않는다. B→A, 실제 안전 조치, 서비스 종단 간 경로는 이번에 평가하지 않고, 현재 안전 가드는 유지한다. 후보가 개발 관문을 통과하더라도 공식 성능은 별도의 사전 고정·사용자 검수 미노출 평가에서 확인해야 한다.
