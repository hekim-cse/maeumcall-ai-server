# A/S 위험 주체 구절 객체 출력 형식 오라클 개발 진단 결과

> 2026-11-21. 이미 검수한 PC01의 정답을 두 방식으로 모델에 제공한 개발 진단이다. 주체 추출 정확도·개선율, 안전 성능 또는 새 사례 일반화 성능이 아니다.

## 고정 실행과 독립 검증

- [실행 전 방법](nlu_safety_atomic_edge_format_oracle_v6_method.md)에 따라 PC01에서 F1(완성된 정답 JSON 제공)과 F2(문장 번호·주체 구절·종류를 평문 제공)를 고정 순서로 각 한 번 호출했다. 두 조건 모두 v4의 주체 단독 기본 메시지·두 필드 JSON 스키마·Q5 생성 설정을 사용했다. 두 프롬프트는 표현이 달라 단일 변수 인과 비교가 아니다. 재시도는 없었다.
- 실행기·검증기·방법은 모델 호출 전 커밋 `355b89c13d0c7a07311e9b84b0b29476a6f6bfe2`에 고정했다. [프로토콜](../../evals/structured_nlu/data/ai_heldout/as-safety-eb-format-oracle-v6-development-protocol.json)은 별도 선행 커밋 `288a686`에 기록했고 SHA-256은 `5a1c111f44e8bdf276d7d9237537aff2e5fe11db4c150d67855dd54405dad1e8`이다. F1·F2 요청 본문 해시와 호출 순서, v5 참조 프로토콜·저널 해시를 모델 실행 전에 고정했다.
- 모델 파일 SHA-256은 `644b04cde835d486df33c6d4d7552ba367fcb28802fe39b6b4bb9c60b9ab6f3d`, 컨테이너 이미지 digest는 `sha256:17155a3ce4cc906728ec99a2814bf0b4eaffaf3b4872bad8c3affed310cdbc35`다. 로컬 컨테이너는 CPU 2개·메모리 4 GiB·127.0.0.1 전용 포트로 실행했다. 실행 뒤 컨테이너와 Docker Desktop을 종료하고 관련 프로세스가 없음을 확인했다. AWS·KT cloud는 사용하지 않았다.
- [공개 저널](../../evals/structured_nlu/data/ai_heldout/as-safety-eb-format-oracle-v6-development-journal.v1.jsonl)은 헤더 1행·호출 결과 2행의 메타데이터만 담는다. SHA-256은 `8e1e3d2d1312c594969d377ddaf1077b0a3db33231310b88d8068cbd96ece518`이다. 원시 응답은 저장소 밖 0700 폴더·0600 파일 두 개에 보관했다.
- 독립 검증기는 고정 입력에서 두 요청을 자체 재구성하고, 프로토콜·저널·원시 응답의 해시와 순서 및 출력 계약·제공 정답과의 일치를 재계산했다. 검증기 SHA-256은 `9019598580cf38e043b5af7b7a1423b259660b0287db6aa5fc006129d9956d15`이다. 관련 테스트 62개와 Ruff 검사가 통과했고 별도 결과 감사에서도 집계가 일치했다.

F1은 제공한 두 필드 객체와 구조적으로 일치했다. 따라서 **이 모델·스키마·전송 경로에서 비공란 구절 객체를 출력할 수 있음**을 이 한 요청에서 확인했다. F2도 비공란 객체와 `location`, 2번 문장 인용에는 성공했지만, 짧은 주체 구절 대신 **문장 전체를 B로 과다 인용**해 정확 B와 전체 객체 일치에는 실패했다. 문장 전체가 원문에 있다는 사실은 주체 구절의 정확성을 보증하지 않는다. F2의 결과를 사후 허용 정답으로 승격하지 않았다.

직전 **정답 미제공** PC01은 유효한 공란이었다. 이번 결과는 출력 객체 형식이 원천적으로 불가능하다는 설명을 약화시키지만, 정답 제공·질문 방식이 함께 달라져 비오라클 보류의 단일 원인을 입증하지 않는다. 이미 [후보 ID 방식 개발 비교](nlu_safety_extraction_v2_probe_result.md)에서는 정답 구간의 후보 포함이 13/18이고 선택 정확 일치는 0/18이었다. [ES 단계 분리 진단](nlu_safety_stage2_ablation_v1_development_result.md)도 기존 후보 생성기가 비공란 B 18건 중 15건만 포함했다고 기록한다. 따라서 같은 후보 ID 방식을 곧바로 반복하지 않는다. 먼저 **기노출 사례에서 후보 누락 원인·후보 수와 순서·정답이 포함된 경우의 선택 실패**를 오프라인으로 분해해야 한다. 개선한 후보를 새 실험에 쓴다면 정답 구절을 후보 생성에 직접 주입하지 않고, 후보 포함률과 모델 선택을 별도 지표로 고정한다.

두 호출 모두 정답을 입력에 제공했으므로 표의 1/1·0/1은 **추출 정확도 분모가 아니다**. 지연도 서비스 속도 개선 근거가 아니며 토큰 수는 수집하지 않았다. 기존 19건 개발 관문, B→A, 최종 안전 경로는 평가하지 않았고 서비스에 연결하지 않았다. TX·GB 봉인 자료는 사용하지 않았다. 이슈 #93의 완료 조건은 아직 충족되지 않았다.
