# A/S 위험 출처 후보 ID 실험의 오프라인 실패 분해 방법

> 2026-11-21. 이미 모델에 노출된 RE/V 여섯 건의 과거 개발 실험을 재분석한다. 모델·Docker를 실행하지 않으며 새 정확도나 개선율을 산출하지 않는다.

## 감사 대상과 질문

[후보 ID 비교의 고정 프로토콜](../../evals/structured_nlu/data/ai_heldout/as-safety-extraction-v2-probe-protocol.v1.json)과 [공개 저널](../../evals/structured_nlu/data/ai_heldout/as-safety-extraction-v2-probe-journal.v1.jsonl)의 RE03·RE06·RE09·V01·V04·V07만 사용한다. 각 사례의 위험 사건 E·발생 주체 B·소속 대상 C를 별도 구간으로 세어 총 18구간을 분모로 둔다. 후보가 **생성되지 않았는지**, 생성됐지만 **192개 상한에서 잘렸는지**, 모델에 제시됐지만 **선택되지 않았는지**를 나눈다.

후보 목록과 정답 후보의 위치를 재구성할 때는 당시 프로토콜이 지정한 고정 커밋 `c0ef14aa25787fc3730b5d38257aaf382e668c99`의 생성 코드를 사용한다. 현재 작업 트리의 생성기에는 이후 공백 처리 변경이 있으므로 과거 실행의 후보 순위와 혼용하지 않는다. 저널의 순서·상태·후보 수·정답 포함 상태·선택 ID·정확 일치 여부를 재구성 결과와 대조한다. 원문과 검수 정답은 고정 입력 해시로 확인한다. 정답 구절은 **원문만으로 후보를 만든 다음** 일치 여부 계산에만 쓴다.

## 보고 항목과 해석

- 사례별 E/B/C의 `not_generated`, `truncated`, `present_but_not_selected`, `selected_exact`와 후보 수·정답 후보 순위·모델 선택 ID를 보고한다. 후보에 있는 구간만의 선택 일치도 전체 18구간과 분모를 구분한다.
- 누락 원인은 당시 생성기의 토큰 창·구두점·조사 처리와 원문 구간을 대조해 기술한다. 확인되지 않은 의미 원인을 추측하지 않는다.
- 정답 후보 순위와 모델 선택 순위는 함께 제시하지만, 여섯 건의 기술통계만으로 위치 편향이나 모델 오판의 단일 원인을 증명하지 않는다. 공개 저널은 원시 응답을 포함하지 않으므로 원시 응답의 재검증까지 했다고 쓰지 않는다.
- V04는 **당시 고정된 정답**으로 감사한다. 이후 사용자 검수에서 접수 대상을 토스터로 다시 해석한 기록은 과거 점수에 소급하지 않는다.
- 별도 ES 자료의 기존 후보 15/18, 후속 원문 후보 생성기의 18/18은 이미 기록된 **후보 포함률**이다. 이번 RE/V의 18구간과 합산하지 않으며 모델 선택 성능으로 해석하지 않는다.

이 감사의 목적은 다음 후보 실험에서 실제로 고쳐야 할 생성·선택 병목을 찾는 것이다. 새 후보를 만들더라도 정답을 후보 생성에 주입하지 않고, 기노출 개발 자료에서 선택한 뒤 새 미노출 사례를 별도 검수·사전 고정해 평가한다. TX·GB 봉인 자료와 최종 안전 경로는 다루지 않는다.
