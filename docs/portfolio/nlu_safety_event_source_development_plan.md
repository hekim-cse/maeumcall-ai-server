# A/S 안전 사건·출처 관계 개발 실험 계획

## 왜 다시 검토하는가

기존 관계 분류와 기준선은 이미 노출된 V06(다른 제품의 연기)과 V09(발생은 관찰했으나 출처 불명)를 모두 틀렸다. 근거 인용 후보는 V의 실제 위험 즉시 보호가 7/8에서 6/8로 줄고 계약 오류가 3건 발생해 [사전 기준](nlu_safety_transfer_development_audit.md)을 통과하지 못했다. 문자열이 같은 제품명이 같은 실체임을 보증하지 않고, 부품명과 발생 위치는 제품명과 일치하지 않을 수 있다. 이 결과는 새 후보의 필요성을 설명하지만 새 방식의 성능 근거는 아니다.

## 독립적으로 검증할 가설

위험 **발생**과 현재 접수 제품으로의 **출처 귀속**을 분리한다. 모델은 접수 대상, 위험 사건, 발생 근거, 출처 관계 또는 출처 불명 근거를 각각 원문 문장 번호로 지목한다. 관계는 현재 제품 자체, 현재 제품의 부품, 명시된 다른 제품, 단순 발생 위치, 대안 출처 또는 출처 불명으로 제한한다. 뒤 문장에서 앞 문장의 귀속을 취소하거나 불확실하게 만들 수 있으므로 발화 전체를 고려한다. 같은 제품 이름의 재등장이나 인용 문자열의 포함 관계만으로 동일 실체를 확정하지 않는다.

발생이 관찰되고 현재 제품 또는 그 부품에 귀속되면 즉시 보호, 발생은 관찰됐으나 출처가 불명확하면 안전 확인, 다른 제품에 귀속되거나 위험이 발생하지 않았다면 일반 수집을 제안한다. 필수 근거가 빠지거나 상태가 모순되면 계약 오류로 기록한다. 이 구조 역시 모델이 잘못된 문장 번호와 관계를 내면 의미상 오판할 수 있다. 독립 검증기는 형식과 기록의 재현성만 보증한다.

## 비교 경계와 중단 기준

- **개발 입력:** 이미 모델에 노출된 AI 작성·사용자 검수 RE01–RE16, V01–V16만 사용한다. 같은 Q5 파일, 컨테이너 이미지, 요청 설정과 순서를 사전에 고정하고 기준선과 후보를 교대로 호출한다. 중단 또는 오류를 조용히 재시도하지 않는다.
- **필수 통과 기준:** V의 현재 제품 실제 위험 즉시 보호가 7/8 이상, 다른 출처 위험의 즉시 보호 오분기가 1/4 미만, V06 일반 수집, V09 안전 확인, 후보 계약 오류가 기준선보다 많지 않아야 한다. 추가로 V07(발생 위치)과 V12(제품 부품)가 즉시 보호인지 확인한다.
- **별도 보고:** RE와 V의 경로 정답 수, 실제 위험 누락, 다른 출처 오분기, 불확실 출처 확인 누락, 계약 오류 및 요청 지연 시간의 중앙값·상위 구간을 각각 보고한다. 작은 개발 집합의 선택 기준 통과를 일반화나 공식 정확도로 쓰지 않는다.
- **전이 경계:** 개발 기준을 모두 통과하고 후보 코드·프로토콜·모델·정답 파일 해시를 고정한 뒤에만 TX01–TX16을 한 번 호출한다. TX는 아직 모델에 노출되지 않았지만 설계자는 문장을 볼 수 있으므로 설계자 블라인드가 아니다. TX 결과를 보고 후보를 고친 뒤 같은 TX를 새 평가로 재사용하지 않는다.

현재 단계의 산출물은 서비스 적용이 아닌 격리된 개발 후보와 탐색 평가다. AI 작성·1인 검수 데이터의 수치를 포트폴리오에 쓸 때도 출처, 분모, 실패 사례, 적용하지 않은 이유를 함께 적는다.
