# A/S 위험 출처 연결 단독 진단 결과

## 질문과 고정 조건

앞선 [출처 근거 진단](nlu_safety_owner_evidence_diagnostic_result.md)에서 다른 출처 6건이 모두 현재 접수 제품으로 잘못 연결됐다. 이번에는 검수된 위험 주체의 원문 구간과 문장 번호까지 모델에 제공하고 `source_relation` 하나만 출력하게 해, **구간 추출과 관계 판단을 분리**했다. 출력 정답인 관계와 연결 종류는 모델에 제공하지 않았다.

이미 모델에 노출된 AI 작성·사용자 검수 사례 중 주체 구간이 있는 22건(`current` 16, `other` 6)을 사용했다. 주체 구간이 공란인 RE07·V09는 입력이 정답 `unknown`을 암시할 수 있어 제외했다. RE06은 실제 누출일 경우의 조건부 주체, V04는 이번 진단에서만 토스터 접수 대상으로 해석했다. 원래 V04 정답이나 과거 실행 기록은 수정하지 않았다.

실행 전에 코드·검수 입력을 커밋 `e44fdc2`, 프로토콜을 커밋 `0ba76fc`로 고정했다. [실행 프로토콜](../../evals/structured_nlu/data/ai_heldout/as-safety-gold-owner-link-diagnostic-protocol.v1.json)의 SHA-256은 `a2494350296425c6fb4d903a3c79bbbdc5a135b70240cc44575bf04bdd2a616b`다. 같은 로컬 Kanana Q5와 고정 컨테이너에서 ID 순서대로 각 한 번 호출하고 재시도하지 않았다. [결과 저널](../../evals/structured_nlu/data/ai_heldout/as-safety-gold-owner-link-diagnostic-journal.v1.jsonl)은 45행이며 SHA-256은 `74bb20a18dfec3805d27b6fb7dbc149caddf9dd8e7729adac8bc9ede08d23f50`이다. 저널에는 발화·인용 구간·모델 응답 본문을 저장하지 않았다. 검증기는 순서, 분모, 프로토콜·소스 해시 및 커밋 일치, 중복 JSON 키, 유한 오류 코드와 경로를 다시 확인했다.

## 관찰값

| 구간 | 관계 일치 | 다음 경로 일치 | 계약·호출 오류 |
| --- | ---: | ---: | ---: |
| 전체 | 16/22 | 16/22 | 0/22 |
| 현재 제품 `current` | 16/16 | 16/16 | 0/16 |
| 다른 출처 `other` | 0/6 | 0/6 | 0/6 |
| V03·V04 제외 | 14/20 | 14/20 | 0/20 |
| RE06 제외 | 15/21 | 15/21 | 0/21 |

모든 출력이 `current`였다. 다른 출처 오답은 RE09·RE10·RE11·V02·V06·V08이며 `unknown` 출력은 0건이다. V01/02, V05/06, V07/08의 세 대비쌍은 모두 동일한 `current` 출력으로, 기대한 관계 반전이 0/3쌍이었다. 이 로컬 단일 실행의 호출 지연 중앙값은 6,824.322ms, 최근접 순위 p90은 7,453.160ms였다. 이 지연은 구간 정답 제공과 짧은 출력 형식의 비용이며 실제 서비스 전체 응답 시간은 아니다.

같은 22개 ID만 다시 집계하면 이전 단일 관계 오라클과 출처 근거 진단은 각각 관계 15/22였다. 이번 16/22는 이전에 `unknown`이던 RE08의 출력이 `current`가 된 결과다. 다른 출처 6건은 세 진단에서 모두 0/6이었다. 입력 단서와 출력 과제가 다르고 사례가 반복 노출됐으므로 이 **탐색적 재집계**를 정확도 개선율이나 인과 효과로 해석하지 않는다.

## 판단과 남은 반증

사전 기준(`current` 최소 15/16, `other` 6/6, 오류 0/22, 대비쌍 반전 3/3)을 통과하지 못했다. **이 후보를 서비스 경로에 적용하지 않는다.** 위험 출처의 정확한 주체 구간을 알려줘도 다른 실체와 접수 제품을 구별하지 못한 사례가 지속됐다. 이는 이번 조건에서 Q5의 관계 판단 또는 `current` 출력 편향을 더 조사할 근거지만, 모델 내부 원인을 확정하지는 않는다.

다음 실험은 출처 관계의 명시적 증거를 별도 계약으로 표현하거나, 관계 판단을 독립 검증 가능한 규칙·작은 분류기로 분리하는 후보를 비교할 수 있다. 먼저 다른 출처 및 출처 불명 문맥의 새 사례를 고정하고, 거짓 안전 조치와 위험 누락을 각각 세어야 한다. 정답 구간을 서비스 입력에서 어떻게 얻을지도 별도 검증이 필요하다. 이 결과는 **기노출 AI 작성 사례의 오라클 개발 진단**이며 공식 전체 정확도, 실서비스 성능 또는 일반화된 개선율이 아니다.
