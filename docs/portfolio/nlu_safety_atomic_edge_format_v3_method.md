# A/S 위험 주체 출력 형식 제약 분리 진단

> 2026-11-20 실행 전 설계. 이미 노출된 AI 작성·사용자 검수 ES 사례의 개발 진단이다. 공식 정확도, 정확도 개선율 또는 안전 경로 성능으로 사용하지 않는다.

## 판단 근거

[첫 E→B 진단](nlu_safety_atomic_edge_v1_development_result.md)의 19건과 [보류 문구 비교](nlu_safety_atomic_edge_abstention_v2_development_result.md)의 10건은 모두 동일한 `unresolved`·두 공란을 출력했다. 두 번째 비교에서 보류 판단 문장 한 곳을 바꿔도 각 조건의 5건 모두 보류했고, 기준선은 첫 진단의 원시 응답을 재현했다. 따라서 다음에는 문구를 유지한 채 출력 제약의 영향만 시험한다. 이 결과들만으로 보류 원인은 아직 특정되지 않았다.

## 한 변수 비교

- ES01·ES03·ES09·ES17·ES18의 첫 사건 5건을 사용한다. ES01/ES09는 동일한 연기 사건과 다른 출처, ES03은 명시 주체, ES17은 정당한 출처 불명, ES18은 발생 불확실성과 명시 위치를 점검한다. 모두 기노출 개발 사례이며 E→B `implicit` 정답은 이 집합에 없다.
- 각 사례를 두 조건에서 한 번씩, 총 10회 호출한다. 순서는 실행 전에 고정하고 조건 순서를 섞는다. 오류가 나도 같은 호출을 재시도하거나 부분 기록을 이어 쓰지 않는다.
- 시스템·사용자 메시지는 두 조건에서 바이트 단위로 같다. [기존 E→B 요청](../../experiments/as_safety_atomic_edges_v1/event_owner.py)의 원래 보류 문구를 유지한다. `model`, 메시지, 토큰 한도, temperature, repeat penalty, stop, seed, endpoint와 모델 서버 설정도 같다.
- 유일한 요청 차이는 `response_format`이다. 조건 A는 기존 `{"type":"json_object","schema": <기존 세 필드 스키마>}`, 조건 B는 `{"type":"json_object"}`로 보낸다. llama.cpp의 [공식 서버 문서](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)는 두 형식을 설명한다. 고정된 로컬 이미지에서 조건 B가 실제로 지원되지 않으면 이를 요청·전송 오류로 기록하고 모델 보류 원인 해석을 유보한다. 조건 B에서도 프롬프트의 세 필드 JSON 지시는 유지한다. 이 비교는 스키마 강제의 영향이며 JSON 출력 요청 자체를 없애는 시험은 아니다.
- 접수 제품 A, 위험 사건 E, 발생 상태만 모델 입력에 제공한다. 검수된 주체 B, E→B 정답, B→A 관계와 기대 안전 경로는 채점에만 사용한다. TX·GB 봉인 자료는 사용하지 않는다.

## 고정·검증·해석

코드·방법 문서·입력 자료를 커밋한 뒤 모델 파일·컨테이너 이미지·런타임·호출 순서·10개 정확한 요청 본문 SHA-256을 별도 프로토콜에 고정한다. 조건 A의 요청 본문 해시는 이전 보류 문구 비교의 A 요청 해시와 일치해야 한다. 공개 저널에는 원문·프롬프트·응답을 넣지 않고, 원시 응답은 저장소 밖 권한 제한 파일로 보관한다. 독립 검증기는 기존 A 응답 재현 여부와 새 원시 응답을 함께 점검한다.

조건별로 전송·종료 오류, JSON/세 필드 출력 계약, 보류 비율, B 인용 일치(비공란 정답 4건), E→B 종류와 근거 일치(각 5건), 비공란 근거 일치(4건), ES17의 정당한 보류·근거 없는 주체 확정을 분리한다. 조건 B가 형식을 지키지 못하면 이를 계약 오류로 보고한다. ES17에서 근거 없이 주체를 확정하면 비공란 사례가 좋아져도 안전한 후보로 채택하지 않는다.

조건 A가 이전 원시 응답을 재현하지 않으면 이전 전건 보류의 원인과 이번 차이를 연결하지 않는다. 차이가 있더라도 이 5건만으로 원인을 확정하거나 19건 전체로 일반화하지 않는다. 이전 19건의 개발 관문(계약 오류 0, B 18/18, ES17 공란 1/1, 종류 19/19)은 이번 소수 비교로 대체하지 않는다. B→A나 서비스 안전 분기에 연결하지 않고, 후보를 선택한 뒤 새 미노출 검수 사례로 별도 평가한다.
