# AI 작성·사람 검수 NLU validation V2: 범위 계약 후보 선택

> 상태: **후보 선택 관문 통과, 새 test 미실행**. 2026-11-17(한국 시간) 로컬 Kanana Q5에서 기존 코드 `c46c27a`와 범위 계약 후보 `04af278`을 같은 32건에 적용했다. 이 결과는 개발용 validation이며 포트폴리오의 내부 공식 test 정확도 개선율이 아니다.

## 실행과 검증 경계

[사전 커밋한 V2 프로토콜](../../evals/structured_nlu/data/ai_heldout/nlu-internal-validation-pair-protocol.v2.json)의 SHA-256은 `02bc4b8a790be6da3f5db22df6d15e1e188b88aad3d6afb178230b7a98320d09`다. 16개 상세 업무마다 시작 상태의 업무 안 발화 1건·범위 밖 발화 1건, 총 32건은 AI 작성·사용자 1인 검수 자료다. 각 사례를 두 코드에서 평가해 **64개 arm 평가**를 완료했고, 재시도 포함 **원시 모델 응답 77개**를 권한 제한된 로컬 폴더에 저장했다. 8 arm마다 계획한 서버 재시작 7회가 기록됐다. 전송 실패·OOM·예기치 않은 재시작은 없었다.

[독립 재생 검증 영수증](../../evals/structured_nlu/results/nlu-internal-validation-pair-v2-verified.json)은 원시 응답·저널·출력 계약을 다시 계산해 `verified`로 발행됐다. 저널 SHA-256은 `a7be35620644455ec2b312d3b1ec1fc55da2deba11257427215e68418ca339d8`다. 첫 V1 실행은 [수동 재시작 판정 오류로 무효](nlu_internal_validation_v1_invalid_restart.md) 처리했고 그 8개 arm을 V2 결과에 이어 붙이지 않았다.

## 사전 지정한 후보 선택 지표

| 지표 | 기존 | 후보 | 해석 |
| --- | ---: | ---: | --- |
| 사례 전체 일치 | 5/32 (15.625%) | 9/32 (28.125%) | 같은 validation에서 **+4건, +12.5%p** |
| 업무 안 사례 전체 일치 | 1/16 | 1/16 | 개선 없음 |
| 범위 밖 사례 전체 일치 | 4/16 | 8/16 | 증가 4건의 전부가 이 그룹 |
| 범위 밖 `unknown` 행동 적중 | 4/16 | 8/16 | 지원 범위 인식 개선 신호 |
| 업무 안 요청의 `unknown` 오거절 | 0/16 | 0/16 | 새 오거절 없음 |
| 첫 시도 출력 계약 통과 | 25/32 | 26/32 | 형식 계약과 의미 정답은 별개 |
| 최종 출력 계약 통과 | 27/32 | 30/32 | 완전 계약 실패 5건→2건 |
| 재시도 사례 | 7/32 | 6/32 | 요청 부담의 한 측면 |

짝지은 전이표는 **둘 다 정답 5건, 후보만 정답 4건, 기존만 정답 0건, 둘 다 오답 23건**이다. 정답이 있는 비공란 필드 45개 중 **계약 실패 때 해당 정답도 누락으로 세는 기준에서** 누락은 14→9개, 정확한 값은 16→18개였다. 공란에 불필요한 값을 채운 건은 양쪽 12개지만, 계약 유효 출력에 한정된 분모가 87→98로 달라 단순 `hallucination_rate` 비율을 후보의 개선으로 읽지 않는다. 정보 변경 행동과 실제 A/S 위험 정답은 이 validation에서 각각 0건이므로 해당 정확도를 계산하지 않는다.

시도별 completion HTTP 왕복 시간은 기록됐다. 사례의 시도 시간을 합산한 **사후 기술통계** 중앙값은 기존 19.9초·후보 20.5초, 95백분위는 기존 31.6초·후보 34.2초였다. 95백분위는 32개 사례 합계의 선형 보간(`inclusive`) 방식이다. 서버 로드·계획 재시작 시간은 제외되며 토큰 수·첫 토큰 시간은 없다. 이 분석은 사전 지정한 성능 관문도, 독립 재생으로 재측정한 속도 결과도 아니므로 속도 개선 주장에 쓰지 않는다.

## 별도 안전 회귀 관문과 결정

기노출 개발용 PF01–PF16을 [별도 동결 프로토콜](../../evals/structured_nlu/data/ai_heldout/nlu-internal-pf-sentinel-protocol.v1.json)로 평가했다. 16쌍·32 arm 평가에서 원시 모델 응답은 28개였다. [독립 검증 영수증](../../evals/structured_nlu/results/nlu-internal-pf-sentinel-v1-verified.json)에 따르면 직접 위험 8건의 안전 상태 진입은 기존 2건·후보 3건, **새 직접 위험 누락 0건**, 기존부터 양쪽이 놓친 사례 5건, 후보에서 회복한 사례 PF01 1건이다. 비위험 8건의 오경고는 양쪽 0건이다. 위험 탐지의 일반적 성능을 주장할 수 없으며 PF 사례를 위의 32건 분모에 합치지 않는다.

사전 지정한 네 관문은 모두 충족했다: 전체 일치 증가, 업무 안 오거절 증가 없음, 최종 계약 실패 증가 없음, 기노출 A/S 직접 위험의 새 누락 없음. 따라서 **후보 `04af278`을 새 미노출 test의 비교 대상으로 선택**한다. 업무 안 전체 일치가 1/16에 머문 점과 후보의 왕복 시간이 약간 길었던 점은 한계로 유지한다. 새 64건의 문장·상태·행동·전체 필드를 작성·검수하고 양 조건의 원시 응답을 독립 검증하기 전에는 “공식 정확도 개선율”을 발표하지 않는다.
