# AI 작성·사람 검수 내부 공식 표본 평가 V1: 사전 등록 방법

> 상태: 2026-11-16 방법과 데이터 관문 초안. **새 validation·test 사례, 실모델 결과, 정확도 개선율은 아직 없다.** 이 평가는 기존 사람 작성·Coverage V3 전수 공식 벤치마크와 별개다. 데이터 작성 출처를 `human_authored`로 바꾸지 않는다.

## 주장할 수 있는 범위

평가 이름은 **“AI 작성·사람 검수 내부 공식 표본 평가”**로 고정한다. 대상은 마음콜 32개 전체 흐름이 아니라 모델이 구조화 추출을 맡는 **16개 상세 업무**다. 주지표는 한 사례의 출력 계약·`intent`·`user_action`·`change_field`·모든 업무 필드가 동시에 맞는 `case_exact_match_rate`다. 같은 test 사례에 기존 방식과 수정 방식을 각각 적용해 `기존 정답 건수/N → 수정 정답 건수/N`, **퍼센트포인트 차이**와 같은 사례에서 한쪽만 맞힌 건수를 함께 제시한다. 기존 점수가 0이면 상대 개선율은 계산하지 않는다. 기존 사람 작성 V3의 공식 점수나 실제 사용자 분포에서의 정확도라고 쓰지 않는다.

## 빠르게 시작하되 분모를 숨기지 않는 표본 설계

각 업무마다 validation은 **최소 2건**, test는 **최소 4건**으로 시작한다. 각각 업무 안의 정상 행동과 범위 밖 `unknown`을 절반씩 두고, 같은 분할 안에서는 16개 업무의 사례 수를 같게 유지한다. test는 업무마다 시작 상태 외 **후속 상태를 최소 1건** 포함한다. 시작 최소치는 validation 32건, test 64건이다. 이 수는 모든 계약 조합을 덮는 수가 아니라 사람의 전체 필드 검수 부담을 제한하면서 업무별 과대표집과 시작 상태만 평가하는 문제를 막는 **첫 표본 크기**다. 64건의 한 건은 전체 비율에서 1.5625%p이므로 작은 차이를 과장하지 않는다. 필요하면 모델 실행 전에 업무마다 같은 수만큼 늘리고 새 버전으로 동결한다.

정상 행동은 `user_action != unknown`이며 `hard_negative` 태그가 없어야 한다. 범위 밖은 `user_action=unknown`과 `hard_negative` 태그가 일치해야 한다. **그 요청이 실제로 업무 범위 밖인지**는 코드가 태그만 보고 증명할 수 없으므로 사용자가 발화 의미를 별도로 확인한다. 분할 간 동일 원문·모델 입력·원본 대화 그룹을 금지한다. 각 사례의 문장·상태·행동·전체 업무 필드와 공란, 허용 문자열을 사용자가 검수하고 `adjudicated`로 확정한다.

검수 기록은 두 층이다. 기존 묶음 검수 원장은 데이터 원문 SHA와 전체 case ID를 묶는다. **추가된 사례별 결정 원장 V1**은 validation/test의 모든 case ID와 일대일로 맞아야 하며, 각 사례의 전체 내용 SHA-256, 검수자 역할 ID, 시간대가 있는 확정 시각, 사례별 판단 근거, `accepted` 결정을 요구한다. 문장·정답·상태·태그 중 하나라도 바꾸면 사례 지문이 달라져 과거 결정을 재사용할 수 없다. 역할 ID·시각·지문은 한 사람의 실제 검수 신원이나 의미 정답의 옳음을 암호학적으로 증명하지 않는다. **사람이 실제로 각 사례를 읽고 판단했다는 작업 기록**과 의미 검토는 별도로 남겨야 한다.

## 동결과 노출 순서

1. 이미 모델에 노출된 개발 자료에서 현재 서비스 기준선을 다시 측정한다. 이 개발 점수는 최종 test 점수가 아니다. validation은 후보 선택에만 쓴다.
2. 비교할 **기존·수정 코드와 모델 파일, 프롬프트·요청·서버 설정**을 커밋과 SHA로 고정한다. 수정 후보를 선택한 다음 새 test 문장을 작성한다. 후보가 test를 보거나 test 점수를 보고 바뀌면 그 test는 개발 자료로 격하한다.
3. 새 test는 AI 작성 사실을 그대로 기록하고, 사용자가 문장·상태·행동·전체 필드·공란을 검수한다. 이전 개발·validation·test·모델 호출에 사용한 발화의 원문 목록과 정규화 원문을 대조하고, 가까운 바꿔쓰기는 사람이 별도로 검토한다. 자동 일치 검사는 **알려진 목록의 정확한 일치만** 막으므로 미등록 노출이나 의미상 근접 중복의 부재를 보증하지 않는다.
4. validation/test, 검수 원장, 이 정책의 지문, 실행기·독립 검증기, 두 조건의 정확한 실행 순서와 재시도 정책, 결과 출력 경로를 **첫 test 모델 호출 전** 버전 지정 프로토콜로 커밋한다. 같은 test와 같은 실행 환경을 두 조건에 사용하고 호출 선후를 균형 있게 배정한다. 중단 실행을 이어 붙이거나 결과를 덮어쓰지 않는다.
5. 원시 예측과 시도별 계약 결과를 접근 제한 위치에 보존하고, 공개 결과에는 발화·프롬프트·응답 원문을 넣지 않는다. 독립 검증기가 원시 기록·동결 입력·전 사례 점수를 재계산해야 내부 공식 표본 결과로 발행한다.

현재 추가한 `ai_reviewed_internal_policy_v1.py`는 **3번의 데이터 형식·묶음과 사례별 검수 원장·분할 균형·알려진 원문의 정확 일치 관문**만 구현한다. 커밋 시간 순서, 노출 목록의 완전성, 실행 환경, 원시 응답 독립 재검증은 향후 동결·실행·검증기에서 구현하고 통과시켜야 한다. 이 문서와 관문만으로 “공식 평가 완료”가 되지 않는다.

## 불확실성과 안전 실패 보고

사전 고정한 불확실성 계산은 **업무×행동 그룹별 층화 짝지은 백분위 부트스트랩**이다. 16개 업무의 정상 행동·범위 밖 `unknown` 조합 32개 층 각각에서 기존·수정 결과가 묶인 동일 사례를 복원추출하고, 층별 원래 사례 수를 유지한 20,000회 재표본의 정확도 차이 2.5·97.5백분위를 95% 구간으로 보고한다. 난수 시드는 `0`이다. 이는 이 균형 표본 안의 불확실성을 보여 주며, 임의로 수집한 실제 사용자 발화 분포에 대한 신뢰구간으로 해석하지 않는다. 기존 방식만 정답·수정 방식만 정답·둘 다 정답·둘 다 오답 건수, 업무별 분모, 시작/후속 상태, 범위 밖 행동, 필드 누락·사실 생성, A/S 직접 위험 누락과 다른 출처 오경고를 분리해 보고한다. 안전 위험 표본이 적다면 위험 경로의 일반적 안전성을 주장하지 않는다.

수정 방식의 관측 점수가 높더라도 95% 짝 비교 구간이 0을 포함하면 포트폴리오에는 **“이 표본에서 관측된 차이”**로만 쓴다. 하한이 0을 넘고 위험 사례에서 새 직접 위험 누락이 없을 때에만 **“이 내부 표본에서 개선을 확인”**이라고 쓴다. 16개 상세 업무 전체의 실제 운영 정확도, 32개 흐름 전체, 사람 작성 V3 전수 평가와 등치하지 않는다. 후보가 개선되지 않으면 개선율이라는 표현 자체를 쓰지 않는다.
