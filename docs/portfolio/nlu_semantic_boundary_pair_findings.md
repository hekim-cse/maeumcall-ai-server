# NLU 의미 경계 지시문의 로컬 Q5 탐색 비교

2026-11-05에 사용자에게 **탐색용 의미 방향을 검토받은 AI 작성 발화 12건**을
기존 지시와 [추가 의미 기준](../../evals/structured_nlu/semantic_boundary_policy.py)으로
비교했다. [SB01–SB08](nlu_semantic_boundary_review.md)은 초점 필드에 값이
있는 사례, [SB09–SB12](nlu_semantic_negative_review.md)는 공란 사례다.
각 발화를 조건별 2회씩 실행했고, 첫 반복은 기본→후보, 두 번째는 후보→기본
순서와 역순 사례 배열을 사용했다. 따라서 **고유 문장 12개, 조건별 관찰 24회**다.
이 발화들은 모델 실행 전에 검토·고정했지만 AI 작성 개발 자료이므로 독립 test나
공식 정확도 근거가 아니다. 이전 D05·F23은 이번 12건 실행에 포함되지 않았고,
[후속 수정 라벨](nlu_meaning_label_amendment.md)은 별도 보존한다.

| 조건 | 계약 통과 | 계약 통과와 행동 초안 일치 | 계약 통과와 초점 필드 초안 일치 | 행동·모든 필드 초안 전체 일치 | 재시도 관찰 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 기본 | 19/24 | 19/24 | 10/24 | 0/24 | 7/24 |
| 의미 기준 후보 | 19/24 | 19/24 | 14/24 | 0/24 | 11/24 |

후보에서는 SB03·SB04의 재배달 희망과 SB05의 정부24 발급 경로가 두 반복
모두 초안과 일치했으나, 기본 조건에서는 그렇지 않았다. 반대로 SB07의 날짜는
기본 조건에서 두 번 일치하고 후보에서는 두 번 불일치했다. SB02는 두 조건에서
초점 필드가 맞지 않았고 후보의 한 반복에서는 계약도 실패했다. SB06은 후보에서
두 번 모두 계약 실패, SB09는 두 조건에서 두 번 모두 계약 실패했다. SB08의
`매주 화요일` 값은 양쪽에서 두 번 모두 정확한 초안 문자열과 불일치했다.
계약 실패는 필드 의미 성공으로 세지 않았다.

초안의 `issue_detail`과 `duration`처럼 자연어로 정규화하는 문자열은 다른
표현이 의미상 같을 수 있다. 보고서는 원문 답변을 보관하지 않고 불일치 필드
이름만 보관하므로, 0/24 전체 일치를 곧바로 실제 의미 오류 24건으로
해석하지 않는다. 반대로 14/24 초점 일치도 전체 NLU 정확도나 안정적 개선으로
해석하지 않는다. 두 번의 반복은 독립 표본 24개가 아니며 개발 사례에 맞춰
후보를 작성했다.

기본 조건은 총 생성 시도 31회, 완료 토큰 2,390개였고 후보는 35회,
완료 토큰 2,783개였다. 후보가 4회 더 재시도하고 완료 토큰은 393개 더 썼다.
기록된 총 소요 시간은 기본 159.592초, 후보 122.108초였으나 순서·캐시·
재시도 구성이 달라 속도 우열을 주장하지 않는다. 요청은 두 조건 모두
`max_tokens=180`, `temperature=0`, `repeat_penalty=1.05`, 종료 토큰
`<|eot_id|>`로 보냈다. 후보는 기존 사용자 지시의 **첫 사용자 메시지**에
고정해 넣었고 재시도 오류 안내 뒤로 이동하지 않도록 테스트했다.

[실행 보고서](../../evals/structured_nlu/results/exploratory-q5-semantic-boundary-2026-11-05.json)는
사례 ID별 계약·초안 일치·불일치 필드 이름, 안전한 출력 형태, 재시도·토큰·시간,
입력·검토 원장·코드·모델 지문을 기록한다. 발화와 모델 답변 전문은 저장하지
않았다. [모델 노출 기록](../../evals/structured_nlu/data/exploratory/semantic-boundary-model-exposure-2026-11-05.json)은
첫 요청 전 생성해 이 입력의 무심코 재실행을 막는다. 실행은 입력·후보·검토
원장을 먼저 고정한 커밋 `023789e`에서 시작했다. 로컬 Q5 GGUF SHA-256은
`644b04cde835d486df33c6d4d7552ba367fcb28802fe39b6b4bb9c60b9ab6f3d`,
서버 이미지 digest는
`sha256:17155a3ce4cc906728ec99a2814bf0b4eaffaf3b4872bad8c3affed310cdbc35`였다.
Docker CPU 4개·메모리 6GiB·스레드 4개·단일 슬롯·컨텍스트 4096이었고
실험 후 컨테이너를 종료했다.

**판단:** 초점 필드의 개발 초안 일치가 일부 늘었지만 계약 실패와 다른 필드
불일치가 남았고 재시도·토큰 부담도 늘었다. 후보를 서비스에 적용하지 않는다.
특히 SB08의 `매주 화요일`은 사용자가 날짜 정보로 인정했더라도, 현재 스터디룸
가용 여부 조회는 날짜를 조회 키로 사용하지 않는다. 반복 예약 가능·완료를
보장하는 운영 흐름으로 해석하면 안 된다. 포트폴리오의 전체 정확도 개선율은
별도의 사람 작성·검수·동결 test와 적용 가능한 후보가 준비된 뒤에만 계산한다.
