# A/S 출처 명시 구문 오프라인 대조

[#93](https://github.com/hekim-cse/maeumcall-ai-server/issues/93)의 일부인 사건 E와 후보 B의 연결을 점검했다. [v23](nlu_safety_eb_event_reference_v23_result.md)에서는 Qwen이 출처 근거가 없는 후보에도 사건 또는 출처 불명 문장을 선택했다. 다음 비교에서는 기존 Kiwi 형태소 분석과 원문 오프셋을 재사용해, 명시 구문을 찾았을 때만 근거를 반환하는 기준선을 만들었다.

동일 문장의 시작에 있는 후보 전체가 일반·고유 명사로 분석되고, 출처 조사 `에서`·`로부터`·`으로부터`를 사이에 두고 검수된 관찰 사건과 바로 연결되는지를 본다. 사건 뒤에 추가 문구가 있거나 후보가 부분 구절이거나 다른 문장에 있으면 보류한다. 원문 오프셋 불일치는 입력 오류이며 보류와 구별한다.

| 기노출 후보 쌍 | 검수 기준 | v23의 출처 선택 | 명시 구문 기준선 |
| --- | --- | --- | --- |
| PC01/P014 | 지지 | 선택 | 2번 문장, 후보와 사건의 원문 위치 |
| PC01/P016 | 출처 지지 없음 | 선택 | 보류 |
| NC01/P020 | 출처 지지 없음 | 선택 | 보류 |
| NC01/P002 | 출처 확인 불가 | 선택 | 보류 |

v23 원시 응답을 재생하고 같은 네 쌍에 기준선을 적용했다. 지지 근거는 두 방식 모두 1/1에서 선택했다. 지지가 없는 세 쌍에서 v23은 3/3 선택했고, 기준선은 3/3 보류했다. 개발에 이미 사용한 두 발화의 결과이므로 새 발화에서의 보류율이나 성능 개선율로 해석할 수 없다.

이 기준선은 명시된 발생 위치나 출처 구절을 찾는다. 부품 소속이나 제품 동일성, 원인, 이전 문장의 지시어, 여러 사건과 모순되는 후속 발화의 판단은 범위 밖이다. `observed` 사건과 오프셋은 사전에 검수된 입력이며, 암묵적이나 비정형 출처는 놓칠 수 있다. 후속 평가에서는 실제 출처와 같은 문장 속 다른 후보를 최소 대조쌍으로 구성하고, 굳이 보류한 정답과 잘못 승인한 후보를 따로 센다.
