# A/S 제품·위험 사건 관계 후보

## 문제와 판단

이전 [실제 발생 어휘 게이트](nlu_safety_event_gate_fresh_findings.md)는 새 실제 위험 EG01–EG08 중 5건을 즉시 대응에서 확인 질문으로 늦췄다. 위험 단어의 활용형을 계속 추가하면 새로운 표현에 다시 실패하고, 위험을 말한 대상이 현재 접수 제품인지도 해결되지 않는다. 이 결과는 AI 작성·1인 검수 탐색 사례에 한정된다.

이번 후보는 모델에 원문을 문장 번호로 제공하고 `product_index`와 `hazard_index`를 별도로 요구한다. `target_relation`은 위험의 대상이 현재 제품인지, 다른 대상인지, 불명확한지를 표현한다. `event_status`는 실제 관찰, 발생 여부 불확실, 부정·가정·일반 질문, 위험 없음으로 구분한다. `current + observed`만 즉시 대응, 현재 대상이나 대상 불명의 관찰·불확실성은 확인 질문, 다른 대상과 미발생은 일반 수집으로 제안한다.

## 계약과 검증 범위

[개발용 후보 코드](../../scripts/probe_as_safety_relation.py)는 두 근거 번호가 실제 원문 문장 범위 안에 있는지, enum과 공란 조합이 일관적인지 검증한다. 번호가 다른 문장을 가리켜도 허용한다. 실제 제품이 앞 문장에 나오고 위험이 뒷 문장에 나오는 경우를 표현하기 위해서다. 유효한 번호가 의미상 올바른 지시 관계를 보증하지는 않는다. 모델의 관계 판단 실패와 계약 형식 실패를 별도 지표로 기록해야 한다.

이는 **개발용 후보**이며 현재 서비스 그래프, 응답 문구, 보호 전이에 연결하지 않았다. 이전 EG·CF 사례는 설계에 노출됐으므로 새 성능 근거로 재사용하지 않는다.

## 실행 전 평가 기준

- 새 AI 작성 발화를 모델에 보내기 전에 문장, 기대 경로, 제품·위험 근거와 관계·발생 상태를 사용자가 탐색용으로 검수한다.
- 후보 코드·요청 설정·모델 파일·컨테이너 이미지·사례 순서와 해시를 호출 전에 고정한다.
- 기존 문장 번호 기반 후보와 새 관계 후보를 동일한 모델·자원·발화에서 비교한다. 안전 즉시 대응 유지, 잘못된 즉시 대응, 불필요한 확인, 계약 오류, 요청 수와 지연을 분리한다.
- 특히 서로 다른 제품이 한 발화에 등장하는 경우와 실제 위험 보고 뒤에 후속 질문이 붙는 경우를 포함한다.
- AI 작성·1인 검수 표적 탐색 결과를 공식 전체 정확도나 배포 성능으로 소개하지 않는다. 실제 위험을 늦추거나 계약 오류가 늘면 새 후보를 채택하지 않는다.
