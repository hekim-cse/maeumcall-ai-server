# A/S 위험 주체 후보 ID 실모델 개발 진단 방법

> 2026-11-22. 모델 호출 **전** 방법. PC01·NC01은 기노출 AI 작성·사용자 검수 개발 사례다. 공식 정확도·안전 경로·속도 개선을 평가하지 않는다.

## 질문과 사전 관문

v9에서는 원문에 존재하는 후보 밖 구절이 형식 계약을 통과했다. v10에서는 후보 ID 또는 공란만 반환하고, 서버가 ID를 원문 구절로 복원한다. **형식상 후보 밖 출력이 거절되는가**와 **정답 선택·정당 보류가 함께 되는가**를 분리한다. 후보 생성은 원문만 사용하고 검수 정답은 요청에 넣지 않는다.

PC01의 검수 B는 2번 문장 `선풍기 모터`, 종류 `location`이다. NC01은 B 공란·`unresolved`다. 두 사례 모두 v8 명사 끝 후보를 원순으로 표시한다. 호출 순서는 **PC01→NC01**, 각각 정확히 1회이며 재시도·부분 재개하지 않는다. v9 결과를 보고 정한 작은 개발 관문이므로 통과해도 일반화 근거가 아니다.

관문은 두 호출 모두 전송·길이·출력 계약 오류 0건, PC01의 정확 B·종류, NC01의 유효 공란·`unresolved`를 요구한다. 후보 ID 소속은 출력 계약이 강제한다. 실패하면 ES 전체나 서비스 안전 경로로 확대하지 않는다. 출력 계약 오류는 의미 오답과 별도로 기록한다.

## 실행 전 동결

방법·코드·테스트를 먼저 커밋한다. 고정 Q5 파일 SHA-256 `644b04cde835d486df33c6d4d7552ba367fcb28802fe39b6b4bb9c60b9ab6f3d`, 컨테이너 이미지 digest `sha256:17155a3ce4cc906728ec99a2814bf0b4eaffaf3b4872bad8c3affed310cdbc35`, 모델 경로·서버 인자·로컬 포트, 요청 설정, 후보 행·스키마·요청 바이트 해시, 실제 서버 토크나이저 입력 수, 4096 문맥 예산, 호출 순서와 출력 경로를 프로토콜에 기록하고 **모델 생성 호출 전에 별도 커밋**한다. 스키마가 서버에서 실패하면 오류를 남기고 멈춘다. 프로토콜 뒤 요청이나 방법을 바꿔 재실행하지 않는다.

모델 파일 검사는 컨테이너 생성 전에 호스트 파일 해시·식별자를 기록하고, 생성 후 읽기 전용 마운트·내부 SHA-256·컨테이너 생성 시각과 ID를 확인한다. 각 호출 전후에도 반복한다. 검사 실패 시 응답을 공개 저널에 기록하지 않고 중단해 부분 실행을 수동 감사한다. Docker가 고정 이미지의 `sha256sum`을 제공하는 것은 앞선 스모크 테스트에서 확인했으나, 실제 모델 서버 통합은 이번 실행에서 확인해야 한다.

원시 응답은 저장소 밖 권한 0700 폴더의 0600 파일로 저장한다. 공개 저널에는 원문·프롬프트·원시 응답 없이 해시와 오류 코드·지연만 넣는다. 독립 검증기는 동결 커밋에서 요청을 다시 만들고, 저널 순서·원시 해시·출력 계약·검수 정답을 분리해 확인한다. 모델 파일을 악의적으로 변조한 실행 환경이나 서버 메모리 내부의 실제 로드 바이트까지 증명하지 않는다.

이 두 사례는 이미 여러 실험에 노출됐다. v9와 입력 길이·출력 형식·지시문이 함께 바뀌므로 차이를 후보 ID 하나의 인과 효과로 주장하지 않는다. 새 미노출 자료와 전체 정답의 별도 검수·사전 고정 전에는 공식 개선율을 쓰지 않는다. TX·GB는 사용하지 않는다.
