# 내부 test 64건 문장 초안 A: IT01–IT32

> **AI 작성·사용자 문장/방향/전체 필드 검수 완료, 모델 미실행.** 독립 감사에서 IT05·IT17·IT27 문장을 교체했고, 사용자가 최종 교체 문장과 라벨 방향을 채택했다. [필드 검토표](nlu_internal_test64_field_review_part_a.md)의 모든 값·공란도 사용자 검수를 마쳤다. 데이터 계약·노출 검증과 평가 입력 동결은 아직 남아 있다. 이름·주문번호·모델명은 모두 가상이다.

각 업무에서 시작 `greeting` 2건과 실제 도달 가능한 `collecting_*` 상태 2건을 배치했다. 고객센터·배달의 후속 `current_fields`는 아래 적은 값만 채우고 **계약의 나머지 필드는 모두 `null`**로 하는 초안이다. 교수님 세 업무의 직접 분석기는 이전 필드 대신 상태와 현재 발화만 입력받으므로 후속 `current_fields={}`로 둔다. 아래의 직전 질문은 상태가 왜 가능한지 설명하는 검수 맥락이며, 지금 실행기의 모델 입력에 별도 대화 이력으로 전달되지 않는다.

## 채택 후 남은 검증 경계

- IT16·IT20·IT24의 후속 상태는 이전 대화의 주제가 각각 결석·과제·면담이어도 현재 발화는 범위 밖이라는 해석을 사용자가 채택했다.
- IT01–IT32는 **AI 작성·사용자 1인 검수** 사례다. 사용자 채택 사실은 모델 미노출, 기존 자료와의 의미 독립성, 평가 입력 동결을 증명하지 않는다. 실제 데이터화할 때 서비스 업무 5개 필드 집합은 모두 정확한 키로 채우고, 교수님 직접 분석의 `current_fields`는 빈 객체로 둔다.
- 모델 입력에 들어가는 현재 상태와 현재 필드, 실제 직전 질문의 관계를 사례별로 다시 검증해야 한다. 특히 후속 대화의 값이 이미 수집된 필드와 충돌하지 않는지 확인한다.
