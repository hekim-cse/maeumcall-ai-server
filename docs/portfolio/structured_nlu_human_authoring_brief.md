# 구조화 NLU 독립 평가용 발화 작성 안내

## 목적과 범위

마음콜의 16개 상세 업무에서 모델이 사용자 발화의 행동과 업무 필드를 얼마나
정확하게 추출하는지 비교하기 위한 **새 가상 발화**를 받는다. 자유 대화의 답변
품질이나 전체 32개 흐름의 품질을 평가하는 자료가 아니다.

이 문서는 작성자에게 전달할 안내문이다. 아직 확보된 테스트 사례나 정답,
정확도 결과가 아니다. 작성 칸은
[H01–H36 접수표](heldout_nlu_new_test_intake.md)에 있다.

## 작성자에게 요청할 내용

1. 접수표의 업무와 발화 유형을 보고 문장을 직접 작성한다. AI 문장 생성기나
   기존 개발·탐색 사례의 바꿔쓰기를 사용하지 않는다.
2. 실제 고객 정보 대신 가상의 이름, 주문번호, 장소, 날짜를 사용한다.
   비밀번호, 전화번호, 실제 주소 등 개인정보는 넣지 않는다.
3. 사람이 말할 법한 한두 문장으로 쓴다. 정보 제공 발화에는 해당 업무의
   새 정보가 들어가야 하고, 어려운 발화에는 모호한 의사·범위 밖 질문·수정·부정
   중 자연스러운 상황을 담는다. 정답 행동을 문장에 억지로 설명하지 않는다.
4. 예약 후속 발화에는 앞선 대화에서 이미 정해진 값과 서버가 제시한 대체 시간이
   있으면 별도 문맥 칸에 적는다. 이번 발화에서 새로 말한 값과 구별한다.
5. 문장을 만든 뒤 모델 출력, 예상 정답 또는 다른 작성자의 문장을 보지 않은 상태로
   제출한다. 모호해 보이는 문장도 임의로 정답을 붙이지 않고 표시한다.

작성자는 모든 36칸을 한 번에 채울 필요가 없다. 다만 적은 수의 새 사례만으로는
16개 업무 전체의 공식 정확도를 주장할 수 없다.

## 접수 후 검수 절차

- 접수 시 작성자의 역할, 작성 방법, 제출 시각과 원문 버전을 기록한다. 역할은
  실제 작성자를 식별할 수 있어야 하지만 공개 결과에는 개인정보를 넣지 않는다.
- 기존 development 및 AI 탐색 발화와 중복·가까운 바꿔쓰기를 확인한다. 이미
  Q4·Q5 실험에 노출된 문장은 독립 테스트에서 제외한다.
- AI는 상태와 정답의 **초안**을 제안할 수 있다. 사람 검수자가 문장 의미,
  행동, 모든 필드와 공란, 허용 문자열을 확인·수정하고 판단 근거를 남긴다.
- 작성 원본, 분할, 검수 원장, 대조 관계와 coverage를 검증한 뒤 버전 지정
  동결 기록을 커밋한다. 동결 전에는 비교할 모델에 사례를 실행하지 않는다.
- 같은 동결 test 사례와 요청 설정으로 비교 대상을 실행한다. 계약 실패도 오답으로
  세며, 정답 건수·분모·퍼센트포인트 차이와 사례별 실패를 함께 보고한다.

사람이 AI 초안을 채택하거나 일부 고친 문장은 현재 평가 정책에서
`human_authored`로 취급하지 않는다. 그런 문장은 별도 탐색 자료로 보관한다.
검수 완료와 사람 작성 출처는 각각 확인해야 한다.

## 현재 상태

2026-11-06 기준 compiled V2의 36건은 모두 `development`·`draft`다.
검수 완료된 독립 `test` 사례와 V4 동결 기록이 없으므로 공식 정확도 비교는
아직 실행할 수 없다. 이 수치는 현재 저장소 상태를 확인한 시점의 기록이다.
