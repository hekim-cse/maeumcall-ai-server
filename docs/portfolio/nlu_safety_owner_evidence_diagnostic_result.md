# A/S 위험 출처 근거 진단 결과

## 입력과 주장 범위

- 2026-11-11, 로컬 Kanana Q5에 검수된 접수 대상·위험 사건 원문 구간과 발생 상태를 제공했다. 위험 사건의 **출처 구간·문장 번호·연결 종류·최종 관계**는 모델이 출력했다.
- 기존 RE/V 중 발생 상태가 `observed` 또는 `uncertain`인, 이미 모델에 노출된 AI 작성·사용자 검수 24건을 ID 순서로 한 번씩 호출했다. `nonoccurring` 8건은 제외했다. V04는 이번 진단에서만 토스터 접수·`current` 해석을 사용했다.
- 코드·검수 정답·프로토콜은 결과 호출 전에 각각 커밋 `6d99e22`, `cdf0357`, `93ffdf5`로 고정했다. 프로토콜 SHA-256은 `854d1c4484e8d33853ca236dc785fec1a584d5b1c697388276c30ddaff4be260`, 결과 저널 SHA-256은 `88b16b8d8dca79fe3e6f19eb25c2c1d4b212112406fa9b085feb54788692fed5`다.
- 저널 49행은 헤더 1행과 24건의 시작·종료 기록이다. 원문·인용 구간·모델 응답 본문은 저장하지 않고, 근거 구간의 문장 번호와 문자열 위치만 기록했다.
- PR 리뷰에서 원래 독립 검증기의 JSON 파싱이 **중복 키를 마지막 값으로 덮어쓸 수 있는 점**이 발견됐다. 당시 검증기·프로토콜·저널은 해시로 고정돼 있어 소급 수정하지 않았다. 별도 사후 감사기에서 저널 원문 49행의 중복 JSON 키를 거부한 다음 고정 검증기를 다시 실행했고, 실제 저널은 통과했다. 이 사후 보강은 실행 전 고정된 검증 범위와 구분한다.

관계별로는 현재 제품 `current` **15/16**, 다른 출처 `other` **0/6**, 출처 불명 `unknown` **0/2**였다. V01/02, V05/06, V07/08 세 대비쌍에서 모델은 모두 양쪽을 `current`로 판단해 출처 반전이 **0/3쌍**이었다. V16은 `finish_reason=stop` 뒤 `ValueError` 계약 오류로 기록됐고 자동 재시도하지 않았다. 응답 본문을 저장하지 않았으므로 어느 필드가 위반됐는지는 저널만으로 확정할 수 없다. HTTP 오류는 없었다.

승인 주체 구간과 정확히 같지 않은 14건 중 8건은 더 길거나 짧은 **인용 경계 차이**였다. 따라서 10/24는 승인 구간의 정확 일치 수이며 의미상 주체 식별 정확도가 아니다. 반면 RE10의 `친구가 쓰는 같은 모델`, RE11의 `욕실 전등`, V02의 `가습기의 전원선`은 승인 구간을 정확히 인용하고도 연결을 `part_or_anaphora/current`로 잘못 판단했다. 이는 주체 인용 실패와 별개로 **접수 제품과 다른 실체의 관계 판단 실패가 관찰됐음**을 보여준다. 모델 내부 원인은 이 기록만으로 확정하지 않는다.

같은 24건의 앞선 [단일 관계 오라클 진단](nlu_safety_oracle_relation_diagnostic_result.md)은 관계 15/24, 경로 17/24, 오류 0/24였다. 이번에는 관계 15/24가 같지만 RE08이 맞게 바뀐 1건과 V16 계약 실패 1건이 상쇄됐다. 프롬프트와 출력 과제가 다르므로 이 둘은 같은 개발 사례의 **탐색적 쌍 비교**이며 성능 개선율이나 지연 개선율로 계산하지 않는다. 이번 로컬 단일 실행의 호출 지연 중앙값은 9,251.196ms, 최근접 순위 p90은 10,187.926ms였다.

## 결정과 다음 반증

사전 기준인 `current` 최소 15/16, `other` 6/6, `unknown` 2/2, 오류 0/24와 세 대비쌍 반전 3/3을 충족하지 못했다. **이 후보는 서비스 경로에 적용하지 않는다.**

다음에는 이미 검수된 **출처 주체 구간까지 입력으로 제공하고 연결만 묻는** 22건의 개발 진단으로 추출 실패와 관계 판단 실패를 더 분리한다. 이때 검수 정답에 주체 구간이 지정된 `current` 16건과 `other` 6건만 사용한다. RE06의 주체는 실제 누출일 경우의 조건부 해석이다. `unknown` 2건에 `null` 주체를 제공하면 정답을 누출하므로 별도의 경쟁 출처·후속 불명 문맥 실험으로 다룬다. 22건에서도 다른 출처가 `current`로 남으면 Q5의 관계 판단 또는 출력 편향을 더 의심할 수 있고, 회복되면 주체 추출·출력 결합 문제를 조사할 근거가 된다. 어느 경우에도 기노출 AI 작성 개발 사례로 공식 전체 정확도나 실서비스 안전 성능을 주장하지 않는다.
