# A/S 안전 출처: 원문 근거 인용 개체 연결 개발 진단 결과

## 실행 경계

[사전 개발 계획](nlu_safety_grounded_entity_link_development_plan.md)에 따라 이미 노출된 AI 작성·사용자 검수 RE/V 22건만 사용했다. 모델에는 원문과 검수된 접수 대상·위험 주체 구절 및 문장 번호를 제공했으므로 **오라클 입력 하위 과제**다. 위험 발생 상태·관계 정답·안전 경로는 요청에 제공하지 않았다. GB01–GB24는 후보 개발과 모델 실행에 사용하지 않았다.

후보·실행기·독립 검증기와 요청 정책을 첫 호출 전에 커밋으로 고정했다. [프로토콜](../../evals/structured_nlu/data/ai_heldout/as-safety-grounded-entity-link-diagnostic-protocol.v1.json)의 SHA-256은 `dcd8e989352768f667960c083ef47760c5985393f93947d6132342c2ceddd929`다. 이전과 동일한 Kanana Q5 GGUF(SHA-256 `644b04cde835d486df33c6d4d7552ba367fcb28802fe39b6b4bb9c60b9ab6f3d`)와 llama.cpp 이미지 digest를 사용했다. 모델 서버는 로컬에서 2 CPU·4 GiB·4096 context·2 thread·동시 처리 1개로 제한했다. 인용이 최대 두 개로 늘어 [전용 요청 정책](../../evals/structured_nlu/data/ai_heldout/as-safety-grounded-entity-link-request.v1.json)의 최대 생성 길이를 320토큰으로 사전 설정했다. 180토큰에서 실제 길이 종료가 있었다는 뜻은 아니다.

22건을 정해진 순서로 각 한 번 호출했고 재시도하지 않았다. [45행 시작·종료 저널](../../evals/structured_nlu/data/ai_heldout/as-safety-grounded-entity-link-diagnostic-journal.v1.jsonl)의 SHA-256은 `47afe97448dd7f046b0eae72ac37455614a9358c8bfd2d830f4a61c8fb9ac6da`다. 저널에는 발화와 모델 응답·인용 본문이 없고, 인용의 문장 번호·문장 안 위치·SHA-256만 남겼다. [독립 검증기](../../scripts/verify_as_safety_grounded_entity_link_diagnostic.py)가 프로토콜의 소스·입력 해시, 22건 순서, 45행, 인용 위치·해시·두 검수 구절 포함, 관계·경로 매핑과 집계를 재검산해 통과했다.

## 관찰값

| 검수 관계 | 관계 일치 | 출력 분포 |
| --- | ---: | --- |
| 현재 제품 `current` | 7/16 | `current` 7, 보류 `unknown` 9 |
| 다른 출처 `other` | 0/6 | 보류 `unknown` 6 |
| 전체 | 7/22 | 보류 15, 호출·계약 오류 0 |

현재 제품의 **관찰된 실제 위험 13건 중 6건만 현재 제품으로 연결**했고, 나머지 7건은 보류했다. 현재 제품 전체 7/16에는 발생이 불확실한 RE06도 포함된다. 세 대비쌍 V01/02·V05/06·V07/08 중 기대한 `current → other` 관계 반전은 **0/3쌍**이다. V05/06과 V07/08의 출력은 서로 달랐지만, `other`를 정답으로 확정한 쌍은 없다. 발생 상태를 검수 정답에서 사후 결합한 **오라클 파생 경로** 일치는 9/22이며 실서비스 경로 점수가 아니다.

타출처를 현재 제품으로 확정한 사례는 0건이었지만, 타출처 6건을 전부 안전 확인으로 보류했다. 거짓 즉시 조치가 없다는 관찰만으로 경계가 개선됐다고 볼 수 없다. RE01–04·V01·V03·V04 등 현재 제품의 실제 위험에서도 즉시 조치가 늦춰졌다. 모델 응답 본문을 저장하지 않았고 저널에는 검증 후 판단만 있어, 15건의 보류가 모델의 직접 선택인지 원문 앵커 검증에 따른 변환인지 이 기록만으로는 분리할 수 없다. 또한 원문 구절이 존재한다는 검사는 그 구절이 소속 관계를 **의미상 증명하는지** 판정하지 않는다.

단일 로컬 실행에서 모델 호출 지연의 중앙값은 8,164.835ms, 최근접 순위 p90은 8,945.337ms였다. 이전 단일 관계 진단과는 프롬프트·출력 계약·최대 생성 토큰이 달라 지연이나 17/22→7/22 차이를 인과적 효과·정확도 개선율로 해석하지 않는다.

## 판단과 다음 설계

사전 게이트인 현재 제품 최소 15/16, 관찰된 현재 제품 위험 13/13, 다른 출처 6/6, 대비쌍 3/3, 오류 0/22 중 **오류 0건만 충족**했다. 원문 인용을 요구한 이번 후보는 타출처의 잘못된 확정을 줄이는 대신 보류가 과도했고, 현재 제품 위험의 즉시 보호도 놓쳤다. **후보를 기각하고 서비스 그래프에 연결하지 않으며 GB 탐색 평가로 넘어가지 않는다.** 이 결과는 기노출 AI 작성 사례의 개발 진단이고 공식 전체 정확도나 배포 안전성의 근거가 아니다.

다음에는 보류의 원인을 측정 가능하게 나눈다. 새 실행 버전의 저널에 원문 없이 `model_relation`과 `anchor_status` 같은 유한 코드만 분리 기록하면 모델 자체의 보류와 서버 앵커 검증에 따른 보류를 구별할 수 있다. 그런 진단 뒤에도 **관계 근거를 의미상 검증할 방법**과 검수 구절 없이 원문에서 대상·주체를 추출하는 방법이 필요하다. 기존 RE/V를 다시 실행해 점수를 새 평가로 부르지 않고, 후보를 결정하면 새로 작성·검수한 사례에서 별도 프로토콜로 시험한다.
