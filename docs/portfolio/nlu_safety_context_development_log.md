# A/S 안전 표현 개발 점검

이 기록은 [이전 SC 탐색 평가](nlu_safety_contract_graph_pair_run_log.md)에서 드러난 네 위험 표현 누락을 개발 사례로 사용한 뒤의 수정 과정이다. SC01–SC20은 이미 모델에 노출됐고, [CX01–CX16](nlu_safety_context_fresh_review.md)은 코드 작성자가 문장을 본 후 규칙을 고쳤으므로 **둘 다 미노출 성능 평가가 아니다**.

## 선택한 방법과 이유

기존 보호 경로는 명시적 위험을 모델보다 먼저 처리해 모델의 안전 필드 누락을 보완한다. 이번에는 별도 모델 호출을 추가하지 않고, 위험 단서와 실제 발생을 나타내는 표현을 함께 요구하는 제한된 패턴을 보강했다. 대상은 탄내·매캐한 냄새, 전기 부품의 고열, 충전대의 연무, 배터리 덮개 변형, 전원 부품의 불꽃, 연기의 과거형이다. 가정형·부정형·타인 후기와 다른 제품의 경험은 위험 상태로 확정하지 않는 방향을 유지한다.

이는 모든 한국어 안전 발화를 이해하는 의미 분석기가 아니다. 안전 단서가 나타나는 방식이 더 다양해지면 누락할 수 있고, 위험 단어가 다른 대상에 붙는 복합 문장에서는 과잉 차단할 수 있다. 그래서 개발 사례 통과만으로 보호 경로의 민감도나 특이도를 주장하지 않는다.

## 개발 점검 결과

- 이전에 놓친 SC05–SC08과 기존 SC01–SC04를 포함한 노출된 위험 8건을 직접 규칙 검사에서 감지했다.
- 노출된 비위험 SC09–SC16 8건은 직접 규칙 검사에서 차단하지 않았다.
- 사용자가 문장·안전 방향을 채택한 CX01–CX16에서도 개발용 직접 규칙 검사 결과는 위험 8/8 감지, 비위험 0/8 차단이었다. CX는 코드 수정 전에 작성·열람됐으므로 이 숫자는 회귀 점검일 뿐 포트폴리오 성능 개선율이 아니다.

다음 실모델 평가는 이 코드 버전을 먼저 커밋해 고정한 뒤, 별도의 AI 작성 발화와 모든 행동·필드 정답을 사용자에게 검수받고 모델 노출 전에 실행 조건을 동결한다. 기존 SC·CX 사례는 새 분모에서 제외한다.
