# A/S 안전 그래프·빈 정보 계약 탐색 짝비교

## 평가 경계

SC01–SC20은 AI가 작성하고 사용자가 문장·의미 방향과 모든 행동·필드 값을 별도로 검수한 A/S `greeting` 발화다. 독립적인 두 번째 검수자는 없다. 모델 실행 전 [데이터](../../evals/structured_nlu/data/ai_heldout/nlu-safety-contract-reviewed.v1.json)와 [검수 원장](../../evals/structured_nlu/data/ai_heldout/nlu-safety-contract-ledger.v1.json)을 `0c481d8`에, [실행 프로토콜](../../evals/structured_nlu/data/ai_heldout/nlu-safety-contract-graph-pair-protocol.v1.json)을 `70e09fb`에 고정했다. 두 코드의 소스 해시·모델 파일 해시·요청 설정·로컬 컨테이너 설정을 실행 전에 대조했다.

이전 코드 `ae91656`과 안전 보호 경로·빈 정보 정규화가 있는 코드 `9eacb92`를 **같은 Kanana Q5**로 비교했다. 사례마다 실행 순서를 번갈아 적용했고 5쌍마다 서버를 재시작했다. 결과에는 그래프 최종 상태, 정규화된 모델 출력, 요청 횟수, 오류 유형과 지연 시간만 남겼다. 프롬프트와 모델 응답 전문은 저장하지 않았다. AWS는 사용하지 않았다.

## 결과

[결과 파일](../../evals/structured_nlu/results/nlu-safety-contract-graph-pair-v1.json)의 20쌍·40개 그래프 실행을 [독립 검증기](../../scripts/verify_nlu_safety_graph_pair.py)로 다시 계산했다. 계획한 서버 재시작은 5·10·15쌍 뒤에 기록됐다.

리뷰 뒤 평가 실행기의 전송 오류 처리와 워커 경로 검사를 보강했다. 위 결과는 동결 프로토콜의 실행기 해시와 일치하는 `70e09fb` 버전으로 재현한다. 현재 실행기로 과거 프로토콜을 조용히 다시 실행하지 않는다. 이번 기록의 시도 오류는 계약 검증 `ValueError`뿐이며 전송 오류는 없었다.

| 지표 | 이전 `ae91656` | 수정 `9eacb92` |
| --- | ---: | ---: |
| 실제 위험 8건 중 안전 보호 상태 진입 | 0/8 | 4/8 |
| 위험 진술이 없는 8건 중 잘못된 안전 보호 상태 진입 | 0/8 | 1/8 |
| 범위 밖 문의 4건의 최종 출력 계약 통과 | 2/4 | 4/4 |
| 범위 밖 문의 4건의 `unknown` 행동 | 2/4 | 4/4 |
| 범위 밖 문의의 총 모델 요청 | 6회 | 4회 |

SC01–SC04는 수정 코드의 명시적 안전 가드가 모델 요청 없이 안전 상태로 보냈다. SC05–SC08의 다른 위험 표현은 두 코드 모두 놓쳤다. SC10은 **다른 제품**의 배터리 팽창을 인용했는데 수정 코드의 정규식이 문장 중간의 “부풀었다”까지 잡아 잘못 차단했다. SC17·SC20은 이전 코드에서 각각 두 차례 계약 검증에 실패했으나 수정 코드에서는 첫 시도에 `unknown`으로 통과했다. 결과에는 이전 코드의 오류 유형만 `ValueError`로 남아 있으므로 이 두 건의 세부 검증 메시지까지 단정하지 않는다.

**해석:** 안전 경로 재현율과 계약 통과는 이 작은 표본에서 개선됐지만, 안전 누락 4건과 과잉 차단 1건이 남았다. 따라서 안전 처리 완료나 전체 서비스 정확도 개선이라고 쓰지 않는다. 분모는 AI 작성·1인 검수 A/S 한 상태의 8·8·4건이며 실제 사용자 발화 분포를 대표하지 않는다. 이 20건은 이번 실행 이후 개발·회귀 사례로만 쓴다.

`9eacb92`의 빈 정보 `unknown` 정규화는 리뷰에서 추출 실패를 숨길 위험이 확인돼 이후 운영 코드에서 철회했다. 따라서 범위 밖 계약 통과 4/4는 **현재 PR의 최종 코드 성능이 아니라 철회한 후보의 실험 수치**다. 이 수치를 현재 구현의 성과로 인용하지 않는다.

## 결과 확인 뒤 수정

SC10을 본 뒤 “부풀었다는/부풀었다고”처럼 위험 진술을 인용하는 어미를 즉시 위험으로 분류하지 않도록 배터리 패턴을 좁혔다. 실제 위험 진술 “부풀었다”는 유지하는 회귀 테스트를 더했다. **이 수정은 위 결과의 후보 코드 `9eacb92`에 포함되지 않는다.** 노출된 SC10을 다시 통과시켜도 새 모델 성능 근거가 되지 않는다. 다른 위험 표현 SC05–SC08을 그대로 정규식에 추가해 이번 표본 점수만 올리는 대신, 표현 확장 시의 오탐 범위를 별도 새 사례로 검수·평가해야 한다.
