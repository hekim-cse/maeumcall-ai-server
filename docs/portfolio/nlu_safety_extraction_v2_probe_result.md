2026-11-14에 기존 모델 노출 이력이 있는 AI 작성·사용자 검수 자료 중 RE03·RE06·RE09·V01·V04·V07 여섯 건을 비교했다. 짧은 원문 인용(`quote`)과 원문에서 생성한 후보 ID 선택(`ids`)을 사례마다 교대 순서로 한 번씩 실행했다. 후보·실행기·검증기·입력은 커밋 `c0ef14aa25787fc3730b5d38257aaf382e668c99`, [사전 프로토콜](../../evals/structured_nlu/data/ai_heldout/as-safety-extraction-v2-probe-protocol.v1.json)은 커밋 `40cbc7ffce7dff3b3006fcd61afc8bcd526155b1`에 고정했다. 프로토콜 SHA-256은 `c5cc4020b157f34f578cfc0aa207281c1ec6705c2a4d75e7ce79771bb0f3dcff`다.

ID 방식의 13/18은 **후보 생성 재현율**이지 모델 선택 정확도가 아니다. 두 방식 모두 E/B/C 의미 추출이 충분하다고 볼 수 없다. 별도 AI 보조 정성 점검에서는 짧은 인용 방식이 여섯 건 중 네 건의 위험 사건을 의미상 잡았지만, 위험 물리 주체는 여섯 건 모두 정확히 분리하지 못했다. 이 판단은 사람 확정 라벨이 아니며 위 표의 정확 인용 수치와 구분한다.

사전 선택 기준인 계약 통과, E/B/C 참조 적중, 후보 재현율, 지연 순으로 짧은 인용 방식을 다음 22건 개발 실행에 선택했다. 후보 ID 방식은 원문 후보 생성 단계에서 5/18이 빠지고, 모델 선택도 0/18 정확 일치였으며 호출 지연이 더 길었다. 선택 여섯 건이 뒤의 22건에도 포함되므로 다음 결과는 독립 일반화 평가가 아니다.
