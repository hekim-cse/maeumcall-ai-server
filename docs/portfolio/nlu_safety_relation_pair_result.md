# A/S 제품과 위험 사건 관계 후보: 새 발화 쌍 비교

## 평가 경계

- 2026-11-09에 사용자가 문장·경로와 모든 근거 번호·상태를 탐색용으로 검수한 AI 작성 RE01–RE16을 사용했다. 사람 작성 독립 사례나 공식 정확도 평가가 아니다.
- 사례와 정답, 비교기, 검증기, 모델·요청 설정의 SHA-256을 첫 모델 호출 전에 [프로토콜](../../evals/structured_nlu/data/ai_heldout/as-safety-relation-pair-protocol.v1.json)로 커밋했다. 동일한 Kanana Q5 파일(SHA-256 `644b04cd…f3d`)을 CPU 2개·메모리 4 GiB·고정 컨테이너에서 사용했다. 각 사례에 기존 단일 근거 방식과 새 제품·위험 이중 근거 방식을 교대로 호출했다. 실패는 재시도하지 않고 오류로 센다.
- [원자료](../../evals/structured_nlu/data/ai_heldout/as-safety-relation-pair-result.v1.json)는 발화와 모델 출력 전문을 저장하지 않는다. 독립 [검증기](../../scripts/verify_as_safety_relation_pair.py)가 사례 순서, 판단값 범위, 경로, 집계를 다시 계산해 통과했다.

## 결과

| 기대 경로·사례 | 기존 경로 일치 | 관계 후보 경로 일치 | 관계 후보의 특이사항 |
| --- | ---: | ---: | --- |
| 현재 제품의 관찰된 위험, RE01–04 | 3/4 | 4/4 | 실제 위험 누락 1건 감소 |
| 위험 발생·출처 불확실, RE05–08 | 2/4 | 1/4 | 즉시 보호로 성급히 분기한 사례 1→2건 |
| 다른 출처의 위험, RE09–12 | 3/4 | 1/4 | 즉시 보호 오분기 1→3건 |
| 부정·가정·일반 질문, RE13–16 | 1/4 | 2/4 | RE13 후보 계약 오류 1건, 즉시 보호 오분기 3→1건 |
| **전체 경로 일치** | **9/16** | **8/16** | 오류도 분모에 포함 |

관계 후보의 세부 필드 일치는 `product_index` 13/16, `hazard_index` 13/16, `target_relation` 8/16, `event_status` 10/16이고 네 필드 완전 일치는 5/16이다. 근거 번호를 맞혀도 위험이 현재 접수 제품에 속하는지 판단하는 단계에서 실패했다. 특히 RE09·11·12는 다른 출처의 위험을 현재 제품의 실제 위험으로 판단했다. RE13의 오류는 원문 출력을 보존하지 않아 형식 오류의 세부 유형까지는 판별할 수 없다.

현재 후보는 전체 경로 일치가 낮고, 다른 출처 위험을 현재 제품의 위험으로 오분기하는 문제가 크다. **서비스 그래프에 연결하지 않는다.** 이 결과를 개선율이나 안전성 입증으로 쓰지 않는다. 작은 표적 사례에서의 실패 원인 분석이다. 다음 후보는 더 많은 규칙을 덧붙이기 전에 두 문장 사이의 소유·지시 관계 판단을 분리해서 검증하고, 새로 작성·검수한 사례로 다시 평가해야 한다.
