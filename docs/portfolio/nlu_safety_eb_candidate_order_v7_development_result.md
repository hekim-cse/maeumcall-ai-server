# A/S 위험 주체 원문 후보 목록·순서 대조 개발 진단 결과

> 2026-11-21. 사용자 검수 PC01·NC01 두 AI 작성 기노출 문장의 개발 진단이다. **후보 목록의 다음 개발 실험 진입 관문은 실패했다.** 공식 정확도·개선율, 일반화 성능 또는 서비스 안전 성능으로 쓰지 않는다.

## 실행과 독립 검증

- [실행 전 방법](nlu_safety_eb_candidate_order_v7_method.md)대로 PC01 A→B→C, NC01 C→B→A의 여섯 요청을 각 한 번 실행했다. A는 기존 두 필드 기준선, B는 원문에서만 생성한 후보 목록 원순, C는 **같은 후보·ID의 표시 순서만 역순**이다. B/C의 목록 제공에는 추가 지시문도 들어가므로 A와의 차이를 목록만의 인과 효과라고 보지 않는다. B/C도 원문 구절 객체를 반환하므로 과거 RE/V의 ID 반환 계약을 직접 재시험한 것은 아니다.
- 코드·방법은 모델 호출 전 커밋 `20b3aef44f1f662188b32dd40335b8df0086b275`, [프로토콜](../../evals/structured_nlu/data/ai_heldout/as-safety-eb-candidate-order-v7-development-protocol.json)은 별도 선행 커밋 `1908ccb`에 고정했다. 프로토콜 SHA-256은 `0047f11fab48db468f08d7ef524c00c39b1199d837b93cfe2c7773e3b65b7102`다. 여섯 요청 본문 해시·순서, 원문 후보 목록의 원순·역순 해시와 후보 수를 기록했다. 정답 B·종류는 요청·후보 생성에 넣지 않았다.
- PC01 후보는 22개이고 정답 B 구절이 **P014**에 포함됐다. NC01 후보는 35개이며 정답은 출처 불명 공란이다. 같은 Q5 모델 파일 SHA-256 `644b04cde835d486df33c6d4d7552ba367fcb28802fe39b6b4bb9c60b9ab6f3d`와 고정 컨테이너 이미지 digest `sha256:17155a3ce4cc906728ec99a2814bf0b4eaffaf3b4872bad8c3affed310cdbc35`를 사용했다. 입력 토큰 수는 같은 서버의 대화 요청 토큰 계산으로 **294–857개**였고, 최대 생성 320개를 더한 최댓값 1,177은 컨텍스트 4,096개보다 작았다. 출력 토큰 수는 수집하지 않았다.
- [공개 저널](../../evals/structured_nlu/data/ai_heldout/as-safety-eb-candidate-order-v7-development-journal.v1.jsonl)은 원문·프롬프트·응답을 담지 않는다. SHA-256은 `316a1d72abccb2b792928877ac9a526be187154917d4a0e815539f517ddfeb6a`다. 원시 응답 6개는 저장소 밖 권한 제한 디렉터리에 두었다. 독립 검증기는 고정 요청 재구성, 프로토콜·저널·원시 응답 해시·순서·권한, 출력 계약·검수 정답을 대조했다. 실행 당시와 재생 검증기 SHA-256은 모두 `c143bd868bd334eb1c838fdedc82f1271a86e4206f3bb1229f470f8a2e426413`이다. 관련 테스트 75개와 Ruff 검사에 통과했다.

## 조건별 관찰

| 사례·조건 | 출력 계약 | B 구절 | 종류 | 판단 |
| --- | --- | --- | --- | --- |
| PC01 A 기준선 | 통과 | 공란 | `unresolved` | 양성 실패 |
| PC01 B 원순 | 통과 | 비공란·원문 인용 유효, **정답 불일치** | `location` 일치 | 정답 구절보다 긴 인용 |
| PC01 C 역순 | 통과 | 비공란·원문 인용 유효, **정답 불일치** | `location` 일치 | 정답 구절보다 긴 인용 |
| NC01 C 역순 | 통과 | 공란 | `unresolved` | 정당 보류 |
| NC01 B 원순 | **실패: `quote_not_anchored`** | 의미 채점 제외 | 의미 채점 제외 | 원문 구절 위치 계약 오류 |
| NC01 A 기준선 | 통과 | 공란 | `unresolved` | 정당 보류 |

출력 계약은 **5/6**, 계약 오류 **1/6**, 전송·종료 오류 **0/6**이다. PC01의 B 정확 일치는 A/B/C **0/3**, B/C만 보면 **0/2**이고, B/C의 종류 일치는 **2/2**다. NC01은 A/C에서 정당 보류했지만 B는 계약 오류여서 정당 보류 여부를 채점하지 않는다. 계약 유효 응답에서 근거 없는 비공란 확정은 **0건**이다. B/C 모두 PC01의 정확 B·종류와 NC01의 유효 보류를 충족해야 하는 사전 관문은 **실패**했다. 요청 지연 합계 45,125.681ms는 이 여섯 로컬 호출의 기술 기록이며 서비스 속도·개선 근거가 아니다.

원순·역순 모두 PC01의 비공란을 이끌었지만 정답 구절을 **과다 인용**했다. 원순은 후보 P013(8자), 역순은 P022(17자)를 인용했고 정답 후보는 P014(6자)였다. 후보에 정확한 구절이 존재했음에도 경계를 다르게 고른 관찰이다. 순서가 바뀌어도 같은 종류의 실패가 남았다는 사실만으로 순서 효과가 없다고 일반화할 수 없다. NC01에서는 순서별 계약 결과가 달랐으나 각각 한 번의 실행이고 내용 오류도 있어 순서가 원인이라고 단정하지 않는다. 이 작은 결과는 **형식상 비공란 출력**과 **정확한 구절 선택**이 다른 문제임을 다시 보여 준다. v5의 기준선 관문 실패를 소급해 통과 처리하지 않는다.

## 다음 판단과 경계

이번 후보 목록 인터페이스를 ES 전체로 확대하거나 서비스 안전 분기에 연결하지 않는다. 다음에는 원문 기반 후보의 긴 구절을 그대로 선택하게 하는 구조를 점검하고, **짧은 주체 구절 경계**와 출처 불명 보류를 함께 지킬 수 있는 방법을 오프라인에서 먼저 설계해야 한다. 구절 길이만 줄이는 사후 채점이나 정답 후보 주입은 하지 않는다. 별도 미노출 사례를 준비하기 전에는 개선율을 주장하지 않는다. B→A와 최종 안전 경로는 평가하지 않았고 TX·GB 봉인 자료도 사용하지 않았다. 실험 뒤 컨테이너와 Docker Desktop을 종료했으며 AWS·KT cloud는 사용하지 않았다. 이슈 #93의 완료 조건은 아직 충족되지 않았다.
