# A/S ES 출처 후보 생성과 선택 분리 감사 결과

[사전 방법](nlu_safety_source_selection_es_method.md)과 감사 코드를 `d8b6b4f`에 고정하고, 이미 노출된 사용자 검수 ES의 사건 19개를 계산했다. 관찰 18개와 불확실 1개를 평가했고 미발생 3개를 제외했다. 두 규칙 모두 발화별 전체 후보 목록과 검수 사건 구절·발생 상태를 받았다.

정답 출처가 있는 18개 사건에서 정답 구절은 **18/18** 후보 목록에 있었다. 미생성과 한도 탈락은 각각 **0/18**이었다.

| 지표 | 기기 문맥 규칙 | 기기 조작 근거 규칙 |
| --- | ---: | ---: |
| 정답 출처를 유일하게 선택 | 0/18 | 0/18 |
| 정답 후보가 있었으나 보류 | 18/18 | 18/18 |
| 정답 출처 공란을 보류 | 1/1 | 1/1 |
| 오선택, 복수 승인, 판별 오류 | 각 0/19 | 각 0/19 |

OP 대조에서 승인 세 건을 회복한 확장은 이 ES 자료에서 새 선택을 만들지 못했다. 구체적으로 ES02는 `오늘` 뒤에 출처가 나와 절의 맨 앞에서 시작하는 출처만 받는 규칙에 걸린다. ES14는 위험 사건 뒤에 후속 조치가 이어져 사건이 절의 끝에 있어야 한다는 조건을 충족하지 못한다. ES03은 물체의 변형을 서술하지만 여러 변화와 후속 수리 요청이 이어져 단순 주어·변형 서술 검사를 통과하지 못한다. ES18은 검수 발생 상태가 불확실해 두 규칙이 보류했다. 이는 사례별 구조 진단이다. 어느 조건 하나를 완화하면 성공한다는 의미로 해석하지 않는다.

다음에는 위치 표현을 통째로 허용하기 전에 시간 부사 뒤의 직접 출처와 사건 뒤 후속 행동을 각각 분리해 개발 대조한다. 같은 문장 안의 다른 사건이나 관찰 위치가 출처로 승격되는지도 함께 본다. 이후 관계와 안전 경로 검증은 이슈 #93의 별도 조건으로 진행한다.

[사건별 결과](../../evals/structured_nlu/results/as-safety-source-selection-es-development.v1.json)는 `python -m scripts.audit_as_safety_source_selection`으로 재현한다. Kiwi 0.23.2, 사전 모델 0.23.0을 썼다. 신선한 미노출 자료나 실서비스 정확도 자료로 사용할 수 없다.
