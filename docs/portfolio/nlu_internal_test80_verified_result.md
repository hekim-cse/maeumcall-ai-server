# 구조화 NLU 범위 계약: 신규 내부 표본 실모델 짝 비교

> **원문 재생 검증과 독립 수치·방법 감사 완료.** 2026-11-17(한국 시간) 로컬 Kanana Q5에서 기존 코드 `c46c27a52bc8cfc6e11bfa62985aa6a90d6f4da3`와 범위 계약 후보 `04af27849563f7b30845441e0f8fc6ca90f876ff`를 비교했다. 발화는 **AI 작성·사용자 1인 문장/행동/전체 필드 검수** 자료다. 외부 공식 벤치마크, 사람 직접 작성 표본, 운영 통화의 정확도가 아니다. 모델 응답 원문은 저장소 밖의 권한 제한 폴더에 보존했다.

## 실험 경계

- [표본 설계](nlu_internal_test64_sampling_plan_v1.md)는 개발 validation 결과 확인 전에 커밋했다. 후보 선택 후 16개 업무마다 `greeting`/후속 상태 × 업무 안/범위 밖 각 1건을 새로 만들어 **일반 test 64건**으로 고정했다. 접수 제품의 직접 위험·불확실·다른 출처·미발생 각 4건은 **별도 안전 16건**으로 고정했고 정확도 64건의 분모에 합치지 않았다.
- 검수한 정답 JSON의 SHA-256은 일반 test `b3aa00925bd52b826a3e1ffd1423bf070148ccb945b0af7ac69c5f9ad3b03bef`, 안전 `315e75e9e82254bd55e32753b610e0f1b066dd6fa44d611fa536b8d60098c377`다. 두 코드가 같은 입력·모델·이미지·요청 설정을 사용했다.
- 최종 프로토콜 SHA-256은 [일반 test](../../evals/structured_nlu/data/ai_heldout/nlu-internal-test64-pair-protocol.v1.json) `9756af64466c5edae8ce85c4cc00c105a4c6fcb68266ea866773644995fb9984`, [안전 표본](../../evals/structured_nlu/data/ai_heldout/nlu-internal-safety16-pair-protocol.v1.json) `09eabc0caa33e9a274cb44112bb80e9f017e1fdf5c72ef6ad26dee6017ba24af`다. 이전 프로토콜의 실행 전 출력 표기 정정은 [별도 기록](nlu_internal_test80_protocol_prerun_revision.md)에 남겼다.
- 일반 test는 **64쌍·128 arm 평가, 원시 모델 응답 176개, 계획 재시작 15회**다. 안전은 **16쌍·32 arm 평가, 원시 응답 33개, 계획 재시작 3회**다. 전송 오류·OOM·예기치 않은 재시작 없이 끝났고, 원시 응답 해시·저널·각 arm 결과를 재생한 [일반 검증 영수증](../../evals/structured_nlu/results/nlu-internal-test64-pair-v1-verified.json)과 [안전 검증 영수증](../../evals/structured_nlu/results/nlu-internal-safety16-pair-v1-verified.json)이 발행됐다. 검증기는 실행기와 분석·채점 함수를 공유하므로 **독립 구현 채점**은 아니다.

짝지은 전이표는 **둘 다 정답 9건, 기존만 1건, 후보만 11건, 둘 다 오답 43건**이다. 업무 안 32건의 전이는 각각 `둘 다 3 / 기존만 1 / 후보만 1 / 둘 다 오답 27`, 범위 밖 32건은 `둘 다 6 / 기존만 0 / 후보만 10 / 둘 다 오답 16`이다. 이번 표본의 순증가 10건은 모두 **범위 밖 `unknown` 적중**에서 나왔다. 업무 안의 의미·필드 추출이 개선됐다고 주장할 수 없다.

사전 지정한 32개 `업무×범위` 층의 2건에서 2개를 복원추출하되 같은 사례의 기존·후보 결과를 쌍으로 유지한 부트스트랩 20,000회(seed 0)의 차이 95% 구간은 **+9.375~+21.875%p**였다. 하한이 0을 넘었다. 이는 의도적으로 균형 맞춘 **이 내부 표본의 재표집 기술통계**이며 실제 통화 모집단 개선에 대한 95% 보증이 아니다.

### 사례별 사후 진단

후보의 범위 밖 32건은 `전체 일치 16 / 최종 계약 실패 10 / 계약 유효하지만 오답 6`으로 나뉜다. 업무 안 32건은 `전체 일치 4 / 최종 계약 실패 10 / 계약 유효하지만 오답 18`이다. 후보의 최종 계약 실패 20건은 고객센터 7건, 배달 7건, 시청 6건이며 교수님·예약 업무에서는 없었다. 이 분류는 **결과를 본 뒤의 원인 탐색**이지 사전 지정한 추가 개선 판정 지표가 아니다.

업무 안의 계약 유효 오답 18건 중 17건에서 기대 비공란 필드 불일치가 있었다. 이 17건의 필드 불일치 33개는 **비공란 오답값 31개와 누락 2개**다. 날짜 `2027년 1월 9일`과 `2027-01-09`, 이용 시간 `한 시간 반`과 `1.5h`, 인원 `네 명`과 `4`처럼 엄격한 문자열 채점에 걸리는 표기 차이도 일부 포함한다. 반면 `저녁 6시쯤`을 `18:00`으로 바꾸면 근사성이 사라지므로 모든 차이를 의미상 정답으로 바꿀 수 없다. 동결된 정답과 전체 일치 점수는 **사후에 수정하지 않았다**.

## 별도 안전 16건

안전 관문은 실제 서비스 그래프 전체를 실행한 점수가 아니라, 정규화된 `safety_status=safety_issue`가 즉시 보호 경로를 발동시킬 **필드 신호**인지 확인한 결과다.

| 범주 | 기존 `safety_issue` 신호 | 후보 신호 | 해석 |
| --- | ---: | ---: | --- |
| 현재 접수 제품의 직접 위험 | 2/4 | 4/4 | 후보의 새 직접 위험 누락 0건, 기존 누락 2건 회복 |
| 위험 발생·출처 불확실 | 0/4 | 1/4 | 정답 공란인 불확실 사례에서 후보의 `safety_issue` 신호 1건 |
| 다른 물건에서 발생한 위험 | 1/4 | 2/4 | **오경고 증가** |
| 가정·부정·미발생 | 0/4 | 0/4 | 이 표본에서 새 오경고 없음 |

다른 출처·미발생 8건을 합친 오경고는 **1/8→2/8**이다. 안전 16건의 **사례 전체 일치는 양쪽 모두 0/16**이다. 직접 위험 4건에서 회복이 관찰됐지만 분모가 작고 다른 출처에 대한 오경고가 악화했으므로 안전 성능 전반의 개선으로 일반화하지 않는다. 현행 그래프에는 불확실한 위험을 따로 확인하는 상태가 없어 이 영역의 응대 적절성은 이번 필드 신호 지표로 판단할 수 없다.

안전 16건의 최종 출력 계약 통과도 **16/16→15/16**으로 1건 줄었다. 직접 위험 신호의 회복과 별도로 이 형식 회귀를 유지한다.

사후 사례 대조에서 후보는 직접 위험 SS01·SS03의 `safety_issue` 신호를 회복했지만, 불확실한 열감 SS07과 다른 출처의 누출 SS11에는 새 위험 신호를 냈다. 이 사례들에 맞춰 동결 test를 다시 훈련·선택 자료로 사용하지 않는다. 다음 후보는 **새 개발 사례**에서 계약 실패의 구조화된 오류 코드, 날짜·시간·수량 정규화와 근사성 보존, 제품과 위험 사건의 출처 관계 및 불확실성 확인을 검증해야 한다. 그 후보의 성능 주장은 다시 새 미노출 test가 필요하다.

## 발행 판단과 한계

PR 리뷰에서 동결 정답의 두 의미·표기 경계를 추가로 발견했다. SS14는 무늬와 발열만 부정하는 발화를 `no_safety_issue`로 채택했지만, 다른 안전 이상까지 없다고 확정하기에는 근거가 약하다. IT33의 주문번호 정답은 `주문번호 M-928`로, 같은 묶음의 다른 주문번호 정답과 달리 접두어를 포함한다. 이 둘은 실행 후 발견한 문제이므로 **동결 정답·원시 결과·검증 영수증을 소급 수정하지 않았다**. 저장된 출력에서 IT33은 두 조건 모두 `M-928`을 추출했지만 다른 필드도 틀려 사례 전체 일치 여부는 어느 쪽도 바뀌지 않는다. SS14도 두 조건 모두 다른 필드가 틀려 사례 전체 일치 여부가 바뀌지 않고, 이 안전 관문은 `safety_issue` 신호만 세므로 해당 경계의 가정상 정답 변경은 위 직접 위험·오경고 건수를 바꾸지 않는다. 따라서 아래 수치는 **실행 전 동결 정답 기준**의 결과이며, 새 평가에서는 두 정답 기준을 먼저 다시 검수해야 한다.

[동결 후 원문·노출 점검](nlu_internal_test80_exposure_audit_v1.md)에서 최종 80건은 서로 다른 발화였고, 검사한 기존 구조화 NLU 데이터·validation·포트폴리오 문서·보존 실행 원문과 원문 정확 일치가 없었다. 가까운 사건을 재사용할 위험이 있던 사례는 모델 실행 전 교체하고 사용자에게 다시 검수받았다. 이 검사는 저장소 밖의 모든 과거 노출이나 의미상 모든 바꿔쓰기를 배제하지 않는다. 정답의 사례별 이유 문장은 AI가 채택된 라벨을 요약했고, 독립된 두 번째 사람 검수자는 없었다.

사전 지정한 **내부 표본의 개선 확인 조건**인 전체 일치 차이 구간 하한 `>0`과 직접 위험의 새 누락 `0건`은 충족했다. 따라서 이 **AI 작성·사용자 1인 검수 내부 표본에서, 범위 밖 요청 처리로 사례 전체 일치가 +15.625%p 높았다**고 쓸 수 있다. 검증 영수증은 기술적 원문 재생 상태만 `verified`로 표시하며 별도 노출 감사 완료를 자동 반영하지 않아 `publication_status`를 잠정 상태로 보존했다. 이 문서가 제한된 노출 감사와 발행 해석을 함께 기록한다. 외부 공식 점수나 운영 전체 정확도 개선율로 표기하지 않는다.
