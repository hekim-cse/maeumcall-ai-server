## 이번 검토에서 확인할 것

1. **문장이 실제 통화에서 자연스러운지**, 기존 개발 발화의 단순 바꿔쓰기가 아닌지 확인한다. 고정 날짜는 평가 시점에 따라 정답이 달라지지 않도록 적었지만, 예약 날짜 자체가 상황에 맞는지도 본다.
2. IT의 `업무 안/범위 밖`과 후속 상태가 주어진 상황에서의 판단을 확인한다. 후속 상태의 직전 질문은 문맥 설명이며 직접 분석기 입력에는 전달되지 않는다. 특히 교수님 IT16·IT20·IT24는 이전 대화 주제가 있어도 현재 발화를 범위 밖으로 볼지, 여권 IT43은 온라인 신청 자격 문의를 지원 범위에 넣을지 판단이 필요하다. 예약 IT51·IT55·IT59·IT63은 이전 예약 정보가 입력되지 않아 상태명과 현재 문장만으로 해석해야 한다.
3. SS의 **접수 제품에서 실제 위험이 발생했는지**와 현장 전체의 일반 안전 안내를 분리해 판단한다. 특히 SS03의 배터리실 누출, SS06·SS08의 출처/손상 불확실, SS09·SS11·SS12의 다른 출처 사건, SS13의 부분적 부정을 확인한다.

문장·상태·방향에 이어 [IT01–IT32 전체 필드](nlu_internal_test64_field_review_part_a.md), [IT33–IT64 전체 필드](nlu_internal_test64_field_review_part_b.md), [SS01–SS16 전체 필드](nlu_internal_safety16_field_review.md)도 사용자가 채택했다. 계약·노출 검사를 마치고 코드·데이터를 동결한 뒤, 두 조건의 실모델 짝 비교와 원문 재생을 거쳐야 내부 공식 표본 결과가 된다. 재생 검증기는 실행기와 채점 함수를 공유하므로 독립 구현 채점이라고 표현하지 않는다.

초안 80개의 ID와 원문은 서로 달랐다. 교체 문장 6건과 IT27 최종 문장도 검토 범위의 이전 자료에서 원문 일치·고위험 상황 반복을 찾지 못했다. 동결한 최종 80건의 재검사 범위와 결과는 [노출 점검](nlu_internal_test80_exposure_audit_v1.md)에 기록했다. 저장소 밖의 과거 노출이나 모든 의미상 바꿔쓰기의 부재는 증명할 수 없다.
