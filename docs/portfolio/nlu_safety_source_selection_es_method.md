# A/S ES 출처 후보 생성과 선택 분리 감사

기노출 ES 개발 자료에서 최신 조작 근거 규칙이 두 후보를 제공한 OP 평가 밖에서도 출처를 찾는지 확인한다. 후보 생성은 검수 원문만 사용한다. 판별 규칙에는 기존에 사용자가 검수한 사건 구절 E와 발생 상태를 제공한다. 정답 출처 B는 각 사건의 두 규칙이 결정을 마친 뒤에만 채점에 사용한다. 접수 대상 A, 제품 관계, 안전 경로 정답은 사용하지 않는다.

- 고정 입력은 [기존 ES 20개 발화의 검수본](../../evals/structured_nlu/data/ai_heldout/as-safety-event-source-v4-exploration-reviewed.v1.json)이다. 관찰·불확실 사건 19개를 평가하며 미발생 사건 3개는 건너뛴다. TX와 GB는 사용하지 않는다.
- 전체 발화의 최대 5토큰 원문 후보를 최대 192개까지 제공한다. 후보의 원문 절 번호와 코드포인트 시작·끝 위치가 B와 모두 같은지 확인한다. 정답 미생성과 생성 후 한도 탈락을 구분한다.
- 기존 기기 문맥 규칙과 새 기기 조작 규칙을 같은 전체 후보 목록에 적용한다. 오류가 없고 후보를 하나 승인한 경우에만 선택으로 센다. 둘 이상인 경우 모호로 보류한다.
- 결과는 정답 후보 가용성, 정확 선택, 오선택, 정답 후보가 있는데 보류, 정답 공란의 올바른 보류, 복수 승인, 오류로 보고한다. 후보가 없어서 보류한 경우에는 미생성과 한도 탈락을 따로 기록한다. 발생 상태별 결과는 해당 사건 행에서 확인할 수 있다.

코드와 입력 SHA-256을 실행 전에 고정하고, 입력이나 점수를 맞추기 위한 규칙 변경 없이 결과를 보존한다. 모델·클라우드 없이 재현하는 개발 감사이며 서비스의 제품 관계, 안전 경로, 실제 정확도는 평가 범위에 포함되지 않는다.
