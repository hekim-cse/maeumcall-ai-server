# A/S 안전 관계 계약 오류 재발 진단 계획

## 확인된 사실

[기존 개발 결과](nlu_safety_typed_relation_development_result.md)의 후보 오류 28/32건은 모두 응답 종료 이유 `stop`, 계약 단계의 정확한 예외 유형 `ValueError`다. JSON 문법 오류였다면 `JSONDecodeError`가 기록됐을 것이다. 성공적으로 반환된 후보 판단은 저장용 유한값 스키마와 같은 필드·값을 사용하므로, 실패 범위는 후보의 필드 집합, 값 또는 근거 번호 일관성 검증으로 좁혀진다. 응답 원문과 예외 메시지를 보존하지 않아 어느 규칙이 각 건에서 실패했는지는 기존 저널에서 복원할 수 없다.

## 새 진단의 범위

이미 모델에 노출된 RE01–RE16·V01–V16을 후보 단독으로 다시 호출한다. 기존 Q5 파일, 이미지, 프롬프트, JSON 스키마, 요청 설정은 유지한다. 새 실행은 **기존 28건의 원인 재생이 아니라 같은 조건에서 오류가 재발하는지 확인하는 별도 개발 진단**이다. TX와 서비스 그래프는 사용하지 않는다.

응답 본문이나 예외 문구는 저장하지 않는다. 사례 ID·종료 이유·지연·성공 시 유한 판단값, 실패 시 사전에 정의한 유한 오류 코드만 새 저널에 남긴다. 호출 시작을 기록한 뒤 중단되면 재개하거나 재시도하지 않는다. 코드, 입력, 모델, 요청 설정과 기존 저널 해시를 첫 호출 전에 프로토콜로 고정한다. 독립 검증기는 기록의 구조·해시·순서·분모·유한값을 검증하되, 저장하지 않은 원문에서 오류 코드를 다시 추론했다고 주장하지 않는다.

결과는 계약 오류 유형의 **재발 빈도**로만 보고한다. 이 결과로 후보를 다시 채택하거나 공식 정확도 개선을 주장하지 않는다. 진단 후 다음 후보의 필드 수나 근거 요구를 줄일지 결정하되, TX를 통한 조정은 하지 않는다.
