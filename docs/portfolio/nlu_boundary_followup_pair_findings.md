# NLU 업무 필드·날짜 경계 후속 탐색 비교

2026-11-06에 사용자에게 **모델 실행 전에 탐색용으로 채택받은 AI 작성 발화
10건**을 로컬 Q5 GGUF에서 기본 지시와 그룹별 후보 지시로 비교했다.
[BF01–BF06](nlu_boundary_followup_review.md)는 업무 행동·필드 일관성,
BF07–BF10은 날짜 정규화 대조다. 각 사례를 조건별 2회씩 실행하고 두 번째
반복에서는 사례 순서와 조건 순서를 뒤집었다. 총 **고유 발화 10건·관찰
40회**이며 반복 관찰은 독립 발화가 아니다. [입력 초안과 검수 원장](../../evals/structured_nlu/data/exploratory/boundary-followup-review-draft-2026-11-05.json)은
커밋 `a020393`에, [두 후보와 실행기](../../scripts/probe_gguf_boundary_followup_pair.py)는
커밋 `6711ca9`에 모델 노출 전에 고정했다.
이후 PR 리뷰에서 실행기의 의존성 해시 범위와 중단 시 체크포인트를 보강했다.
**이미 완료된 보고서의 코드 해시는 실행 당시 `6711ca9` 파일을 가리키며**
후속 코드로 재실행하거나 과거 수치를 덮어쓰지 않았다.

계약 실패 13회는 모두 마지막 오류가 `action_missing_required_field`였다.
업무 후보는 BF02에서 기본의 0/2 계약 실패를 2/2 계약 통과로 바꾸고
`issue_type` 초안도 두 번 맞췄지만, 두 출력 모두 `evidence_status`와
`resolution_preference` 등 다른 필드가 초안과 달랐다. BF04에서도 후보는
0/2에서 2/2 계약 통과로 바뀌었지만 `document_type` 값은 초안과 불일치했다.
반대로 BF01은 기본 2/2 계약 통과에서 후보 0/2로 악화됐다. BF03은 양쪽
모두 0/2 계약 통과였고, BF06은 후보에서 한 번 계약을 통과했으나
`unknown` 행동과 `inquiry_topic` 공란 초안에 모두 불일치했다. **계약 통과
증가는 전체 의미 일치 증가가 아니다.**

날짜 후보의 BF07은 날짜 초안 일치가 기본 1/2에서 후보 2/2로 늘었으나,
BF08은 기본 1/2에서 후보 0/2로 줄었다. BF09의 반복 요일은 양쪽 모두
0/2였다. BF10은 날짜 미정 대조군인데 기본은 1/2에서 `date=null`을
지켰고 후보는 0/2였다. 후보의 두 출력 모두 **비공란 `date`**가 기록되어
사전 검수한 공란 판단과 충돌한다. 날짜 묶음의 계약 통과는 8/8로 같아서
이 과잉 추출을 잡아내지 못한다.

[실행 보고서](../../evals/structured_nlu/results/exploratory-q5-boundary-followup-2026-11-06.json)는
사례 ID별 계약·초안 일치, 안전한 출력 형태, 실패 코드, 시도 횟수와
토큰·시간, 입력·코드·모델·이미지 해시를 남겼다. 발화·프롬프트·모델 답변
전문이나 날짜 값 원문은 저장하지 않았다. 따라서 BF07–BF09에서 허용 문자열과
다른 날짜의 **의미가 틀렸는지, 표현만 다른지**는 판정할 수 없다. BF10은
검수한 공란과 비공란의 차이만 확정할 수 있다. `issue_detail`과 `duration`처럼
자연어 표현이 여러 개인 필드의 불일치도 그대로 의미 오류로 세지 않는다.

업무 묶음의 기본·후보는 총 20·19회 생성 시도와 완료 토큰 1,430·1,432개,
날짜 묶음은 11·8회 생성 시도와 완료 토큰 840·613개였다. 후보의
입력 토큰과 프롬프트 캐시 양도 달랐으므로 기록된 시간 차이를 속도 개선으로
해석하지 않는다. 두 후보 모두 온전한 필드·행동 일치 관찰이 없고,
BF01 악화와 BF10 과잉 날짜가 있어 **서비스에 적용하지 않는다**.

이 사례는 기존 SB 실패를 보고 설계한 **AI 작성 개발용 대조**다. 사용자
검수는 탐색 목적이며 독립 사람 작성 test 정답 확정이 아니다. 4/12→7/12,
3/8→2/8 등을 전체 정확도 개선율로 표현하거나 앞선 12건 결과와 합쳐
일반화 수치로 쓰지 않는다. 포트폴리오에는 **행동 계약·필드 의미·재시도
비용을 분리해 후보의 부작용을 발견했다**는 검증 과정으로만 사용한다.
