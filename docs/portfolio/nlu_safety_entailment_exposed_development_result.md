# A/S 위험 함의 판단 후보: 노출 사례 개발 점검

## 범위와 실행 기록

RE01–RE16은 앞선 관계 후보 실험에서 이미 모델에 노출된 AI 작성·사용자 검수 사례다. 새 함의 후보의 **개발 점검**에만 재사용했다. 미노출 탐색 평가나 공식 정확도 수치가 아니다. 함의 후보는 `0cb7b50`에서, 실행기와 [요청 조건](../../evals/structured_nlu/data/ai_heldout/as-safety-entailment-exposed-development-protocol.v1.json)은 첫 호출 전에 고정했다. 동일한 Kanana Q5 파일·CPU 2개·메모리 4 GiB 로컬 서버에서 기존 단일 근거와 함의 후보를 교대 순서로 각각 16회 호출했다.

[원자료](../../evals/structured_nlu/data/ai_heldout/as-safety-entailment-exposed-development-result.v1.jsonl)의 SHA-256은 `ed6f7bf4ed3cb2245b88bf77e885ceb616ecb93a8588fca314832c82d4136cad`다. 호출 시작·종료를 arm마다 디스크에 기록했고 원문 발화와 응답 전문은 저장하지 않았다. [독립 기록 검증기](../../scripts/verify_as_safety_pair_journal_v2.py)가 프로토콜 해시, 16건 32호출의 교대 순서, 완료, 오류 단계와 지연을 확인했다. 로컬 컨테이너와 Docker Desktop은 실행 후 종료했다.

## 관찰 결과

| 기대 경로·사례 | 같은 실행의 기준선 일치 | 함의 후보 일치 | 후보 오류 |
| --- | ---: | ---: | ---: |
| 현재 제품 실제 위험 RE01–04 | 3/4 | 1/4 | 0 |
| 위험·출처 불확실 RE05–08 | 2/4 | 0/4 | 0 |
| 다른 출처 RE09–12 | 3/4 | 2/4 | 0 |
| 미발생 RE13–16 | 1/4 | 1/4 | 2 |
| **전체** | **9/16** | **4/16** | **2/16** |

후보가 다른 출처 위험의 오분기를 안정적으로 제거하지 못했고, 실제 위험 4건 중 3건을 놓쳤다. 두 오류는 모두 계약 검증 단계의 `ValueError`로 기록됐지만 원문 응답을 보존하지 않아 세부 원인을 단정하지 않는다. 호출별 관찰 지연의 중앙값은 기준선 약 1.46초, 후보 약 2.90초였다. 이 작은 로컬 표본의 지연은 배포 환경 성능을 뜻하지 않는다.

**함의 후보를 미채택한다.** 더 간결한 3필드 계약과 명시적 함의 질문이 더 나은 판단을 보장하지 않았다. 이미 검수한 새 V01–V16은 이 후보에 보내지 않고 미노출 상태로 보존한다. 다음 설계는 제품명·위험어 열거 규칙을 늘리기 전에, 위험 사건의 주어를 원문 근거로 식별하고 접수 대상과 연결하는 경계를 개발 사례에서 다시 검증해야 한다. 새 후보가 개발 점검의 안전 누락·다른 출처 오분기·오류를 함께 개선한다는 근거가 생긴 뒤에만 V 사례를 한 번 평가한다.
