# 16개 업무 범위 경계 탐색 비교: Q4·Q5

2026-11-04에 16개 구조화 NLU 업무마다 범위 안 발화 1개와 가까운 범위 밖 발화
1개, 총 **32개 AI 작성 사례**를 준비했다. 사용자는 문장과 행동 방향을 탐색용으로
채택했다. 정확한 필드 정규화 값은 AI 초안이며 사람 정답으로 확정되지 않았다.
각 모델에 같은 32개 사례를 두 번씩 보냈다. 첫 반복은 ID 순서, 두 번째는
역순이었다. **64회 관찰은 독립적인 64개 문장이 아니라 32개 문장의 반복**이다.

Q4와 Q5는 같은 Kanana 1.5 2.1B의 서로 다른 GGUF 양자화 파일이다. 동일한
`llama.cpp` 이미지에서 로컬 ARM CPU 2개·스레드 2개·단일 서버 슬롯·컨텍스트
4096·메모리 제한 6GiB로 순서대로 실행했다. 각 모델 파일 SHA-256, 서버 이미지
digest, 문장·라벨 초안·코드 해시와 코드 커밋은
[Q4 보고서](../../evals/structured_nlu/results/exploratory-q4-broad-ai-2026-11-04.json),
[Q5 보고서](../../evals/structured_nlu/results/exploratory-q5-broad-ai-2026-11-04.json)에
있다. [비교 보고서](../../evals/structured_nlu/results/exploratory-q4-q5-broad-ai-comparison-2026-11-04.json)는
입력·설정·집계를 재검사하고 사례별 차이를 기록한다. 발화와 모델이 생성한 필드
값 전문은 결과 파일에 저장하지 않았다.

| 관찰 항목 | Q4 | Q5 |
| --- | ---: | ---: |
| 전체 출력 계약 통과 | 48/64 | 48/64 |
| 범위 안 16문장의 계약 통과 | 28/32 | 30/32 |
| 범위 밖 16문장의 계약 통과 | 20/32 | 18/32 |
| 범위 밖 발화의 채택한 행동 방향과 일치하며 계약 통과 | **2/32** | **2/32** |
| 범위 밖 발화에서 계약은 통과했지만 행동 방향 불일치 | 18/32 | 16/32 |
| 재시도가 발생한 관찰 | 27/64 | 19/64 |
| 두 반복의 계약 통과 여부가 같았던 고유 문장 | 30/32 | 32/32 |
| 미검수 AI 라벨 초안의 모든 필드와 일치 | 8/64 | 8/64 |

범위 밖 행동 일치 2/32는 두 반복에서 같은 **1개 문장(B26)**이 맞은 결과다.
나머지 15개 범위 밖 문장을 두 모델이 대체로 현재 업무의 정보 제공으로 취급하거나
계약을 통과하지 못했다. 계약 실패 유형 중 `action_missing_required_field`는
두 모델 모두 14건이었다. 즉 출력 계약을 통과했더라도 업무 범위 판단이 맞았다는
뜻은 아니다. 범위 안에서는 Q4가 B17 두 번과 B21·B31 각 한 번, Q5가 B19 두 번
계약에 실패했다. 같은 사례의 두 모델 간 계약 통과 차이는 Q4만 4회,
Q5만 4회였다. 전체 계약 통과 수가 같아도 실패 사례는 달랐다.

실험 전 Q4의 4GiB 컨테이너는 25건에서 OOM으로 종료됐다. 그 불완전한 기록은
비교에서 제외하고, 두 모델 모두 단일 서버 슬롯·6GiB로 처음부터 재실행했다.
완주 보고서의 모델 요청 시간 합계는 Q4 691.397초, Q5 728.295초다. 모델을
순서대로 실행했고 캐시 사용량·재시도 횟수가 달라 이 합계를 속도 우열이나
운영 지연 시간으로 해석하지 않는다.

이 결과는 **사용자가 행동 방향을 채택한 AI 작성 개발 사례의 탐색 진단**이다.
필드 값은 미검수 초안이고 사례 수가 업무당 두 개뿐이므로 전체 정확도, 정확도
개선율, 통계적 우월성, 운영 일반화 성능으로 쓰지 않는다. 사례는 이번 실행으로
모델에 노출됐으므로 독립 test로 재사용하지 않는다. 포트폴리오에는 16개 업무를
고르게 표집하고 계약 성공과 범위 판단을 분리해 오판을 찾아낸 실험으로 설명할
수 있다. 다음 모델·프롬프트 수정은 별도의 새 사례에서 검증해야 한다.
