# A/S 위험 관계 판단: 다음 탐색 설계

## 출발점

RE01–RE16은 AI 작성·사용자 1인 검수의 표적 탐색이다. 기존 방식 경로 일치 9/16, 제품·위험 이중 근거 후보 8/16이었다. 후보는 RE09·11·12에서 제품·위험 문장 번호를 맞혔지만 다른 출처의 위험을 현재 제품의 위험으로 연결했다. RE02에서는 반대로 앞 문장의 제품을 가리키는 표현을 연결해 기존 방식의 누락을 회복했다. 번호 추출 성공만으로 소유·지시 관계의 성공을 주장할 수 없다.

## 비교할 설계

1. **기존 단일 근거 모델:** 현재 배포 후보의 기준선. 추가 호출이 없다.
2. **한 번의 구조화된 관계 판단:** 제품·위험 근거 번호에 더해 위험의 소유 대상, 실제 발생 여부, 관계 판단의 근거 종류를 제한된 값으로 반환한다. `current + observed`일 때만 즉시 보호, 불명확하면 확인, 다른 출처 또는 미발생이면 일반 수집으로 분기한다. 단일 호출의 비용은 낮지만 RE09·11·12처럼 모델이 관계를 과신할 수 있다.
3. **별도 관계 검증 호출:** 첫 추출 뒤 같은 모델에 두 문장의 함의 관계를 제한된 선택지로 다시 묻는다. 추가 호출이므로 지연·오류 표면이 커지고, 두 답이 독립적이라는 보장은 없다. 개발 사례에서 2번보다 안전 누락과 다른 출처 오분기를 함께 줄인다는 근거가 있을 때만 새 사례 평가 후보로 올린다.

한 번의 집중된 함의 질문을 3필드 JSON으로 묻는 [개발 후보](../../scripts/probe_as_safety_entailment_v2.py)도 만들었다. 그러나 이미 노출된 RE16건의 [쌍 비교](nlu_safety_entailment_exposed_development_result.md)에서 기준선 9/16 대비 4/16으로 낮고 오류 2건이 발생해 미채택했다. 새 V 사례에는 실행하지 않았다.

[KLUE](https://huggingface.co/datasets/klue/klue)에는 한국어 자연어 추론 과제가 있고, [NLI로 표시된 공개 체크포인트](https://huggingface.co/Huffon/klue-roberta-base-nli)도 있다. 다만 해당 체크포인트의 모델 카드에는 이 A/S 제품 지시 관계에 대한 검증 정보가 없고, 일반 NLI의 문장 함의가 위험 사건의 소유 대상을 정확히 판별한다는 근거도 없다. 따라서 모델 이름만 보고 도입하지 않고, 별도 모델을 실험한다면 데이터 사용 조건·라벨 대응·실패 비용·추가 메모리와 지연을 먼저 확인한다.

제품명이나 위험 어휘를 열거한 규칙은 우선 후보에서 제외한다. 이번 실패는 단어 탐지보다 같은 위험을 **어느 물건에 연결하는지**의 문제이며, 노출된 RE 표현에 맞춘 규칙은 새 문장으로 일반화됐다는 근거가 없다. 새 모델이나 NLI 전용 모델도 선택지지만, 모델 교체 효과와 계약 변경 효과를 섞지 않도록 같은 Q5 기준의 구조 비교를 먼저 수행한다.

## 평가 원칙

- 기존 RE01–RE16은 원인 분석·개발용으로만 사용한다. 새 성능 수치의 분모에 재사용하지 않는다.
- 새 발화는 같은 위험 표현에서 접수 제품의 지시 대상만 바꾸는 대조쌍, 실제 위험 뒤에 수리 질문이 붙는 사례, 출처 불확실·설명서·부정 사례를 포함한다. 문장과 전체 필드 정답을 모델 호출 전에 검수한다.
- 후보 코드·프롬프트·모델 SHA-256·실행 조건·평가 입력·검증기를 첫 호출 전에 커밋한다. 비교 순서를 번갈아 실행하고 요청 횟수·지연·오류 단계를 기록한다.
- 단일 경로 일치율 외에 실제 위험의 즉시 보호, 다른 출처 위험의 오분기, 불필요한 확인, 계약 오류를 각각 분모와 함께 보고한다. 실제 위험 누락을 감춘 채 전체 일치만 올리는 후보는 채택하지 않는다.
- 새 사례도 AI 작성·1인 검수라 **탐색 평가**다. 포트폴리오에 공식 전체 정확도 개선율로 쓰지 않는다.

## 실행기 계약

새 [쌍 비교 실행기](../../scripts/as_safety_pair_executor_v2.py)는 호출 시작을 디스크에 먼저 기록하고 각 arm의 결과를 바로 기록한다. 잘린 응답·응답 처리 오류, 계약 오류, 경로 결정 오류를 구분하며 재시도하지 않는다. 중단 후 기존 기록을 자동 재생하지 않는다. [독립 기록 검증기](../../scripts/verify_as_safety_pair_journal_v2.py)는 순서·완주·오류 단계·지연을 재검산한다. 실행기와 기록 검증기는 이후 [V 평가](nlu_safety_consensus_fresh_result.md)에 사용했다. 평가 당시 소스 해시를 보존하기 위해 실행기에서 놓칠 수 있는 `HTTPException` 계열과 첫 호출 전 검증기 해시 확인 누락은 결과의 한계로 기록하고, 후속 실행 버전에서 다룬다. 기록의 오류 상태는 현재 별도 사후 감사로 재검산한다.
