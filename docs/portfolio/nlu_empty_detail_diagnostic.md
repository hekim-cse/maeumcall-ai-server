# A/S 출력 계약 실패의 개발 진단

이 문서는 [RF01–RF12 동결 평가](nlu_review_followup_run_log.md)를 수정하거나 다시 채점하지 않는다. RF02·RF06은 이미 모델에 노출된 사례이므로 아래 재실행은 개발 진단이다.

## 확인한 원인

동결 평가에서 최종 코드 `ae91656`은 RF02·RF06의 두 시도 모두 `ValueError`로 계약 검증에 실패했다. 원문 응답을 보존하지 않았기 때문에 당시 결과 파일만으로 세부 원인을 알 수 없었다. 이후 같은 두 발화를 로컬 Kanana Q5에 다시 실행해 메모리 안에서 검증 오류를 확인했다. 두 사례 모두 모델이 `provide_details`를 선택하면서 이번 발화의 필드를 전부 공란으로 제출했고, `provide_details requires at least one current-turn field` 규칙을 위반했다. 진단 중 프롬프트와 응답 원문은 파일에 저장하지 않았다.

## 수정 근거와 확인 범위

현재 발화에서 새 필드가 하나도 없으면 `provide_details`는 정보 제공을 뜻할 수 없다. 검증 직전에 이 조합을 `unknown`으로 정규화하고, 필드는 계속 공란으로 둔다. 실제 필드가 하나라도 있는 `provide_details`와 필드를 담은 `unknown`의 기존 검증은 유지한다.

수정 뒤 동일한 로컬 Q5와 요청 설정으로 RF02·RF06을 재실행하자 두 사례 모두 첫 시도에 출력 계약을 통과했고 `unknown`으로 정규화됐다. 이는 노출된 두 사례의 계약 복구 확인이며, 새 사례의 정확도 또는 전체 16개 업무의 개선율은 아니다. 안전 보호 경로 역시 아직 미노출 실모델 사례로 평가되지 않았다.

## 다음 평가의 조건

안전 보호 경로와 이번 정규화의 일반화 여부는 새 발화를 모델에 보내기 전에 문장·행동·모든 필드의 정답을 검수하고, 데이터와 실행 조건을 동결한 뒤 평가한다. 안전 표현의 긍정·부정·가정과 비안전 A/S 문의를 함께 포함해 과잉 차단도 확인한다.
