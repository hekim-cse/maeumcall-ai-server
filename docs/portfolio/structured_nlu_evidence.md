# 대화 상태 검증 작업의 포트폴리오 근거

이 문서는 포트폴리오 문구를 작성할 때 수치와 적용 범위를 다시 확인하기 위한
근거 목록이다. 실행 기록은 [`evals/structured_nlu/results/README.md`](../../evals/structured_nlu/results/README.md)와
그곳에서 연결한 JSON 파일에 있다. 사용자 발화와 모델 출력 원문은 결과 파일에
저장하지 않았다.

## 현재 확인 가능한 내용

- 검증된 구조적 출력 계약과 상태 전이 테스트의 수치는 해당 실행 커밋과 로그를
  함께 확인한 경우에만 사용한다. 서로 다른 시점의 `862`, `901`, `906` 같은
  테스트 수를 하나의 성과로 합치지 않는다.
- 로컬 Q5 GGUF의 개발용 초안 16건 탐색에서 출력 계약은 15건 통과했다.
  초안의 모든 라벨과 정확히 일치한 사례는 3건이었다. 이는 미검수 초안에 대한
  탐색 결과이며 서비스 정확도는 아니다.
- 시간 표현 불일치 4건을 대상으로 한 별도 지시문 비교에서는 각 조건을
  사례별 2회 실행했다. 기본 조건은 계약 8/8 통과·시간 필드 8/8 불일치였고,
  수정 조건은 계약 6/8 통과·통과한 6건의 시간 필드 일치였다. 병원 예약은
  수정 조건에서 두 번 모두 필수 키 누락으로 실패했다. 수정안을 배포하지 않은
  이유까지 함께 설명해야 한다.

## 포트폴리오 작성 경계

계약 통과는 답변 내용의 정확도를 뜻하지 않는다. 초안 라벨은 사람의 합의를
마친 정답이 아니다. 4건의 사후 선택 사례를 전체 32개 흐름의 개선율로
외삽하지 않는다. 성능 수치를 쓰려면 동일 실행 경로와 하드웨어·캐시 조건으로
비교한 기록을 사용한다. 현 단계에서 설명할 수 있는 성과는 **모델 출력과
서버 상태 검증을 분리하고, 오류를 사례·필드 단위로 추적해 배포 여부를
판단했다는 점**이다.

## 전체 정확도 개선율을 얻기 위한 비교 기준

여기서 `전체`는 16개 상세 업무의 **구조화 정보 추출** 범위로 정의한다. 자유
대화까지 포함한 32개 흐름의 답변 품질을 이 숫자에 합치지 않는다. 16개 흐름의
각 사례에서 출력 계약, intent, user_action, change_field, 모든 업무 필드가
함께 맞아야 `정답 1건`으로 센다. 계약 실패는 오답이다. 이 지표는
`evals.structured_nlu.metrics.score_predictions`의 `case_exact_match_rate`다.

`evals.structured_nlu.comparison.compare_test_predictions`는 같은 `test` 사례에
두 방식의 예측이 각각 정확히 한 건씩 있는지 확인하고 정답 건수·분모·정답률·
퍼센트포인트 차이·상대 변화율을 계산한다. 이 계산 함수만 통과했다고 공식 결과가
되는 것은 아니다. 공식 결과에는 별도의 데이터 동결·coverage·검수 원장 관문이
필요하다.

비교 대상 두 방식에 **같은 검수 완료 test 사례**를 적용하고, 방식별 정답 건수와
전체 건수를 함께 공개한다. 개선 폭은 `수정 정답률 - 기존 정답률`의 퍼센트포인트로
표시한다. 상대 개선율을 쓴다면 `(수정 정답률 - 기존 정답률) / 기존 정답률 × 100`이며,
기존 정답률이 0이면 계산하지 않는다. 프롬프트 수정에 이미 사용한 development
36건과 시간 오류 4건을 최종 test에 재사용하지 않는다.

현재 corpus는 development·draft 36건뿐이다. 별도 validation/test 사례,
사람의 정답 확정과 검수 원장, 데이터·실행 조건 고정, 동일 조건의 두 방식 실행이
끝나기 전에는 실제 숫자나 `개선` 표현을 채우지 않는다.

2026-10-10에 AI 미검수 새 후보 36건도 로컬 Q5 모델로 **탐색 실행**했다.
[실험 기록](../../evals/structured_nlu/results/README.md)에서 계약 통과 31/36과
AI 초안 전체 라벨 일치 5/36을 확인할 수 있지만, 후자는 정확도가 아니다.
이 후보들은 모델 결과를 확인한 개발 자료가 되었으므로 최종 독립 test에서
제외한다. 따라서 아직 전체 정확도 개선율은 없다.
