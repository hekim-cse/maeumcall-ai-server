# 리뷰 후 수정 검증: 새 발화 검토 초안

**상태:** AI 작성 발화 12건의 문장과 행동 방향을 사용자가 2026-11-06에 채택했다. 모델 미노출. 전체 필드 정답은 [별도 검토표](nlu_review_followup_field_review.md)에서 채택했다. 입력과 실행 조건을 동결하기 전에는 모델에 실행하지 않는다.

## 평가 질문

PR #49의 리뷰 후 수정에서 (1) A/S의 범위 밖 요청과 안전 이상이 함께 나올 때 안전 가드를 유지하는지, (2) 면담 목적을 발화대로 보존하고 명시되지 않은 이름을 만들지 않는지 확인한다. 비교 대상은 이전 후보 `f52d991`과 병합된 최종 코드 `ae91656`이다. 기존 NS11과 리뷰 후 개발 진단 발화는 이미 모델에 노출됐으므로 재사용하지 않는다.

두 코드에 같은 Kanana Q5 파일·요청 설정·실행 이미지와 동일한 발화를 적용한다. 문장·정답·실행 순서·재시작 조건·채점 기준을 실행 전에 동결하고, 같은 문장의 전후 결과를 짝으로 비교한다. 이 묶음은 **두 업무의 리뷰 후 수정 검증**이며 16개 업무 전체 정확도를 추정하지 않는다.

## 정답 확정 전 점검할 항목

- RF01·RF03의 구매·보증 문의 자체는 현재 A/S 접수 범위 밖이다. 안전 이상 발화가 함께 있을 때 허용 행동, `symptom`, `safety_status`와 다른 필드의 공란을 먼저 확정한다.
- RF04는 실제 응급 안내나 접수 완료 여부를 평가하지 않는다. 구조화 출력과 상태 그래프의 안전 가드 경로를 각각 검증한다.
- RF07–RF12는 `appointment_purpose`, `date`, `time`, `user_name`의 값과 공란을 모두 확정한다. 이름이 나오지 않은 RF07·RF09·RF11에는 자리표시자를 정답으로 넣지 않는다.
- 출력 계약 통과, 행동 일치, 모든 필드 완전 일치, 안전 가드 진입을 구분해 보고한다. 예상과 다른 결과나 회귀도 그대로 보존한다.

RF08·RF12는 사용자가 직접 수정한 문장이다. 나머지 10건은 AI 초안을 사용자가 채택했다. 이 검수만으로 공식 서비스 정확도를 주장하지 않는다.
