# A/S 관계 보류 원인 재진단 계획

## 질문과 범위

[이전 진단](nlu_safety_grounded_entity_link_diagnostic_result.md)은 22건 중 최종 `unresolved`가 15건이었지만, 모델이 직접 보류했는지 서버의 원문 인용 검증에서 보류로 바뀌었는지 기록하지 않았다. 기존 저널로는 이 둘을 복원할 수 없다. 같은 RE/V 22건을 **이미 노출된 개발 사례의 원인 분해** 목적으로 다시 한 번 실행한다. 이는 새 데이터의 정확도 평가나 기존 7/22와의 독립 비교가 아니다.

## 고정 입력과 실행

- 기존에 사용자 검수한 RE/V 22건의 발화, 접수 대상·위험 주체 구절과 문장 번호를 입력 오라클로 사용한다. 관계 정답과 발생 상태는 요청에 보내지 않는다.
- 이전과 같은 Kanana Q5 파일, llama.cpp 이미지, 로컬 자원, 온도 0, 최대 출력 320토큰, 재시도 없음, 정해진 순서로 각 한 번 호출한다. 자세한 해시와 설정은 실행 전에 커밋할 `as-safety-grounded-entity-link-cause-protocol.v2.json`에 고정한다.
- GB01–GB24는 이 진단의 개발·프롬프트 조정·실행에 사용하지 않는다. 기존 v1 프로토콜, 후보, 저널, 검증기와 결과는 수정하지 않는다.
- 실행 전 프로토콜과 참조 파일이 커밋되었고 SHA-256이 일치하는지 확인한다. 부분 저널이 있으면 자동 재개하거나 덮어쓰지 않는다.

## 기록과 해석

각 종료 행에 모델이 직접 고른 `model_entity_link`, 인용 검증 결과 `anchor_status`, 서버가 실제로 채택한 `entity_link`를 분리한다. `model_abstained`는 모델의 직접 보류, `accepted`는 원문 앵커 통과, `rejected_*`는 모델의 확정 판단을 서버가 보류로 바꾼 경우다. 응답·계약 오류는 `not_evaluated`와 별도 오류 코드로 남긴다. 인용 본문, 발화 원문, 모델 응답 본문은 저널에 저장하지 않는다.

검증기는 행 수·순서·해시·상태 전이, 채택된 인용의 원문 위치와 해시, 관계·경로 집계를 재계산한다. 거부된 인용의 본문은 보관하지 않으므로 **세부 거부 원인은 실행기의 자기보고**이며 독립적으로 복원할 수 없다. 원문 구절이 실제 관계를 의미상 입증하는지도 이 검증으로 확인할 수 없다. 결과에서는 모델 직접 보류와 앵커 거부를 별도 분모와 ID로 공개하고, 관계별 성공·실패 및 대비쌍 실패를 숨기지 않는다.

이 진단 뒤 새 후보를 만들면 별도 프로토콜과 새로운 사용자 검수 사례에서 평가한다. 이 22건 재실행 수치는 포트폴리오의 공식 전체 정확도 개선율로 쓰지 않는다.
