# NLU 근거 위치 출력의 탐색 결과

2026-11-05에 [이전 필드 경계 비교](nlu_field_boundary_pair_findings.md)의
실패 원인을 더 확인하려고 모델이 각 비공란 필드의 발화 근거 위치를 함께
내는 방식을 시험했다. 서비스 분석기와 반환 형식은 바꾸지 않았다. 실험용
실행기가 `field_evidence`를 별도로 검사한 뒤 제거하고 기존 계약을 검증했다.
근거는 발화의 Python 문자열 코드 포인트 인덱스 `start`·`end`(끝 위치 제외)와 해당 부분의 정확한 인용문
`quote`로 표현했다. [검증기](../../evals/structured_nlu/source_evidence.py)는
비공란 필드와 근거의 1:1 대응, 위치 범위, 원문 인용 일치만 확인한다.
**근거 문구의 존재는 정규화 값의 의미가 맞다는 증명이 아니다.**

이미 모델에 노출된 AI 작성 개발 사례 F15·F17·F23·F29·D05를 사용했다.
첫 실험은 기존 출력과 시스템 근거 지시를 각 사례에서 두 번 교차 실행하고,
두 번째 반복에서 순서를 뒤집었다. [첫 보고서](../../evals/structured_nlu/results/exploratory-q5-source-evidence-2026-11-05.json)는
기존 출력의 업무 계약 통과 4/10, 근거 지시 출력의 **기존 업무 계약** 통과
6/10이지만, **근거 검증 통과는 0/16번 생성 시도·0/10건**이었다. 업무 계약
통과 숫자는 근거 출력이 성공했다는
뜻이 아니다. 모델은 필요한 `field_evidence` 객체를 내지 않았다.

기존 분석기의 출력 형식 설명 뒤에 근거 지시를 두는 두 번째 후보를 한 번
반복했다. [두 번째 보고서](../../evals/structured_nlu/results/exploratory-q5-source-evidence-tail-2026-11-05.json)는
기존 출력의 업무 계약 통과 2/5, 근거 지시 출력의 업무 계약 통과 0/5,
**근거 검증 통과 0/10번 생성 시도·0/5건**이었다. F23·F29는 출력 토큰 상한 180에 도달해 JSON이
끝나지 않았고, 나머지에도 JSON 또는 계약 오류가 있었다. 이 후보와 첫
후보는 반복 수가 달라 통계적 우열을 계산하지 않는다. 어느 쪽도 서비스에
적용하지 않았다.

같은 로컬 Q5 GGUF 파일 SHA-256
`644b04cde835d486df33c6d4d7552ba367fcb28802fe39b6b4bb9c60b9ab6f3d`와
서버 이미지 digest
`sha256:17155a3ce4cc906728ec99a2814bf0b4eaffaf3b4872bad8c3affed310cdbc35`를
사용했다. CPU 4개·메모리 6GiB·스레드 4개·단일 슬롯·컨텍스트 4096이었다.
실행기는 Docker의 읽기 전용 모델 마운트와 파일 해시, 이미지, 자원 설정을
읽어 보고서에 기록했다. 각 보고서에는 평가 코드와 입력 파일의 SHA-256,
사례 ID별 계약 결과, 불일치 필드 이름, 인용문을 제외한 근거 검사 코드,
토큰 수와 종료 사유를 넣었다. 발화·모델 답변·근거 인용문 전문은 저장하지
않았다. 첫 실행 당시 스크립트는
[원본 스냅샷](../../evals/structured_nlu/candidates/source-evidence-probe-v1.txt)에
보존했고, 두 번째 실험 당시 스크립트도
[별도 스냅샷](../../evals/structured_nlu/candidates/source-evidence-probe-v2.txt)에
보존했다. 현재 [실행기](../../scripts/probe_gguf_source_evidence.py)는 두 번째
후보를 재현하면서 기존 업무 계약과 근거 계약의 통과 여부를 분리해 기록한다.
실험 후 컨테이너는 종료했다.

이 실험은 근거 위치를 출력할 수 있는지 살피는 개발 진단이다. 기존 사례가
이미 모델에 노출됐고 사람 작성 독립 test가 없으므로 공식 정확도·개선율을
산출하지 않는다. 또한 근거 위치가 완벽해도 F29의 `평일`을 예약 날짜로
승격하거나 D05의 가능 여부 문의를 환불 희망으로 바꾸는 오류는 잡지 못한다.
F23의 `온라인`도 현재 탐색용 필드 초안에서는 특정 발급 플랫폼으로
확정하지 않는다. 이 세 반례는
[검증기 테스트](../../tests/test_source_evidence.py)에서 근거 검사만으로는
통과할 수 있음을 명시했다. 다음 후보는 모델에 위치 계산을 맡기는 방식의
출력 비용과 실패율을 고려하고, 의미 경계는 별도 검수 기준으로 다뤄야 한다.

**후속 판단 변경:** F23의 발급 경로와 D05의 희망 처리는 이후 사용자 판단으로
수정되었다. [수정 기록](nlu_meaning_label_amendment.md)을 참고해야 한다.
위 실험 결과와 당시 입력 지문은 그대로 보존한다.
