# A/S 다음 평가 실행 경계

## 목적과 현재 상태

PR #59의 V01–V16 평가에서 실행기와 검증기 해시는 실행 전에 고정됐고 결과가 저장됐다. 그 결과와 해시가 가리키는 v2 소스는 수정하지 않는다. 코드 리뷰에서 확인한 두 결함은 HTTP 프로토콜 예외가 호출 기록을 중단할 수 있다는 점과, 첫 호출 전 결과 검증기 해시 대조가 빠졌다는 점이다. 이번 변경은 [후속 이슈 #60](https://github.com/hekim-cse/maeumcall-ai-server/issues/60)의 **다음 평가용 실행 경계**다. 새 모델 실행이나 성능 개선 결과는 아니다.

## v3 계약

- [새 쌍 실행기](../../scripts/as_safety_pair_executor_v3.py)는 `http.client.HTTPException` 계열을 응답 오류로 기록한다. 실패한 응답의 내용은 저장하지 않고 남은 arm을 재시도 없이 실행한다. 중단 후 기존 저널을 자동 재생하지 않는 원칙은 유지한다.
- [사전 고정 검사](../../scripts/as_safety_preflight_v3.py)의 `run_frozen_pair`는 프로토콜의 실행기·[v3 결과 검증기](../../scripts/verify_as_safety_pair_journal_v3.py) SHA-256과 **해당 고정 파일 경로**를 대조한 다음에만 저널을 만들고 모델 호출을 시작한다. 호출자가 다른 파일 경로로 두 필수 검사를 덮어쓸 수 없다. 추가 입력·정책·모델·라우터 해시는 `additional_sources`에 넣어 같은 방식으로 검사할 수 있다. v3 결과 검증기는 호출 순서와 오류 단계·종료 사유의 조합을 함께 확인한다.
- 다음 평가의 상위 러너는 `run_frozen_pair`를 호출하기 전에 프로토콜이 커밋된 상태인지, 데이터가 미노출인지, 모델과 컨테이너 조건이 고정됐는지 확인해야 한다. 이번 변경에는 새 발화·프로토콜·실모델 평가를 포함하지 않는다.

강제 예외 테스트에서 잘못된 HTTP 상태 줄과 긴 헤더를 각각 응답 오류로 남기고 2건의 짝 비교 4호출을 완주했다. 검증기 내용이 고정 해시와 다를 때는 모델 호출 0회·저널 미생성을 확인했다. 이는 로컬 가짜 호출로 검증한 실행 경계이며 서비스 그래프의 성능 근거가 아니다.
