# NLU 의미 경계 탐색: 실패 형태 분석

2026-11-05의 [Q5 탐색 비교](nlu_semantic_boundary_pair_findings.md) 중
SB02·SB06·SB07·SB08·SB09를 다시 읽었다. 원자료는
[실행 보고서](../../evals/structured_nlu/results/exploratory-q5-semantic-boundary-2026-11-05.json)다.
각 사례는 기본·후보 조건에서 두 번씩 실행됐다. 아래 분모 4는 **반복 관찰**이며
독립 발화 4건을 뜻하지 않는다. 발화와 필드 초안은 모델 실행 전에 검토한
AI 작성 개발 자료이므로 공식 정확도 평가에 사용하지 않는다.

| 사례 | 확인된 결과 | 현재 확인 가능한 범위 |
| --- | --- | --- |
| SB02 환불 가능 조건 | 기본 2/2, 후보 1/2 계약 통과. 통과한 3회 모두 `issue_detail`만 비공란이고 `resolution_preference`는 초안과 불일치. 후보의 나머지 1회는 `provide_details`와 모든 필드 공란으로 계약 실패 | 초점 필드를 비운 사실은 확인된다. 질문을 왜 희망 처리로 분류하지 않았는지 모델 내부 이유는 알 수 없다. |
| SB06 온라인 발급 | 기본 1/2, 후보 0/2 계약 통과. 실패 3회는 `provide_details`와 모든 필드 공란. 통과 1회도 `inquiry_topic`만 비공란이며 `issuance_channel`은 초안과 불일치 | 세 실패의 마지막 오류 코드는 `action_missing_required_field`. 저장된 출력 형태에서 `issuance_channel` 비공란은 한 번도 없다. 왜 추출하지 않았는지는 알 수 없다. |
| SB09 환불 미요청·규정 문의 | 기본·후보 모두 0/2 계약 통과. 네 관찰 전부 `provide_details`와 모든 필드 공란으로 두 시도 뒤 실패 | 환불 희망을 공란으로 두는 방향 자체는 검증할 수 없다. 문제 유형·상세도 비어 행동 계약에 실패했다. |
| SB07 다음 주 화요일 예약 | 기본 2/2, 후보 2/2 계약 통과. 기본은 날짜 초안 2/2 일치, 후보는 0/2. 네 출력 모두 `date` 필드가 비공란 | 후보의 날짜 **문자열**이 초안과 다르다. 값 전문이 기록되지 않아 의미 오류인지 다른 정규화 표현인지 확정할 수 없다. |
| SB08 매주 화요일 예약 | 기본·후보 모두 2/2 계약 통과, 날짜 초안 일치 0/4. 네 출력 모두 `date` 필드가 비공란 | 반복 의미를 보존했는지, 표현만 다른지 확인할 원문 값이 없다. 현재 스터디룸 흐름의 실제 반복 예약 지원 여부도 이 실험으로 입증되지 않는다. |

`provide_details`는 이번 턴의 비공란 필드를 최소 하나 요구한다.
[서비스 계약](../../services/flow/service_workflow/structured_contract.py)이
이 규칙을 적용한다. 따라서 모든 필드가 비어 있는 상태의 계약 실패 **형태**는
확정할 수 있다. 그것이 발생한 모델 판단 원인은 저장된 정보만으로 확정할 수 없다.
날짜 쪽은 [비교 코드](../../scripts/probe_gguf_structured_nlu.py)가 검수 초안의
허용 문자열과 정확히 일치하는지 검사한다. 비공란 날짜의 의미 동등성까지
판정한 결과가 아니다.

## 다음 실험의 분리 기준

1. **행동·필드 일관성:** 새 개발 사례에서 `provide_details`에 필드를
   하나 이상 추출하는지와, 해당 필드가 실제 발화에서 지지되는지를 별도로 본다.
   빈 필드를 임의의 값으로 채우거나 `unknown`으로 자동 바꾸어 계약 통과만
   높이는 방법은 채택하지 않는다.
2. **날짜 정규화:** 새 사례에 사용할 의미상 동등한 허용 문자열을 **모델 실행 전에**
   검수하고 동결한다. 모델 출력값의 로컬 검토는 원인 진단에만 쓰고, 그것을 본 뒤
   허용 문자열을 넓혀 같은 실행의 점수를 다시 매기지 않는다. 그 전에는 SB07·SB08의
   정확 문자열 불일치를 의미 오류로 세지 않는다.
3. **비용과 부작용:** 후보별 계약 통과, 초점·전체 필드 일치, 재시도,
   생성 토큰을 함께 기록한다. 기존 후보는 계약 통과가 19/24로 같고
   전체 필드·행동 초안 일치가 양쪽 모두 0/24였으므로 서비스에 적용하지 않는다.

기존 12건은 이미 모델에 노출됐다. 새 모델 비교에 쓸 발화·필드 초안은
별도 입력으로 만들고 **실행 전에 사용자 검토와 해시 고정**을 거친다.
과거 보고서와 [D05·F23 후속 라벨 수정](nlu_meaning_label_amendment.md)은
사후에 고치지 않는다.
