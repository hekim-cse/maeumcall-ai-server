# A/S 출처 근거 표시 번호 대조 결과

[사전 방법](nlu_safety_eb_source_id_swap_v21_method.md)의 코드는 `1273efb`, [프로토콜](../../evals/structured_nlu/data/ai_heldout/as-safety-eb-source-id-swap-v21-protocol.json)은 `1b0ac06`에 고정했다. 같은 Qwen Q5에서 v20과 동일한 네 후보를 호출했다. 원문 문장과 순서, 사건·후보 구절, 질문, 출력 스키마와 생성 설정을 유지하고 표시 번호와 그 참조만 맞바꿨다.

| 항목 | v20 기존 표시 | v21 표시 교환 |
| --- | ---: | ---: |
| 사건 문장이 표시된 번호 | 2 | 1 |
| 사건 문장 선택 | 4/4 | 4/4 |
| 기존 숫자 2 선택 | 4/4 | 0/4 |
| 정답 출처 근거 선택 | 1/1 | 1/1 |
| 출처 미확정·배제 사례의 올바른 보류 | 0/3 | 0/3 |
| 출력 계약 통과 | 4/4 | 4/4 |

표시 번호가 바뀌자 응답 숫자는 전건 1로 바뀌었고, 모델이 가리킨 원문 문장은 그대로였다. 이 네 쌍에서 고정 숫자 2 선택 설명은 관찰과 맞지 않는다. 같은 문장이 사건으로 표시된 채 두 번째 행에도 그대로 있었으므로, 사건을 가리켰는지 두 번째 행을 선택했는지는 구분되지 않는다. 세 오선택이 유지돼 이 후보를 확대할 근거는 얻지 못했다.

요청 본문과 원시 응답을 별도로 독립 검수했다. 전송·출력 계약 오류와 재시도는 0건이다. [공개 저널](../../evals/structured_nlu/data/ai_heldout/as-safety-eb-source-id-swap-v21-journal.v1.jsonl)의 SHA-256은 `710853bad7c0871277d4ebbf11c0196bd965bc8bc87110437a339a9a96567fff`다. 원시 응답은 저장소 밖에 보관했으며 `python -m experiments.as_safety_atomic_edges_v21 replay`로 검증할 수 있다.
