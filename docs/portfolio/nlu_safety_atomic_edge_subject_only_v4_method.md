# A/S 위험 주체 단독 추출 개발 진단 설계

> 2026-11-20 실행 전 설계. 이미 노출된 AI 작성·사용자 검수 ES 사례를 사용한다. 공식 정확도·개선율이나 서비스 안전 성능의 근거가 아니다.

## 왜 이 비교를 하는가

[첫 E→B 진단](nlu_safety_atomic_edge_v1_development_result.md)의 19건 중 비공란 주체 일치는 0/18이었다. [보류 문구 비교](nlu_safety_atomic_edge_abstention_v2_development_result.md)의 소수 사례에서는 문구를 바꿔도 전건 보류했다. [출력 형식 비교](nlu_safety_atomic_edge_format_v3_development_result.md)에서는 스키마를 제거하자 출력 계약이 깨졌다. 기존 요청은 주체 B, 연결 종류, E와 B를 함께 담는 근거를 **한 번에** 요구하며 스키마와 검증기도 이 세 값을 묶는다. 주체만 추출할 수 있는지 별도로 확인해야 다음 병목을 구분할 수 있다.

## 비교 조건

- ES01·ES03·ES09·ES17·ES18의 첫 사건 5건을 사용한다. ES01/09는 유사 위험 표현의 다른 주체, ES03은 명시 주체, ES17은 정당한 출처 불명, ES18은 불확실한 발생과 명시 위치를 포함한다. 모두 기노출 개발 사례이며 이 다섯 건에 `implicit` 정답은 없다. TX·GB 봉인 사례는 사용하지 않는다.
- A는 기존 세 필드(`subject_span`, `event_subject_kind`, `event_subject_evidence_span`) 요청 그대로다. 요청 본문 해시가 이전 v3의 스키마 지정 기준선 5건과 각각 같아야 한다. 실행 뒤 원시 응답도 이전 v3 기준선과 바이트 단위로 비교한다.
- B는 같은 원문, 접수 제품 A, 검수된 위험 사건 E, 발생 상태를 받고 **주체 구절과 연결 종류 두 필드만** 요청한다. `response_format`은 두 조건 모두 JSON 스키마 제약을 사용하되 B의 스키마에는 두 필드만 둔다. B의 주체 구절은 원문의 `{clause_index, quote}` 객체 또는 `null`이다. 종류는 `subject`, `location`, `implicit`, `unresolved` 중 하나이며, 보류일 때만 구절이 공란이다. 검수된 B·연결 정답·B→A·기대 안전 경로는 모델 입력에 포함하지 않는다.
- 같은 Kanana Q5 모델 파일, 컨테이너 이미지, CPU·메모리·컨텍스트·스레드·포트, 생성 파라미터와 전송 제한을 쓴다. 조건 순서를 실행 전에 고정해 각 사례 A/B를 한 번씩, 총 10회 호출한다. 재시도와 부분 실행 재개는 하지 않는다. 호출 오류는 해당 행에 기록하고 다음 고정 호출로 진행한다.

## 고정과 재검증

코드·이 문서·검수 입력을 먼저 커밋한다. 깨끗한 작업 트리에서 모델 SHA-256을 확인하고 소스·입력·정확한 요청 본문 10개의 SHA-256과 호출 순서를 별도 프로토콜에 고정해 **모델 호출 전에 커밋**한다. 공개 저널에는 원문·프롬프트·응답을 넣지 않고 해시·오류·지연 같은 메타데이터만 기록한다. 원시 응답은 저장소 밖 권한 제한 파일에 둔다. 독립 검증기는 고정 요청을 자체 재구성하고 기존 v3 프로토콜·저널 및 비공개 응답의 해시와 새 기준선 재현을 확인한다. 전체 저널 파일 SHA-256과 검증기 SHA-256은 결과 문서에 따로 기록해 재검증할 때 대조한다.

## 사전 지정 지표와 판단 경계

조건별 전송·종료 오류, JSON/필드 출력 계약, `unresolved`, B 원문 구절 정확 일치(비공란 정답 4건), 종류 일치(전체 5건), ES17의 **유효한** 정당 보류·근거 없는 확정·계약 오류를 나눠 보고한다. 정답 일치에는 계약 유효 출력 수를 함께 적고, ES17의 무효 출력은 안전 판단 **평가 불가**로 표시한다. A에는 연결 근거 일치(전체 5건, 비공란 4건)를 추가한다. B는 근거를 생성하지 않으므로 근거 점수를 부여하지 않는다. 요청 지연은 전송 호출 시작부터 응답 수신 또는 오류까지 측정하며 원시 파일 저장 시간은 제외한다. 현재 전송 계층은 토큰 사용량을 보존하지 않으므로 토큰 수를 추정하거나 성능 지표로 사용하지 않는다. 계약을 통과하지 못한 출력은 주체 정답으로 채점하지 않는다.

B가 비공란 4건 중 하나라도 유효하게 맞히고 ES17에서 계약 유효한 `unresolved`·주체 공란을 반환하면, 주체 단독 단계가 다음 개발 진단에 쓸 **탐색 신호**가 된다. 실제 후보 관문은 계약 오류 0/5, B 4/4, 종류 5/5, ES17 정당 보류 1/1로 더 엄격하게 둔다. 관문을 통과하기 전에는 서비스에 연결하지 않는다. B가 보류하거나 계약을 어기면 근거 단계를 덧붙이지 않고 실패 형태를 분석한다. 주체 단계가 의미 있는 신호를 보이면, 근거만 추출하는 두 번째 단계는 모델이 생성한 B에 조건화되는 별도 프로토콜로 사전 고정해 평가한다.

이 비교에서는 프롬프트 요구와 스키마 필드 수가 함께 바뀐다. 따라서 차이가 나도 **동시 근거 요구 하나가 기존 전건 보류의 원인이라는 단일 변수 인과 결론은 내리지 않는다.** 범위는 복합 과제 대 주체 단독 과제의 개발 진단이다. 5건 결과를 기존 19건이나 새 사례로 일반화하지 않는다. B→A 관계와 최종 안전 경로는 평가하지 않고, 공식 성능 주장은 코드·조건 고정 후 새 미노출 검수 사례로 별도 확인해야 한다.
