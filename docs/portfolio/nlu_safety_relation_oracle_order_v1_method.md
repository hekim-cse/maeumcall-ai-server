# A/S 위험 출처 관계 전용 개발 진단 설계 초안

> 2026-11-16. **모델 실행 전 방법 초안**이다. 이미 노출된 AI 작성·사용자 검수 ES 자료만 개발 진단에 사용한다. TX·GB 봉인 사례는 후보 설계와 선택에 사용하지 않는다. 이 초안 자체는 실행 결과가 아니다.

## 왜 관계 단계부터 분리하는가

직전 근거 그래프 호출은 19건 중 15건이 인용·연결 계약에서 실패했고, 19개 원시 응답 모두 `location → part_of`를 냈다. 절 번호만 유일한 원문 일치로 고친 사후 오프라인 대조에서도 새 관계 정답은 생기지 않았다. 따라서 주체 구절 선택기를 더 복잡하게 만들기 전에, **올바른 주체 B를 제공해도 모델이 B와 접수 제품 A의 관계를 구분하는지**를 확인해야 한다. 기존 R 조건은 주체를 주지 않고 전부 `other`로 답했으며, O 조건은 주체를 주었지만 인용 계약과 관계를 함께 다뤘다. 이번 조건은 검수된 A·E·B를 주고 관계 세 값만 출력해 그 부담을 분리한다. 서로 다른 조건의 점수를 정확도 개선율로 비교하지 않는다.

## 입력과 대조 조건

- 기존 ES 20사례·22사건 중 발생 상태가 `observed` 또는 `uncertain`이고 검수 B가 비공란인 **18사건/17사례**만 관계 판단 대상이다. 정답은 관찰된 현재 제품 8건, 발생 불확실한 현재 제품 1건, 관찰된 다른 출처 9건이다. 관계 기준으로는 `current` 9건, `other` 9건이며 무조건 한쪽을 출력하는 상수 기준선은 각각 9/18이다. ES17의 B 공란·관계 `unknown`은 이 주체 오라클 조건에서 제외한다. 이 제외는 모델이 공란을 스스로 발견했다는 뜻이 아니며, 별도 서비스 안전성 증거로 쓰지 않는다. 미발생 3사건은 호출하지 않는다.
- 같은 원문과 검수 A·E·B, 같은 Q5 모델·요청 설정을 두 조건에 모두 제공한다. 두 조건의 차이는 `current`, `other`, `unknown`의 **자연어 정의 제시 순서**뿐이다. 출력 JSON enum 순서는 동일하게 고정한다. 각 사건을 두 조건에 한 번씩 실행하고, 사건별 호출 순서를 정답 범주에 균형 있게 배정해 앞뒤 호출의 시간 효과를 섞는다. 정확한 사건별 순서는 프로토콜에 고정한다. 각 조건의 출력은 세 값 중 하나인 단일 필드 JSON이며, 근거 구절이나 안전 경로를 모델에 출력시키지 않는다.
- 검수 B 제공은 **주체 오라클**이다. 실제 서비스에서 B를 정확하게 뽑는 성능이나 E를 찾는 성능은 이 실험으로 측정할 수 없다. 모델 출력과 관계 정답을 비교할 때만 정답 관계를 읽고, 요청에는 넣지 않는다.

## 실행 전에 고정할 것

사례·사건 순서, 두 조건의 정확한 메시지/JSON 계약, 요청 온도·시드·토큰 한도·서버 이미지, Q5 파일 해시, 데이터 및 코드 해시, 재시도 정책, 원시 응답 비공개 위치, 집계식, 독립 검증기를 모델 호출 전에 커밋과 프로토콜로 고정한다. 관계를 안전 경로로 바꾸는 규칙과 복수 사건의 안전 우선순위도 프로토콜에 명시한다. 중단된 저널은 감사 전 재사용하거나 덮어쓰지 않는다. 각 조건의 호출 수, 계약 오류, 전체 관계 정답, 관찰 현재 8건·불확실 현재 1건·다른 출처 9건의 정답, 두 대비쌍 ES01/09·ES02/11, 모델 관여 17사례의 안전 경로, ES06 복수 사건의 우선순위, 직접 위험 누락·다른 출처 오경고, 두 조건의 사건별 일치·불일치, 출력 분포, 지연 시간을 분리해 보고한다. 결과에는 두 조건의 짝지은 정오표를 넣어 한쪽의 교정과 퇴행을 동시에 보여준다.

## 판정 경계

관계 전용 오라클 조건조차 **두 순서 모두** 관찰 현재 8/8·불확실 현재 1/1·다른 출처 9/9, 모델 관여 경로 17/17, 대비쌍 2/2, 계약 오류 0건에 못 미치거나 두 순서의 사건별 예측이 18/18 일치하지 않으면, 주체 추출기 개선만으로 안전 분기를 완성할 수 있다고 주장하지 않는다. ES06에서는 다른 출처 사건의 판정이 틀려도 현재 제품 사건 때문에 사례 경로가 맞을 수 있으므로 사건별 정답을 우선한다. 한 순서에서만 잘되면 순서 취약성으로 보고하며, 한 번의 불일치를 안정적인 모델 속성으로 일반화하지 않는다. 이 18건에는 정답 `unknown`이 없으므로 확인 경로의 `unknown` 인식도 평가하지 못한다. 어느 조건이 이 개발 문턱을 통과하더라도 ES는 노출된 자료이므로 서비스 적용이나 일반화된 정확도 개선율의 근거가 아니다. 다음 후보 선택 뒤 모델이 보지 않은 새 발화와 전체 정답을 사용자 검수·동결하고 별도로 평가한다.
