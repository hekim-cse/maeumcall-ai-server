# A/S 위험 주체 명사 끝 후보·순서 개발 대조 방법

> 2026-11-22. 이 문서는 모델 호출 전의 사전 방법이다. PC01·NC01은 AI 작성·사용자 검수 후 이미 여러 개발 실험에 노출됐다. 공식 정확도·개선율, B→A 또는 서비스 안전 경로를 평가하지 않는다.

## 이 실험을 하는 이유

[v7 결과](nlu_safety_eb_candidate_order_v7_development_result.md)에서 정확한 PC01 주체 `선풍기 모터`는 전체 후보에 있었지만 모델은 조사 또는 사건까지 붙은 긴 구절을 선택했다. NC01은 전체 후보의 원순·역순에서 출력 계약 결과가 달랐다. [v8 오프라인 감사](nlu_safety_eb_boundary_v8_offline_result.md)의 명사 끝 조건 N은 기노출 양성 23건의 정확 구절을 모두 후보에 남기며 전체 후보 수를 줄였지만, PC01의 긴 오답 후보와 NC01의 출처 아닌 명사 후보도 남는다. 따라서 **후보 가용성**만으로는 정답 선택·정당 보류를 알 수 없다.

## 고정할 비교

PC01·NC01의 원문, 검수된 제품 A·사건 E·발생 상태, v7의 두 필드 JSON 스키마·지시문·생성 정책과 같은 Kanana Q5 파일·컨테이너를 사용한다. 세 조건의 차이는 모델에 표시하는 후보 행 집합과 그 순서다.

| 조건 | 후보 행 | PC01 | NC01 |
| --- | --- | ---: | ---: |
| F | v7 원순 전체 후보. v7 B의 요청 바이트와 같아야 함 | 22개 | 35개 |
| N | v8 `nominal_end` 후보를 기존 ID·원순으로 표시 | 7개 | 4개 |
| R | N과 같은 후보·ID의 표시 행만 역순 | 7개 | 4개 |

PC01 정답 후보 P014는 F 원순 14번째, N 원순 5번째, R 역순 3번째다. 이것은 사후 채점을 위한 위치 기록이며 프롬프트에 정답 표시를 넣지 않는다. NC01은 물리적 출처 B가 공란이므로 후보가 있더라도 `subject_span=null`, `event_subject_kind=unresolved`를 요구한다. 정답 B·종류는 요청 생성·후보 필터에 전달하지 않고 채점에만 사용한다. 정답값만 바꿔도 세 조건의 요청 바이트가 동일한지 테스트한다.

호출 순서는 **PC01 F→N→R, NC01 R→N→F**로 고정한다. 같은 조건을 각 사례에서 한 번씩만 호출하고 재시도·부분 재개는 하지 않는다. F↔N 원순은 같은 실행 환경의 짝 비교이고, R은 N의 순서 민감도 확인이다. 역사적 v7 응답은 별도 실행의 참고 기록으로만 둔다.

## 실행·검증 경계

먼저 방법·실행기·독립 검증기·입력·테스트를 커밋한다. 깨끗한 작업 트리에서 모델 SHA-256, 컨테이너 이미지 digest·실행 인자·127.0.0.1 전용 경로, v7 F 요청 바이트 일치, 소스·입력 해시를 확인한다. 실제 서버 토크나이저로 여섯 요청의 입력 토큰을 계산하고 최대 생성 토큰을 더해 4,096 문맥 예산 내인지 확인한다. F 두 요청의 토큰 수는 같은 요청을 사용한 v7 프로토콜 기록과도 일치해야 한다. 여섯 요청 해시·후보 행 해시·순서·토큰 수·재시도 금지·출력 경로를 별도 프로토콜로 **모델 호출 전에 커밋**한다. 토큰 계산이나 해시 확인이 불가능하면 호출하지 않는다.

원시 응답은 저장소 밖 권한 제한 디렉터리에, 공개 저널에는 원문·프롬프트·응답을 제외한 해시와 실행 메타데이터만 기록한다. 독립 검증기는 실행기를 신뢰하지 않고 고정 입력에서 요청을 다시 만들고, 저널·원시 응답의 해시·순서·권한, 출력 계약과 정답 일치를 분리해 확인한다. 전송·종료 오류와 출력 계약 오류는 의미 오답과 따로 센다. 기존 v1–v8 방법·프로토콜·저널·원시 응답은 수정하지 않는다.

## 사전 관문과 해석 한계

N과 R의 PC01이 **모두** 계약 유효·정확 B `선풍기 모터`·정확 종류 `location`이고, N과 R의 NC01이 **모두** 계약 유효·공란·`unresolved`여야 한다. **N/R 네 호출**의 전송·길이·출력 계약 오류도 0건이어야 다음 개발 실험 진입 신호로 본다. F 두 호출의 오류는 별도 대조 결과로 보고한다. F에 전송·길이·출력 계약 오류가 있으면 해당 사례의 F↔N **의미 점수 짝 비교**는 평가 불가로 표시한다. 어느 N/R 조건이라도 실패하면 ES 전체로 확대하거나 서비스 경로에 연결하지 않고 실패를 분해한다. F의 결과로 관문을 소급 변경하지 않는다.

후보 개수, 정답 표시 위치와 입력 토큰 수가 함께 바뀌므로 F/N 차이를 형태소 필터 하나의 인과 효과로 단정하지 않는다. 각 조건은 기노출 사례에서 단 1회이므로 순서 효과의 크기·재현성도 추정하지 않는다. 이 관문을 통과해도 공식 정확도 개선율은 아니다. 이후 새 미노출 사례와 전체 정답을 별도 검수·사전 고정해야 한다. TX·GB는 입력에서 제외한다. GB 파일의 앞부분은 v8 작업 중 우발적으로 열람돼 이 세션의 미노출 평가 자료로 사용할 수 없다.
