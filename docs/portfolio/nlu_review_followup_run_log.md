# 리뷰 후 수정의 신규 사례 비교 실행 기록

## 실행 전 동결

이 평가는 PR #49의 리뷰 후 수정만 좁게 확인한다. AI 작성 발화 RF01–RF12는 사용자 한 명이 문장·행동·모든 필드 값과 공란을 모델 실행 전에 검수했다. 독립적인 두 번째 검수자는 없다. 기존 NS11과 리뷰 후 개발 진단 발화는 재사용하지 않는다.

- 이전 후보: `f52d991`.
- 최종 코드: `ae91656`.
- 데이터: `nlu-review-followup-reviewed.v1.json`, 검수 원장: `nlu-review-followup-ledger.v1.json`.
- 모델: 같은 Kanana Q5 GGUF 파일, SHA-256 `644b04cde835d486df33c6d4d7552ba367fcb28802fe39b6b4bb9c60b9ab6f3d`.
- 실행 조건: [동결 프로토콜](../../evals/structured_nlu/data/ai_heldout/nlu-review-followup-code-pair-protocol.v1.json). 12건을 같은 서버에서 전후 순서를 번갈아 실행하며, 6쌍 뒤 서버를 재시작한다. 계약 실패 시 한 번만 재시도한다.
- 주장 범위: A/S와 교수님 면담 예약의 `greeting` 상태, 두 코드의 짝비교. 전체 16개 업무나 실제 사용자 발화 분포의 정확도로 일반화하지 않는다.

## 실행 결과

입력·검수 원장·프로토콜을 커밋 `bc890cf`로 고정한 뒤 로컬 Q5에 12쌍·24회 요청을 완료했다. 서버는 계획대로 6쌍 뒤 한 번 재시작했다. 전송 오류나 OOM은 없었다. 결과는 [정규화 예측 파일](../../evals/structured_nlu/results/nlu-review-followup-code-pair-v1.json)에 보존했고, 원문 프롬프트와 모델 응답 전문은 저장하지 않았다. 별도 검증기로 입력·원장·프로토콜 해시, 요청 24회, 재시작 위치, 점수를 재계산했다.

리뷰 뒤 실행기의 범위 검사를 강화했다. 위 결과를 재현할 때는 동결 프로토콜의 실행기 해시와 일치하는 `bc890cf`의 실행기를 사용한다. 이후 실행기 코드로 동결 프로토콜을 조용히 다시 실행하지 않는다.

| 지표 | 이전 후보 `f52d991` | 최종 코드 `ae91656` |
| --- | ---: | ---: |
| 전체 완전 일치 | 1/12 | 2/12 |
| 행동 일치 | 10/12 | 10/12 |
| 최종 출력 계약 통과 | 12/12 | 10/12 |
| 안전 이상 3건의 `safety_status=safety_issue` | 0/3 | 0/3 |

완전 일치의 짝변화는 개선 1건(RF08)·악화 0건이며 정확한 양측 McNemar `p=1.0`이다. 작은 1인 검수 표본에서 통계적으로 확인된 개선이라고 할 수 없다. RF01·RF03·RF04는 두 코드 모두 안전 증상을 일부 추출했지만 `safety_status`를 공란으로 두어 안전 가드에 진입할 수 없었다. 최종 코드는 RF02·RF06에서 각각 두 번의 출력 계약 검증에 실패했다. 결과 파일은 오류 유형을 `ValueError`로 기록하지만 원문 응답을 보관하지 않으므로 실패의 세부 형태는 단정하지 않는다.

면담 사례에서는 RF08의 전체 필드가 새 코드에서 맞았으나, RF09는 여전히 `user_name=학생 이름`을 만들어냈다. RF11은 말하지 않은 목적을 `상담`으로 채웠다. 리뷰 후 안내가 일부 발화에는 도움이 됐지만 이름·목적 환각을 제거했다고 주장할 수 없다.

**판단:** PR #49의 리뷰 후 수정은 이 신규 사례에서 안전 처리를 보장하지 못했고 계약 통과도 악화됐다. 전체 정확도 개선 성과로 쓰지 않는다. 다음 수정은 안전 가드를 모델 출력에만 의존하지 않는 경계를 검토하고, 새 미노출 사례를 다시 검수·동결한 뒤 평가해야 한다. 이번 RF 사례는 이후 개발·회귀 검사로만 재사용한다.

평가가 끝난 뒤 컨테이너와 Docker Desktop을 종료했고, 임시 12GB 메모리 설정을 원래 8GB로 복구했다. AWS는 사용하지 않았다.

## 결과 확인 후 안전 경로 수정

위 12건의 모델 결과를 확인한 뒤, A/S 그래프에 명시적 위험 징후를 별도로 감지하는 보호 경로를 추가했다. 이 경로는 확인된 발열·연기·타는 냄새·배터리 팽창 표현에서 모델 추출이 실패하거나 안전 필드를 비워도 `safety_action_required`로 이동한다. 부정·가정 표현은 대표 사례로 테스트했지만 모든 한국어 표현을 포괄하지는 못한다. 모델의 일반 NLU 점수를 높인 것으로 간주하지 않는다.

**이 수정은 RF01–RF12를 본 뒤 이뤄졌으므로 위 전후 수치의 대상이 아니다.** RF 사례는 앞으로 개발·회귀 검사에만 사용할 수 있다. 수정된 안전 경로의 미노출 평가와 계약 실패 원인 분석은 별도로 진행해야 한다.
