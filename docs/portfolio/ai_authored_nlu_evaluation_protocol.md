# AI 작성·사람 검수 구조화 NLU 평가 규칙 초안

## 지표 이름과 적용 범위

이 경로의 결과 이름은 **AI 작성·사람 검수 고정 평가셋의 16개 상세 업무
구조화 추출 전체 일치율**이다. 한 사례에서 라이브 출력 계약, `intent`,
`user_action`, `change_field`, 모든 업무 필드가 함께 맞아야 정답 1건으로 센다.
계약 실패와 재시도 후 실패는 오답이다. 분모는 **서로 다른 발화 사례 수**이며
같은 사례의 반복 실행을 분모에 더하지 않는다. 우선 비교 대상으로 요청받은
Kanana Q4를 기준, Q5를 비교 대상으로 사전 지정한다. Q4 `a/N`, Q5 `b/N`,
차이 `(b-a)/N × 100` 퍼센트포인트를 함께 보고한다. 차이가 음수거나 0이면
`개선`이라고 부르지 않는다.

이름의 `전체`는 각 사례의 모든 구조화 출력 항목이 함께 맞는다는 뜻이다.
마음콜 32개 전체 흐름, 실제 사용자 발화 분포, 자연스러운 답변 품질 또는
서비스 성공률을 뜻하지 않는다. 사람 작성 공식 벤치마크의 결과와 합산하지 않는다.

## 출처와 독립성

- 발화 작성 출처는 `ai_authored`로 기록한다. 사용자가 발화나 라벨을 검수해도
  `human_authored`로 바꾸지 않는다. 기존 human-authored compiler와 V4 freeze
  경로에 AI 발화를 넣지 않는다.
- 이전 Q4·Q5 탐색에 사용한 D/F/SB/BF 및 다른 AI 후보, 개발 사례, 그 가까운
  바꿔쓰기는 평가에서 제외한다. 새 발화도 중복 검사를 거친다.
- 평가 대상 모델의 출력을 보기 전에 발화, 현재 상태, 이전 필드, 대안 시간,
  모든 정답 필드와 허용 문자열, 행동, 태그를 사람이 검수·확정한다.
- 최종 입력, 검수 원장, 평가 규칙, 비교 대상과 생성 설정을 하나의 Git 커밋에
  고정한다. 첫 모델 호출 전에 그 커밋과 파일 SHA-256을 노출 기록에 남긴다.
  이후 정답이나 규칙을 바꾸면 기존 결과는 별도 버전으로 보존하고 새 평가로
  다시 실행한다. 시각·해시·Git 기록은 변경 순서를 감사하는 근거이지 검수자의
  신원을 암호학적으로 증명하지 않는다.

## 검수와 실행 관문

1. [새 발화 검토 초안](ai_authored_nlu_heldout_review.md)의 문장과 업무 방향을
   사람이 확인한다. 현재 파일은 모델 실행 허가가 아니다.
2. 각 발화의 상태·행동·`intent`·`change_field`·모든 필드의 공란과 허용값을
   별도 표에서 검수한다. 사람의 최종 판단과 수정 근거를 정확한 입력 지문에
   연결한 원장에 기록한다. 별도 `ai_heldout.py` 검수 관문은 AI 출처, 원본
   SHA-256, 사례 ID, `test`·`adjudicated` 상태와 16개 업무 포함을 확인한다.
   이 검사만으로 실제 사람 검수나 모델 미노출이 증명되지는 않는다.
3. 16개 업무의 사례 수와 상태·행동·필드·난이도 분포를 실제로 계산한다.
   비어 있는 영역을 공개한다. 초기 32건은 시작 목표일 뿐 기존 V3의
   1,562개 coverage 의무를 자동으로 충족하지 않는다. coverage가 부족하면
   `16개 업무 전체를 대표한다`는 주장을 하지 않는다.
4. 모든 사례와 정답이 확정된 뒤 개발용과 평가용을 원본 대화 그룹 단위로
   나눈다. 평가용 발화는 프롬프트·후보 선택·오류 수정에 사용하지 않는다.
5. 고정된 평가 사례에 두 모델을 같은 분석 코드, 서버 이미지, 요청 설정,
   재시도 정책으로 실행한다. 각 모델 파일의 해시와 양자화·서버·하드웨어·캐시
   조건을 별도로 기록한다. 실행 순서와 준비 요청도 결과 전에 정하고,
   지연시간 비교는 캐시와 순서의 영향을 분리할 수 있을 때만 한다.
6. 사례별 모든 시도와 정규화 예측 또는 오류, 계약 통과, 토큰 수, 지연시간을
   누락 없이 보존한다. 원문 발화와 모델 응답 전문은 공개 결과에 넣지 않는다.
   검수용 제한 접근 예측 원본은 재채점이 가능하도록 별도로 보존한다.
7. 두 조건의 사례 ID 집합·정답 버전·요청 설정·반복 수가 다르면 비교를
   거부한다. 반복 측정의 변동과 실패 사례도 결과에 함께 공개한다.

결과에는 업무별 사례 수와 계약 실패, 행동 오류, 필드 누락·추가를 분리해
표시한다. 같은 사례에서 Q4만 정답인 수와 Q5만 정답인 수도 함께 기록해
차이가 어느 사례에서 생겼는지 검증한다. 32건처럼 작은 평가에서는 차이를
실사용자 분포의 우위나 통계적으로 확정된 모델 우위로 일반화하지 않는다.

## 현재 상태와 다음 관문

2026-11-06 현재 [새 발화 검토 초안](ai_authored_nlu_heldout_review.md)은 AI가
작성한 **미검수 후보**다. 아직 정답 원장, 평가용 분할, 사전등록 커밋,
모델 노출 기록 또는 점수가 없다. 검수 관문의 데이터 형식과 검사는 준비됐지만
커밋된 사전등록을 확인하는 실행기와 쌍 비교 실행기는 아직 없다. 사람 검수와
실행기 검증 전에는 Q4·Q5에 실행하지 않는다.

기존 [사람 작성 평가 규칙](../../evals/structured_nlu/README.md)과
[포트폴리오 근거](structured_nlu_evidence.md)는 별도로 유지한다.
