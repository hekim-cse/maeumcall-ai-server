# 내부 test 80건의 기존 사례 노출 점검

> **범위가 있는 노출 점검.** 새 test 64건(IT)과 별도 안전 16건(SS)을 개발 validation 뒤에 작성했다. 사용자는 문장·방향·전체 필드와 아래 교체안을 채택했다. 첫 모델 호출 전에 기존 데이터의 정확 일치와 가까운 상황을 점검했고, 동결된 최종 JSON은 실행 후에도 재검사했다. 저장소 밖의 과거 호출이나 모델 학습 데이터까지 검사한 증명서는 아니다.

## 검사 범위와 방법

1. `evals/structured_nlu/data`의 JSON/JSONL에 있는 이전 `user_message`와 validation 32건을 `NFC+strip`한 원문 해시로 비교한다. 평가 도구의 `known-nlu-corpus-inventory-v1.json`은 이 저장소 데이터 범위의 정확 일치만 검증한다.
2. `docs/portfolio`의 기존 문장 초안과 이전 평가 사례도 사람이 읽는 형태로 대조한다. 문장 자체가 달라도 **같은 사건·업무·판단 경계**를 되풀이하면 독립 사례로 보기 어렵기 때문이다. 이 단계의 최초 후보 탐색과 비교표는 AI가 수행했고, 사용자는 변경 후 문장과 라벨 방향을 검수했다. 저장소 전체의 모든 의미상 바꿔쓰기에 대한 사람 전수 보증으로 표현하지 않는다.
3. 마지막으로 새 묶음 내부의 유사성도 점검한다. IT27의 첫 교체 제안은 IT25와 같은 현재 위치 질문이어서 폐기했다.
4. 로컬에 보존한 2026-11-17 validation·PF 실행 기록 120개 파일을 읽어, 최종 IT+SS 80개 발화의 NFC 정규화 원문 UTF-8 바이트가 기록 안에 통째로 나타나는지 검사했다. **일치 ID는 0개**였다. 원문 기록에 사용자 발화가 저장되지 않았을 수도 있으므로 이 검색만으로 과거 모델 미노출을 증명하지 않는다. 원문 내용은 출력하거나 이 문서에 복사하지 않았다.

교체안 6건의 `NFC+strip` 원문은 대조한 기존 문서·데이터 파일에서 일치하지 않았고, AI의 표적 의미 대조에서도 거의 같은 사건·판단을 발견하지 못했다. IT27의 최종 문장도 IT25와 다른 필드와 후속 행동을 평가한다. 이 결과는 검토한 파일과 비교 방법에만 유효하다.

## 검사 한계

- 최종 JSON 64+16건의 원문·내부 중복 검사와 해시 기록은 위 범위에서 완료했다. 이 검사는 독립 표본의 모든 의미상 중복을 증명하지 않는다.
- 2026-11-17 로컬 보존 실행 기록의 원문 부분 문자열 검사는 위 범위에서 완료했다. 그 밖의 비공개 과거 실행 기록과 저장소 밖 노출은 현재 목록에서 확인할 수 있는 범위만 점검한다. 확인하지 못한 범위는 `확인 불가`로 남긴다.
- 의미 유사성의 판단과 사용자 1인 검수를 명시한다. AI 작성·사람 검수 내부 표본이라는 출처를 보존하며, 사람 직접 작성 표본이나 외부 공식 벤치마크로 부르지 않는다.
