# A/S E→B 고정 후보별 관계 판단 개발 진단 결과

> 2026-11-22. AI 작성·기노출 PC01·NC01에서 파생한 네 쌍의 **개발 진단**이다. [사용자 검수 라벨](nlu_safety_eb_pair_relation_v12_review.md)을 모델 생성 전에 확정했다. 사전 관문은 **실패**했다. 공식 정확도·개선율, B→A 관계, 최종 안전 경로 성능으로 쓰지 않는다.

## 실행과 독립 검증

- [설계·코드](nlu_safety_eb_pair_relation_v12_design.md)는 초기 `a9db516`, 사용자 검수 라벨·실행기·검증기는 생성 전 `6663b0b`에 커밋했다. [프로토콜](../../evals/structured_nlu/data/ai_heldout/as-safety-eb-pair-v12-development-protocol.json)은 생성 전 별도 `139e8f9`에 커밋했고 SHA-256은 `91952aafbff5ec9f7767225ea9bfdd62d42d9b6a105d0ca3f02cb3242079c893`이다. 사용자 검수 문장·상태·근거 번호는 실행 후 바꾸지 않았다.
- 고정 Q5 모델 파일 SHA-256 `644b04cde835d486df33c6d4d7552ba367fcb28802fe39b6b4bb9c60b9ab6f3d`, 서버 이미지 digest `sha256:17155a3ce4cc906728ec99a2814bf0b4eaffaf3b4872bad8c3affed310cdbc35`를 사용했다. 실행기는 컨테이너 생성 전 호스트 파일과 생성 후 읽기 전용 마운트·내부 해시·컨테이너 ID를 확인하고 각 요청 전후 재확인했다. 서버 메모리 안의 실제 가중치 바이트를 독립 증명하지는 않는다.
- PC01/P014→PC01/P016→NC01/P020→NC01/P002 순서로 각 1회 호출했다. 재시도는 없었다. 실제 서버 토크나이저 기준 입력은 각각 **346·344·365·365토큰**이며, 독립 요청 생성기와 고정 요청 해시가 모두 일치했다. 정답 상태는 요청에 넣지 않았다.
- [공개 저널](../../evals/structured_nlu/data/ai_heldout/as-safety-eb-pair-v12-development-journal.v1.jsonl)은 헤더 1행·결과 4행이며 SHA-256은 `04b79815a38044a953e16586fe059f4216234958662d5e1cfe3a7c6a7c721db1`이다. 원문·프롬프트·원시 응답을 담지 않는다. 비공개 원시 응답은 저장소 밖 제한 권한 폴더에 보관했다. [독립 재생 결과](../../evals/structured_nlu/data/ai_heldout/as-safety-eb-pair-v12-development-verification.v1.json) SHA-256은 `2c5735a0f63db8e16deb301209ee7e9613004ed56d1cd5fb3e6a4f292b803fe4`, 실행 전 검증기 SHA-256은 `38b532001bb313491af6af4fb3d6293cfb14f1a8e9dd3b13241f3f37cba15ebe`다. 공개 파일만으로 원시 응답의 의미를 독자적으로 재생할 수는 없다.

## 네 쌍의 판정

| 고정 후보 | 사용자 검수 상태·근거 문장 | Q5 상태·근거 문장 | 상태 | 문장 번호 |
| --- | --- | --- | --- | --- |
| PC01/P014 `선풍기 모터` | `supported`·2 | `supported`·2 | 일치 | 일치 |
| PC01/P016 `모터에서 연기` | `unsupported`·2 | `supported`·2 | 불일치 | 일치 |
| NC01/P020 `타는 냄새` | `unsupported`·2 | `supported`·2 | 불일치 | 일치 |
| NC01/P002 `선풍기` | `insufficient`·3 | `supported`·2 | 불일치 | 불일치 |

전송·길이·출력 계약 오류는 **0/4**, 출력 계약 통과는 **4/4**다. 사용자 검수 상태 일치는 **1/4**, 근거 문장 번호 일치는 **3/4**다. `unsupported` 현상·혼합 구절의 잘못된 승인은 **2/2**, `insufficient` 출처 불명 후보의 잘못된 승인은 **1/1**이다. `supported` 정답 후보는 **1/1** 승인했다. 네 원시 응답의 SHA-256이 같고, 독립 재생에서 네 건 모두 `supported`·2번 문장으로 확인됐다. 정확한 문장 번호를 가리킨 3건 중 2건의 관계 상태가 틀렸다. **문장 위치 확인과 의미 연결은 분리해서 채점해야 한다**는 개발 근거다.

사전 관문은 네 상태와 근거 번호의 전건 일치를 요구했으므로 **실패**했다. 후보를 고정해 주면 올바른 출처와 현상 구절을 구별할 수 있을 것이라는 가설은 이 기노출 네 쌍에서 지지되지 않았다. 이전 v10은 후보 **선택**, 이번 v12는 주어진 후보의 **관계 판단**을 측정해 두 수치를 개선율로 비교할 수 없다. 모든 사례가 이미 노출됐고 각 조건 단회 실행이라 일반화 성능이나 원인 크기를 추정할 수 없다.

저널의 `request_latency_ms`는 모델 요청 외에 호출 전후 파일 검사와 원시 응답 저장을 포함한다. 모델 생성 시간이나 서비스 지연 개선 수치로 인용하지 않는다.

## 다음 판단

이 후보 판정을 전체 후보 재순위화나 서비스 안전 경로에 연결하지 않는다. 다음에는 후보가 위험 현상인지 물리적 출처인지 구분하는 표현 자체가 충분한지, 같은 응답으로 수렴한 원인이 스키마·프롬프트·모델 역량 중 어디에 있는지 **변수를 하나씩 고정한 개발 대조**로 분해해야 한다. 새 방법을 선택한 뒤에는 새 미노출 발화와 후보별 상태·근거의 사용자 검수, 호출 전 동결, 독립 검증이 필요하다. 그 전에는 공식 정확도 개선율을 주장하지 않는다. TX·GB, AWS·KT cloud는 사용하지 않았다. 실행 컨테이너와 Docker Desktop은 종료했다.
