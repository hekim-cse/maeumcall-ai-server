# A/S 위험 사건·출처 v4 탐색 평가 결과

2026-11-15에 사용자 검수한 AI 작성 ES01–ES20의 [전체 필드 정답](nlu_safety_event_source_v4_field_review.md)으로 로컬 Kanana Q5를 한 번 실행했다. 평가 코드·입력 고정 커밋은 `873b432df50e3ac50ba48e817e62022643633da1`, [프로토콜](../../evals/structured_nlu/data/ai_heldout/as-safety-event-source-v4-exploration-protocol.v1.json) 고정 커밋은 `64c8ea8cd9eca61bd8b9722044555ef107b4fcfe`다. 프로토콜 SHA-256은 `8ccf4a662ba6c9147fb12fb23b3472b514e3ca6c92cd4bfd3544326561f00bbf`다. 이전 v3와 같은 Q5 모델 파일 SHA-256, llama.cpp 이미지 ID, CPU 2개·메모리 4GiB·컨텍스트 4096·온도 0을 사용했다. 정답 사건·관계·기대 경로는 프롬프트에 전달하지 않았다. 재시도나 중단 재개는 없었다.

**사전 탐색 게이트는 실패했다.** 현재 제품 위험을 즉시 보호하지 못한 사례가 6/8이고, 다른 제품 위험을 접수 제품의 직접 안전 경고로 잘못 보낸 사례가 5/8이다. ES17·18도 확인 경로를 놓쳤다. 1단계 계약 오류 1건(ES05 구간 순서·겹침), 2단계 인용 계약 오류 1건(ES07)이 있어 오류 0건 조건에도 실패했다. 서비스 안전 분기는 변경하지 않는다.

원시 1단계 응답을 사례별로 검토하면 ES05를 제외한 19건에서 일반 고장·수리 발화를 `observed` 위험 사건으로도 나열했다. ES05는 같은 불꽃 사건을 겹치는 두 구절로 반환해 계약 검증에서 거부됐다. **계약을 통과해 공개 기록에 남은 사건 후보는 39개**로, ES05의 거부된 원시 후보 2개는 제외한 값이다. 검수 정답은 22개지만 **39−22를 그대로 과검출 수로 쓰지 않는다.** 모델이 문장 전체를 사건 구절로 인용하거나 여러 징후를 묶는 방식이 검수 구간과 달라, 사건의 의미상 동일성은 별도 판단이 필요하다. 엄격한 사건 구간·발생 상태 동시 일치 사례는 0/20이며, 이것을 의미상 위험 사건 인식률 0%로 해석하지 않는다. 따라서 사건별 출처 관계의 정확도를 엄격 일치 사례 조건으로 계산할 분모도 0이다. 프로토콜에서 계획한 **의미 기준 사건 누락·과검출 수는 미산정**이며, 별도의 사람 동치성 판정 없이 수치화하지 않는다.

출력 양상은 위험 사건 선택과 제품 귀속을 모두 문제로 남긴다. ES01에서는 원문에 `로봇청소기 전원 연결부`가 있는데도 두 출처 판단이 모두 `other`였다. ES06의 최종 안전 우선 경로는 맞았지만 프린터 용융을 `other`, 일반 종이 걸림을 관찰된 `current` 위험으로 잘못 본 결과였다. 따라서 경로 일치 7건 모두를 올바른 근거의 안전 판단으로 취급할 수 없다. ES11·12에서는 별도 제품에서 불꽃·용융이 발생했는데 접수 제품의 일반 고장 문장을 발생 물건 근거로 인용하며 `current`로 분류했다. ES17에서는 출처 미확정인 탄 냄새를 세 개의 `observed` 후보로 나누고 모두 `other`로 분류했다. ES18에서는 열 발생 여부가 불확실한 얼룩에 더해 일반 고장을 관찰 위험으로 분류해 안전 우선으로 보냈다. 이는 **저장된 모델 출력에서 확인한 실패 형태**이며 모델 내부 원인의 증명은 아니다.

총 모델 요청은 56회(20개 사례당 평균 2.8회)였다. 사례 전체 벽시계 지연 중앙값은 25,757ms, 95백분위는 37,055ms다. 이 값은 로컬 CPU 2개에서의 탐색 평가이며 실서비스 종단 간 지연이나 이전 v3의 2단계 호출 시간과 직접 비교할 수 없다. 모델 로드 시간은 이 사례별 지연에 포함되지 않는다.

[42행 공개 저널](../../evals/structured_nlu/data/ai_heldout/as-safety-event-source-v4-exploration-journal.v1.jsonl)의 SHA-256은 `c1dcce387f7f5ffeeb495bedc6ec7dc0aa7a8518e4f3bf55eebbb828972d7321`이고 [독립 검증 결과](../../evals/structured_nlu/data/ai_heldout/as-safety-event-source-v4-exploration-verification.v1.json)의 SHA-256은 `089e11ac5528a4c46cad0ff0c9fe42668d41c735ddca7feed688c4475d8607f7`이다. 검증기는 저장소 밖 접근 제한 원시 응답의 해시·권한, 모델 파일, 사건 구간, 출처·경로, 집계를 다시 계산했고 공개 저널과 일치했다. 공개 기록에는 발화·프롬프트·원시 응답 본문이 없다. 평가 후 모델 컨테이너와 Docker Desktop을 중지했으며 백엔드·모델 서버 프로세스가 남지 않은 것을 확인했다. AWS와 KT cloud는 사용하지 않았다.

이 20건은 v3 실패를 알고 설계한 **AI 작성·사용자 검수 탐색 자료**다. 이번 `7/20`은 공식 전체 정확도나 일반화 성능이 아니다. 이전 v3 `15/20`은 이미 노출된 RE/V 사례의 **유효한 1단계만 대상으로 한 조건부 관계 점수**이므로 이번 전체 경로 `7/20`과 비교해 개선율이나 하락률을 계산할 수 없다. 다음 후보는 일반 고장과 물리적 위험을 사건 열거 전에 분리하고, 위험이 실제로 관찰됐는지와 어느 제품에 속하는지를 각각 검증해야 한다. 이 20건을 다시 조정에 사용한다면 노출된 개발 자료로 격하하고, 이후 새 사례를 모델 실행 전에 별도로 검수·고정해야 한다.
