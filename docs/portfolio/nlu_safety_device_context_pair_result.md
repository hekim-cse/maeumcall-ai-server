# A/S 기기명 공백과 문맥 출처 판별 대조 결과

사용자가 [DC01–DC10 검수표](nlu_safety_device_context_pair_review.md)를 채택했다. 평가 전에 [입력](../../evals/structured_nlu/data/ai_heldout/as-safety-device-context-dc-reviewed.v1.json), 두 규칙, 채점 코드를 커밋 `9e4c968`에 고정했다. 두 규칙에 같은 발화, 관찰 사건 구절, 출처 후보를 입력했다. 관찰 장소 후보는 DC04-1, DC05-1, DC06-1이다.

| 지표 | 기존 조합 규칙 | 새 기기명·문맥 규칙 |
| --- | ---: | ---: |
| 실제 출처 누락 | 4/4 | 1/4 |
| 관찰 장소 오승인 | 0/3 | 0/3 |
| 전체 오승인 | 0/16 | 0/16 |
| 두 후보를 모두 맞힌 발화 | 6/10 | 9/10 |
| 실행 오류 | 0/20 | 0/20 |

새 규칙은 기기명 내부까지 붙은 DC01과 앞서 실제 기기로 소개한 DC02·DC03의 출처를 승인했다. 보관함 이름이라는 정정(DC07), 같은 이름의 장비가 두 대인 경우(DC08), 같은 사건의 출처 불확실 정정(DC10)은 보류했다. DC09의 가루흡입기 집진판은 원문에 직접 출처로 제시돼 승인 정답을 유지했다. 새 규칙은 기기명이 등록돼 있거나 앞에서 기기로 소개된 경우를 지원하므로 DC09는 누락으로 집계됐다.

별도 회귀 테스트에서 AP09의 붙여 쓴 기기 부위는 승인했다. AP10처럼 앞 문장에 기기 소개가 없는 미등록 조합은 보류했다. 기존 AP 결과는 이전 규칙으로 재실행해 저장본과 바이트 단위로 일치했다.

PR 검토에서 발견한 동명 장비 수량 표기를 보완했다. `네 대`, `2대`, `열한 대`는 보류하고 `한 대`, `1대`는 승인하는 회귀를 추가했다. 보완 뒤 DC와 AP를 다시 실행했고 두 결과 모두 저장본과 바이트 단위로 일치했다.
