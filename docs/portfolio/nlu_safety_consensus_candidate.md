# A/S 안전 분기: 두 판단의 합의와 보류 후보

## 설계 근거

기존 단일 근거 모델과 제품·위험 관계 후보는 RE 사례에서 서로 다른 실패를 보였다. 기존 방식은 현재 제품 위험 RE02를 놓쳤고 다른 출처 RE10을 즉시 보호로 보냈다. 관계 후보는 RE02를 찾았지만 RE09·11·12의 다른 출처를 현재 제품으로 연결했다. 두 결과가 같은 방향으로 틀릴 수 있으므로 합의를 정답 보증으로 보지 않는다.

[고정된 후보 코드](../../scripts/as_safety_consensus_v1.py)는 두 경로가 모두 즉시 보호일 때만 즉시 보호, 모두 일반 수집일 때만 일반 수집, 그 밖의 불일치·확인·오류는 안전 확인으로 보낸다. 이 방식은 위험 신호 하나만으로 즉시 대응하지 않고, 오류를 일반 수집으로 숨기지 않는다. 두 Q5 호출을 쓰므로 지연과 오류 표면이 늘고 확인 질문의 부담이 커질 수 있다. 서비스 그래프에는 연결하지 않았다.

## 노출된 RE01–RE16에서의 개발 계산

이전 [쌍 비교 원자료](../../evals/structured_nlu/data/ai_heldout/as-safety-relation-pair-result.v1.json)의 두 경로를 합성했다. **모델을 다시 실행한 결과가 아니며**, RE는 이미 개발에 노출돼 새 성능 근거가 아니다.

| 구간 | 기준선 즉시/확인/일반 | 합의 후보 즉시/확인/일반 | 기대 |
| --- | --- | --- | --- |
| 현재 제품 실제 위험 4건 | 3 / 0 / 1 | 3 / 1 / 0 | 즉시 보호 |
| 위험·출처 불확실 4건 | 1 / 2 / 1 | 0 / 4 / 0 | 안전 확인 |
| 다른 출처 4건 | 1 / 0 / 3 | 0 / 4 / 0 | 일반 수집 |
| 미발생 4건 | 3 / 0 / 1 | 1 / 2 / 1 | 일반 수집 |

경로 일치는 기준선 9/16, 합의 후보 8/16이다. 현재 제품 실제 위험의 즉시 보호는 3/4로 유지됐고 다른 출처의 즉시 보호 오분기는 1/4에서 0/4로 줄었다. 반면 다른 출처 4건 전부 확인 질문으로 밀렸다. RE16은 두 모델 판단이 모두 잘못 즉시 보호라 여전히 오분기한다. RE13의 관계 후보 오류는 합의 경로에서 확인으로 처리하지만 오류 자체는 별도로 보고해야 한다.

## 새 사례 평가 조건

아래는 **V 실행 전 고정한 계획**이다. 사용자가 전체 필드를 검수한 V01–V16에 대해 후보의 경로 규칙·실행기·모델·요청 설정·데이터 해시를 먼저 고정하고, 두 방식을 교대 순서로 한 번씩 실행하도록 했다. 사전에 볼 핵심 지표는 실제 위험의 즉시 보호 분자/분모, 다른 출처의 잘못된 즉시 보호 분자/분모, 불필요한 확인, 각 arm 오류, 추가 호출 지연이었다. 전체 일치율 한 수치만으로 채택하지 않는다. 새 V도 AI 작성·1인 검수의 표적 탐색으로만 기록한다. 실행과 미채택 판단은 [새 V 평가 결과](nlu_safety_consensus_fresh_result.md)에 기록했다.
