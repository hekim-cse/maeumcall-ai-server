# 16개 상세 업무 정확도 비교용 새 사례 검수 작업지

이 작업지는 포트폴리오에 쓸 **16개 상세 업무 구조화 추출 비교**를 준비한다.
아래 수량은 작은 탐색 평가의 작성 목표이며, 공식 V3 benchmark의 coverage
충족이나 통계적 대표성을 뜻하지 않는다. 공식 결과 조건은
[`evals/structured_nlu/README.md`](../../evals/structured_nlu/README.md)에 있다.
사람 검토의 참고 자료로 [AI 초안 후보 36건](heldout_nlu_ai_candidates.md)을
제공한다. 이 후보는 2026-10-10에 Q5 모델로 탐색 실행했으므로 이제 개발
진단 자료다. **최종 독립 test에는 이 36건이나 가까운 변형을 쓰지 않는다.**
새 발화는 [빈 사람 작성 접수표](heldout_nlu_new_test_intake.md)에 적는다.

## 먼저 고정할 범위

- 기존 방식과 수정 방식에 같은 새 `test` 사례를 사용한다.
- 모델 실행 결과를 보기 전에 새 사례의 발화·정답·그룹·split을 확정한다.
- 사용자가 말하지 않은 날짜·시간·업무 정보를 정답에 넣지 않는다.
- 과거 development 36건, 시간 오류 4건, 탐색 실행한 AI 후보 36건의 문장·
  패러프레이즈를 재사용하지 않는다.
- 실제 사용자 대화와 개인정보를 복사하지 않고 가상 사례만 작성한다.

## 최소 탐색 평가 작성 목록

최종 test에는 각 업무에 새로운 정보 제공 발화 1건과 다른 상황의 어려운/부정 발화 1건을
작성한다. 두 발화는 기존 development 사례와 의미 원본이 달라야 한다. 예약 4개
업무에는 이전 턴의 값이 있는 후속 정보 제공 발화를 1건씩 더한다. 합계는
16 × 2 + 4 = **36건**이다. 이것은 최소 탐색 표본일 뿐, 전체 사용자 발화의
정확도 추정치나 공식 벤치마크라고 부르지 않는다.

각 사례의 발화·정답 작성 기준은
[`annotation-guideline.v1.md`](../../evals/structured_nlu/guidelines/annotation-guideline.v1.md)를
따른다. 정답에는 intent, 현재 상태에서 허용된 user_action, 모든 필드의 값 또는
null, 필요한 change_field, 이전 턴 값, 서버가 제시한 대체 시간을 빠짐없이
기록한다. 작성자가 `draft`로 만든 뒤 문장 의미와 정답을 사람 검수로 확정하고,
검수 원장에 근거·시각·case 지문을 남겨야 한다. **AI가 만든 제안을 그대로
`human_authored`나 `adjudicated`로 표시하지 않는다.**

작성 형식을 볼 때는 기존
[`human-review-packet.v1.md`](../../evals/structured_nlu/drafts/human-review-packet.v1.md)와
[`subagent-human-review-packet.v1.md`](../../evals/structured_nlu/drafts/subagent-human-review-packet.v1.md)를
참고할 수 있다. 두 파일의 발화·정답은 AI가 제안한 미검수 예시이므로 새 테스트
사례로 복사하거나 약간 바꿔 재사용하지 않는다.

## 결과를 쓸 때

두 방식의 `맞힌 건수 / 36건`과 계약 실패 건수를 먼저 적는다. 그 뒤 정답률
차이(퍼센트포인트)를 계산한다. 36건은 작은 탐색 표본이므로 문구는
`16개 상세 업무를 포함한 검수 테스트 36건에서 사례 전체 정답률이 A/36에서
B/36으로 바뀌었다`처럼 범위와 분모를 명시한다. 서비스 전체 정확도가 같은
비율로 개선됐다고 쓰지 않는다. 공식 V3 결과를 원한다면 별도 coverage와
동결 절차를 모두 마쳐야 한다.
