# A/S E→B 판단 기준 명시 대조 개발 결과

> 2026-11-23. AI 작성·기노출 사례 네 쌍의 개발 진단이다. 사전 관문은 **실패**했다. 공식 정확도·개선율, B→A 또는 최종 안전 경로 성능으로 인용하지 않는다.

## 고정과 검증

- [설계와 코드](nlu_safety_eb_criteria_v13_method.md)는 생성 전 `a79168e`에 커밋했고, [프로토콜](../../evals/structured_nlu/data/ai_heldout/as-safety-eb-criteria-v13-development-protocol.json)은 생성 전 별도 `53bedd5`에 커밋했다. 프로토콜 SHA-256은 `a0e3282e68a1ec0e278917c02b06361f0c577100d3109f804d99ed5a6de46d5f`다.
- Q5 파일 SHA-256은 `644b04cde835d486df33c6d4d7552ba367fcb28802fe39b6b4bb9c60b9ab6f3d`, 서버 이미지 digest는 `sha256:17155a3ce4cc906728ec99a2814bf0b4eaffaf3b4872bad8c3affed310cdbc35`다. 생성 당시 Docker 메모리 한도는 12,527,820,800바이트였다. 실행기는 모델 파일·읽기 전용 마운트·컨테이너 신원을 요청 전후에 검사했다. 서버 메모리 속 가중치 바이트를 직접 증명하지는 않는다.
- 기존 v12 프로토콜·저널 해시와 비공개 원시 응답을 먼저 재검증했다. 이전과 같은 PC01/P014 → PC01/P016 → NC01/P020 → NC01/P002 순서로 각 1회 호출했고 재시도는 없었다. 서버 토크나이저 기준 새 요청 입력은 각각 **420·418·439·439토큰**이었다. 독립 생성 요청 해시가 네 건 모두 고정 값과 일치했고, 요청 JSON에서 **시스템 메시지의 판단 기준 문단만** 이전과 달랐다. 검수 정답은 요청에 보내지 않았다.
- [공개 저널](../../evals/structured_nlu/data/ai_heldout/as-safety-eb-criteria-v13-development-journal.v1.jsonl) SHA-256은 `c968df6d3a8a9e7099c69cab949aaf745e4360468541f1295db1d5fc8eb1d371`이다. 원문·프롬프트·원시 응답은 저장소에 넣지 않았다. [독립 검증 결과](../../evals/structured_nlu/data/ai_heldout/as-safety-eb-criteria-v13-development-verification.v1.json) SHA-256은 `560eea97653063bf10c79a3608f482637e76b4aac6f18b44273ef442fffe1dc3`다. 공개 파일만으로 원시 응답의 의미를 독자적으로 재생할 수는 없다.

새 호출은 네 건 모두 `stop`으로 끝났고 전송·출력 계약 오류는 **0/4**, 계약 통과는 **4/4**다. 상태 일치는 **1/4**, 근거 번호 일치는 **3/4**로 v12와 같다. 현상·혼합 후보의 잘못된 승인은 **2/2**, 출처 불명 후보의 잘못된 승인은 **1/1**이다. 네 쌍 모두 v12와 v13의 비공개 원시 응답 SHA-256이 **바이트 단위로 동일**했다. 상태·근거 전건 일치 관문은 실패했다.

이 결과는 **판단 기준 한 문단 추가가 네 기노출 사례의 출력에 영향을 주지 않았다**는 관찰이다. 모델이 시스템 메시지를 무시했다거나 스키마가 답을 강제했다는 기계적 원인까지 증명하지 않는다. [`llama.cpp`의 현재 공식 설명](https://github.com/ggml-org/llama.cpp/blob/master/grammars/README.md)은 JSON 스키마가 출력 제약에 사용되며 프롬프트에 삽입되지 않는다고 설명하지만, 이번 고정 이미지의 실제 스키마 적용 여부를 별도로 검증한 것은 아니다. 같은 모델·요청 설정과 기존 원시 응답을 사용했지만, 서로 다른 날의 단회 실행이라 반복 변동성도 추정할 수 없다.

## 실행 후 리뷰 수정

PR #112 리뷰에서 검증기가 `finish_reason=length`인데 `error_code=null`인 저널을 거부하지 못하는 결함을 확인했다. 실제 네 행은 모두 `stop`·오류 없음이므로 공개 저널, 검수 라벨, 기존 독립 검증 결과와 위 수치를 바꾸지 않았다. 검증기는 이제 종료 사유와 오류 코드의 조합, 오류 후 후속 행을 확인한다. 잘못된 enum·추가 필드·공백 응답·전송 오류에서 첫 실패 후 중단과 재실행 거부를 확인하는 테스트도 추가했다. 생성 전 고정 커밋 `a79168e`의 **전체 소스 해시** 검사는 유지한다. 실행 후 수정된 검증기와 이 테스트 파일만 현재 작업 트리 해시 대조에서 제외하며, 나머지 소스·프로토콜·요청·원시 응답 해시 대조는 유지한다. 모델은 다시 호출하지 않았다.

## 다음 판단

문장 수정을 더 반복하기 전에 **실제 서버에서 스키마가 enum을 강제하는지**, **모델 출력이 명백히 다른 지시에도 반응하는지**를 각각 인위적 통제 사례로 검사하는 편이 원인 범위를 좁힌다. 이 통제 사례는 의미 정확도 평가가 아니다. 그 결과에 따라 프롬프트 설계와 구조화 출력 설정 중 어느 쪽을 수정할지 결정한다. 이후 새 미노출 사례에서 후보 선택·관계 판단·보류·B→A·안전 경로를 분리 검증해야 한다. 이번 변경은 실서비스에 연결하지 않았다. TX·GB, AWS·KT cloud는 사용하지 않았다.
