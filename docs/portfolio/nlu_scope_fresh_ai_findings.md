# 새 AI 작성 사례에서 범위 판단 지시문 재탐색

2026-11-05에 기존 B01–B32와 다른 AI 작성 발화 F01–F32를 준비했다.
사용자는 문장·행동 방향을 탐색용으로 채택하고, 필드 초안에서는 F17의 재배달
희망과 F29의 날짜 공란을 수정했다. 16개 업무마다 범위 안 1개와 가까운 범위 밖
1개를 사용했다. 각 문장을 Q5의 기본 지시와 범위 밖 요청을 `unknown`으로
분류하도록 명시한 추가 지시에 각각 두 번 실행했다. 두 번째 반복에서는 사례와
조건의 순서를 뒤집었다. **64회는 32개 고유 문장의 두 번 반복**이다.

짝 비교에서 추가 지시만 계약·행동 방향을 함께 맞힌 것은 11회다. F02는 1회,
F06·F08·F18·F20·F30은 각각 2회였다. 기본 지시만 맞힌 관찰은 없었다.
기본 조건에서 두 반복 모두 맞힌 범위 밖 문장은 F26 하나였고, 추가 지시에서는
F02·F06·F08·F18·F20·F26·F30 일곱 개였다. 다만 추가 지시에서도 **9/16개**
범위 밖 문장은 두 반복 모두 계약·행동을 함께 맞히지 못했다.

범위 안 F15(주문 음료 변경)와 F23(온라인 등본 발급)는 두 조건·두 반복에서
모두 `provide_details`를 출력했으나 이번 턴의 필수 필드를 하나도 채우지 않아
계약에 실패했다. 추가 범위 지시가 이 문제를 고치지는 못했다. F29의 “평일”은
사용자 검토에서 특정 날짜가 아니므로 `date=null`로 정했지만, 두 조건 모두
두 번씩 `date` 값을 출력했다. 따라서 계약과 행동이 맞아도 사용자가 의도한
날짜 재질문으로 이어진다고 보장할 수 없다. F17에서 사용자가 정한 재배달 희망
필드도 네 관찰 모두 출력되지 않았다. 이 내용은 저장된 안전한 출력 형태와
필드 이름 불일치로 확인했으며, 생성 값 전문은 저장하지 않았다.

[실행 보고서](../../evals/structured_nlu/results/exploratory-q5-fresh-scope-instruction-2026-11-05.json)는
입력·검토표·코드 커밋과 해시, 로컬 파일의 Q5 SHA-256, 서버 이미지 digest,
요청 설정, 사례별 관찰을 기록한다. 같은 로컬 ARM Docker 환경에서 CPU 4개·
스레드 4개·단일 슬롯·메모리 제한 6GiB·컨텍스트 4096으로 두 조건을 교차
실행했다. 모델 해시는 지정한 **로컬 파일**에서 검증한 값이며 서버가 실제로
그 파일을 서빙했는지 별도로 증명하지 않는다. 요청 시간 합계는 토큰·캐시·
재시도 차이가 있어 속도 우열로 해석하지 않는다. 실행 후 컨테이너는 종료했다.

이 결과는 **사전에 검토한 새 AI 작성 개발 사례의 탐색 재현**이다. 이전 B사례의
2/32→10/32와 같은 방향으로 범위 밖 판단이 달라졌지만, AI 출처와 16개
고유 범위 밖 문장이라는 작은 표본, 반복 관찰의 상관성 때문에 공식 정확도·
개선율·통계적 우월성·운영 성능으로 쓰지 않는다. 이번 F사례도 실행으로 모델에
노출됐으므로 독립 test에 재사용하지 않는다. 추가 지시는 서비스에 적용하지
않았다. 다음에는 행동 경계와 필드 누락·모호한 날짜를 별개 문제로 다루고,
사람 작성·정답 확정·동결된 독립 test에서 최종 판단해야 한다.
