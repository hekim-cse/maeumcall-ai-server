# A/S 안전 합의 후보: 새 V01–V16 탐색 결과

## 평가 경계

사용자가 2026-11-09에 V01–V16의 문장·기대 경로와 제품·위험 근거 및 전체 필드를 탐색용으로 검수했다. 입력은 [검수본](../../evals/structured_nlu/data/ai_heldout/as-safety-relation-v2-fresh-reviewed.v1.json)에 고정했다. AI 작성·1인 검수 발화이므로 **표적 탐색 평가**이며 공식 전체 정확도나 배포 성능이 아니다. 앞선 RE 사례는 합의 규칙을 정하는 개발용으로만 사용했고 이번 분모에 넣지 않았다.

합의 규칙·비교 실행기·독립 검증기·Q5 모델·요청 정책·입력 해시를 첫 V 호출 전에 [프로토콜](../../evals/structured_nlu/data/ai_heldout/as-safety-consensus-fresh-protocol.v1.json)로 커밋했다. 같은 로컬 Q5 모델을 CPU 2개, 메모리 4 GiB 조건으로 실행했다. 기준선과 관계 후보를 사례마다 번갈아 호출했고, 오류가 나도 재시도하지 않았다. [원자료](../../evals/structured_nlu/data/ai_heldout/as-safety-consensus-fresh-result.v1.jsonl)의 SHA-256은 `1a41cf1831b936528aff199c79a0fa87fe22bf80a348556ddb8c537627fd684e`다. 16건·32호출의 시작과 종료 65줄을 보존했고 발화·응답 전문은 저장하지 않았다. 별도 [검증기](../../scripts/verify_as_safety_consensus_fresh.py)가 순서, 고정 소스 해시, 제한된 판단값, 경로, 집계를 다시 계산해 통과했다.

## 결과

| 검수 구간 | 기준선 경로 일치 | 관계 모델 경로 일치 | 합의 경로 일치 | 합의 즉시/확인/일반 |
| --- | ---: | ---: | ---: | --- |
| 현재 제품 실제 위험 8건 | 7/8 | 7/8 | **6/8** | 6 / 2 / 0 |
| 다른 출처의 위험 4건 | 3/4 | 0/4 | **0/4** | 1 / 3 / 0 |
| 위험 출처 불확실 1건 | 0/1 | 0/1 | **0/1** | 0 / 0 / 1 |

| **전체 16건** | **10/16** | **10/16** | **6/16** | **7 / 8 / 1** |

실제 위험을 즉시 보호한 건수는 기준선 7/8에서 합의 후보 6/8로 **감소**했다. 다른 출처의 잘못된 즉시 보호는 기준선과 합의 후보 모두 1/4로 **줄지 않았다**. V06에서는 두 모델이 같은 다른 제품의 위험을 현재 제품의 위험으로 잘못 판단해 합의 규칙도 즉시 보호로 오분기했다. V01·V03은 한 모델만 실제 위험을 즉시 보호로 봐 합의 후보가 확인 질문으로 늦췄다. V09의 출처 불확실성은 두 모델 모두 일반 수집으로 보내 확인 질문도 놓쳤다.

V13 기준선은 계약 검증 단계에서 `ValueError` 1건이 발생했다. 오류는 전체 16건 분모에 포함했고, 합의 규칙은 확인 경로로 처리했다. 오류의 세부 응답은 저장하지 않아 원인을 더 단정하지 않는다. 관찰 지연 중앙값은 기준선 호출 약 1.44초, 관계 호출 약 2.38초, 두 호출 합계 약 3.82초였다. 단일 로컬 실행의 지연이며 배포 환경 지연이나 비용 추정으로 일반화할 수 없다.

## 판단

개발 RE에서는 합의 후보가 다른 출처의 즉시 보호 오분기를 1/4에서 0/4로 줄였지만, **새 V에서는 그 개선이 재현되지 않았다.** 실제 위험의 즉시 보호도 낮아졌고 확인 질문이 늘었다. **합의 후보를 미채택하고 서비스 그래프에 연결하지 않는다.** 두 프롬프트의 동의는 독립적인 사실 확인이 아니며, 같은 모델의 상관된 오류(V06)를 걸러내지 못했다. 이 결과를 포트폴리오의 정확도 개선율로 쓰지 않는다. 대신 사전 고정·쌍 비교·오류 단계·안전 누락과 오분기를 분리해 후보를 기각한 근거로 사용할 수 있다.

다음에는 모델 프롬프트를 더 다듬어 V에 재실행하지 않는다. RE와 V 모두 이제 개발에 노출됐다. 다른 도구나 모델을 시도하려면 제품·위험의 소유 관계를 원문 근거로 확인할 수 있는지 개발 자료에서 검증하고, **새로 작성·검수한 사례**를 별도 미노출 탐색 분모로 준비해야 한다.
