# A/S 위험 주체 후보 ID 계약 설계

> 2026-11-22. v9 개발 진단의 실패를 바탕으로 만든 **오프라인 계약 시제품**이다. 새 실모델 호출, 서비스 연결, 정확도 측정은 아직 하지 않았다.

## 관찰에서 설계로

v9의 PC01 N에서 모델은 원문에 존재하지만 제시된 7개 후보에는 없는 18자 문장 전체를 반환했다. 기존 두 필드 계약은 `subject_span`이 원문에 있는지만 확인하므로 이 응답을 형식상 허용했다. 따라서 후보를 줄이는 프롬프트만으로 후보 경계를 강제할 수 없었다.

새 인터페이스는 모델에 원문에서 생성한 후보의 **ID**만 선택하게 한다. 출력은 `candidate_id`(제시한 ID 또는 `null`)와 `event_subject_kind` 두 필드다. 서버가 ID를 후보 표의 문장 번호·원문 구절로 변환한다. 목록 밖 ID, 임의 원문 구절, 중복 JSON 키, 잘못된 종류, `null`과 종류의 불일치를 거절한다. 모델이 후보 목록에 없는 정답을 만들어낼 수는 없으므로, **후보 생성 누락은 별도 실패**로 측정해야 한다. `null/unresolved`는 출처를 확인할 수 없는 사례에 그대로 남긴다.

| 경계 | 이번 시제품에서 검증한 것 | 아직 증명하지 않은 것 |
| --- | --- | --- |
| 후보 출처 | 후보 ID의 유일성, 원문 위치·인용·해시 일치 | 후보가 의미상 위험 주체인지 |
| 모델 출력 | ID의 목록 소속, 공란·종류 일관성, 엄격한 JSON | Q5가 이 형식에서 정답을 고르는지 |
| 원문 복원 | 선택 ID를 원래 문장 번호·구절로 변환 | B→A 관계·최종 안전 경로 |
| 모델 식별 | 다음 실행에 쓸 호스트 파일·컨테이너 마운트의 변경 감지 도구 | v9 실행 당시 적재된 메모리 바이트의 소급 증명 |

## 다음 실모델 진단의 사전 조건

1. 새 프롬프트와 후보 ID 집합·동적 JSON 스키마가 고정 Q5 서버에서 실제로 지원되는지 확인한다. 현재는 오프라인 코드·테스트만 검증했다. 모델에 정답 B나 골드 후보 ID를 전달하지 않는다.
2. 원문만으로 후보를 생성하고, 정답 후보가 목록에 있는지 **사후에만** 확인한다. 정답이 누락된 사례는 모델 오답과 분리한다.
3. 모델 파일 스냅샷을 컨테이너 생성 **전**에 만든다. 컨테이너 생성 시각·읽기 전용 마운트·내부 파일 SHA-256·호스트 파일 식별자를 확인하고 각 요청 전후 반복한다. 어느 단계든 검증할 수 없거나 불일치하면 호출 결과를 저널에 기록하지 않고 중단한다. 현재 도구는 독립 모듈이며 실행기에는 아직 연결하지 않았다.
4. 고정 프로토콜과 코드·입력·모델·컨테이너 식별자, 요청 해시, 호출 순서, 토큰 예산, 재시도 금지와 원시 응답 보관 경로를 **실행 전에 커밋**한다. 새 실모델 결과는 기존 v9 원시 응답·저널과 섞지 않는다.
5. 지표를 후보 가용성, 출력 계약 통과, 후보 ID 소속, B·종류 정확 일치, 정당 보류, 전송·길이 오류로 나눠 분모와 함께 보고한다. 기노출 개발 사례로 선택한 방법을 공식 정확도 개선율로 쓰지 않는다. 미노출 사례와 전체 정답은 이후 별도 검수·사전 고정한다.

이번 코드의 모델 파일 관문은 일반적인 파일 교체·수정과 마운트 변경을 감지하도록 설계했다. 악의적 Docker 데몬이나 서버 프로세스 메모리 변조에 대한 증명은 아니다. 고정 이미지 digest `sha256:17155a3ce4cc906728ec99a2814bf0b4eaffaf3b4872bad8c3affed310cdbc35`의 일회성 로컬 컨테이너에서 `docker exec ... sha256sum /models/kanana.gguf`가 예상 모델 SHA-256 `644b04cde835d486df33c6d4d7552ba367fcb28802fe39b6b4bb9c60b9ab6f3d`를 반환함을 확인했다. 이는 해시 도구·마운트의 스모크 테스트이며 `ModelAttestor`를 실제 모델 서버의 요청 경로에 연결한 통합 테스트는 아니다. 임시 컨테이너를 삭제하고 Docker 엔진을 종료했다. AWS·KT cloud는 사용하지 않았다.

오프라인에서 후보 ID 계약·파일 교체/수정·마운트/컨테이너 교체·호출 전후 관문과 v9 회귀를 함께 실행해 **51개 테스트 통과**를 확인했다. 새 코드와 테스트의 Ruff check/format도 통과했다. 이 수치는 실모델 정확도가 아니다.
