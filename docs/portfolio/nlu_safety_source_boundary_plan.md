# A/S 안전 출처 경계 재검증 계획

## 관찰과 선택

[출처 연결 단독 진단](nlu_safety_gold_owner_link_result.md)에서 검수된 위험 주체 구간까지 제공했지만, Q5는 다른 출처 6건을 모두 `current`로 판단했다. 별도 코드 점검에서는 현행 서비스의 [위험 문구 가드](../../services/flow/service_workflow/safety.py)가 출처 관계를 확인하기 전에 [즉시 안전 상태로 이동](../../services/flow/service_workflow/nodes.py)함을 확인했다. 기존 다른 출처 6건 중 RE09·RE11·V02가 이 가드에 걸렸다. 이는 모델의 관계 오답과 별개의 서비스 경로 문제이며, 6건은 이미 여러 번 사용한 개발 사례다.

[재현 가능한 가드 감사](../../scripts/audit_as_safety_pre_model_guard.py)에서 기존 RE/V 32건 중 **A/S 그래프가 가드 적용 상태에 있을 때 선행 패턴에 일치하는 사례**는 5건이었다. 그중 검수 방향과 맞는 현재 제품 실제 위험이 2건(V01·V05), 다른 출처의 잘못된 즉시 조치가 3건(RE09·RE11·V02)이었다. 현재 제품 실제 위험 12건 중 가드에 걸리지 않은 10건은 이후 모델 경로가 결정하므로 이 감사만으로 보호 누락이라고 세지 않는다. 이 감사는 정규식 함수를 실행한 것이며 전체 그래프를 실행한 결과가 아니다. 이 수치는 기노출 개발 사례의 **선행 가드 패턴**만 나타낸다.

문자열 불일치만으로 다른 출처를 확정하는 이전 근거 후보는 현재 제품의 실제 위험을 놓쳐 기각됐다. 6필드 typed 관계 후보는 계약 오류가 많았고, 검수된 타출처·불명 사례 수는 작은 지도 분류기 학습에 부족하다. 따라서 서비스 코드는 아직 바꾸지 않는다. **명시적인 연결 근거만 확정하고 나머지를 보류하는 규칙**도 [기노출 RE/V 22건의 개발 진단](nlu_safety_source_link_development_result.md)에서 현재 제품 5/16·다른 출처 1/6만 확정해 기각했다. 이 진단은 정답 원문 구간을 입력으로 준 규칙의 결과이며 모델이나 전체 그래프의 점수가 아니다.

그다음 시험한 가설은 Q5에 위험 판단을 함께 요구할 때 발생한 `current` 쏠림이, **위험 주체가 접수 대상과 동일한 물건 또는 그 소속 부품·부위인지**만 묻는 중립적인 단일 판단에서도 재현되는지 확인하는 것이었다. 단순히 '같은 물리적 개체'라고 물으면 배터리 같은 부품을 별개로 오해할 수 있다. 이미 노출된 RE/V 22건에서 개발 진단으로 반증했다. 요청에는 원문과 검수된 접수 대상·주체 구절 및 문장 번호만 넣고, 사건 발생 상태·위험 사건 구절·관계 정답·연결 종류는 넣지 않았다. 출력은 `same_or_part`·`distinct_item`·`unresolved` 한 필드로 한정하고, `current`·`other`·안전 경로 용어는 서버 매핑에서만 사용했다. 새 GB 사례에는 이 후보를 실행하지 않았다.

[실행한 중립 단일 판단 진단](nlu_safety_entity_link_diagnostic_result.md)은 기노출 RE/V 22건에서 현재 제품 16/16을 연결했지만 다른 출처는 1/6만 확정하고, 타출처 2건을 현재 제품으로 오분류했다. 기대한 대비쌍 반전도 0/3이므로 사전 게이트에 실패했다. 이 후보 역시 서비스와 GB 평가에 올리지 않는다. 다음 개발 과제는 거짓 동일 판정 두 건과 보류 세 건에서 **소유·소속 근거가 어떻게 표현되는지**를 분리 분석하는 것이다.

이 개발 진단의 주 지표는 현재 제품 16건·다른 출처 6건의 관계 혼동행렬, 보류·계약 오류, 타출처의 거짓 동일 판정과 현제품의 거짓 분리 판정을 각각 세는 것이다. 실제 관찰된 현제품 위험 13건은 즉시 연결 13/13, 타출처 6건은 분리 6/6, V 대비쌍은 반전 3/3, 계약·호출 오류는 0/22를 사전 게이트로 둔다. RE06의 조건부 사건과 V04의 이번 진단 전용 대상 해석은 별도 표시한다. 파생 안전 경로는 검수 발생 상태를 뒤에서 결합한 오라클 경로이며 모델이나 실서비스가 직접 낸 경로가 아니다. 기존 Q5의 16/22와 새 실행 결과를 나란히 제시하더라도 입력과 출력 표현이 함께 바뀌므로 인과적 개선율로 쓰지 않는다.

서비스 설계에서는 **접수 제품의 A/S 경로**와 **발화에 등장한 어느 기기든 실제 위험이 있으면 필요한 일반 안전 안내**를 별도 판단으로 다뤄야 한다. 다른 기기에서 연기가 났다는 이유만으로 접수 제품을 `safety_action_required`에 묶는 것은 관계 오분기일 수 있지만, 그 기기에 관한 안전 안내가 불필요하다는 뜻은 아니다. 현행 그래프는 두 판단을 한 `safety_status`와 경로에 담으므로, 이번 실험은 먼저 A/S 경로의 출처 오류를 계측한다. 안전 안내 분리와 실제 그래프 통합은 별도 정책·사용자 흐름 검토 뒤에 결정한다.

## 평가 경계

이번 [새 AI 작성 발화 검수 기록](nlu_safety_source_boundary_fresh_review.md)은 기존 RE/V 문장을 그대로 바꿔 쓰지 않고, 접수 대상과 위험 주체를 바꾸는 대비쌍·타인 소유의 동일 모델·부품·출처 불명·설명서/가정 문맥을 담는다. 사용자는 **문장과 기대 경로를 먼저**, 이어서 [접수 대상·위험 사건·주체 원문 구간·발생 상태·관계·공란](nlu_safety_source_boundary_field_review.md)을 탐색 평가용으로 채택했다. 두 단계 검수는 끝났지만 새 GB 발화는 아직 모델에 실행하지 않았다. AI 작성 출처와 사용자 검수 여부를 기록하며, 모델 미실행 상태를 성능 결과로 표현하지 않는다.

후보와 기준선은 같은 검수 사례·요청 설정에서 사례별 한 번씩 실행한다. 사전에 코드·데이터·모델·요청 정책·순서·검증기 해시를 고정하고, 중단은 자동 재시도하지 않는다. 모델 호출 저널에는 발화나 응답 본문을 저장하지 않는다. 현행 위험 문구 가드의 선행 분기도 별도로 계측해 **모델 관계 오답**, **가드로 인한 거짓 즉시 보호**, **현재 제품 실제 위험의 보호 누락**, **출처 불명의 확인 누락**, **계약 오류**를 분리 집계한다. 대비쌍의 반전과 문장 순서별 결과도 보고한다.

GB 평가에 이르렀을 때 측정은 세 층으로 나눈다. ① 현행 가드의 패턴 일치와 **가드 적용 상태일 때의 조건부 강제 경로**만 계산한다. 패턴이 안 맞은 사례의 최종 경로는 이 층에서 알 수 없다. ② 기존 4필드 관계 후보를 같은 Q5 설정의 개발 기준선으로 실행한다. ③ 개발 게이트를 통과한 새 후보가 원문 구절과 발생 상태를 추출하고 서버가 앵커·연결 근거를 검증한 뒤 불명확하면 보류한다. 사람이 검수한 구절·관계·경로는 두 모델 요청에 넣지 않는다. 세 층을 합성한 경로는 **그림자 경로**로만 표시하고 실제 서비스 실행 결과라고 부르지 않는다. 현재는 ③의 후보가 없어 GB 평가를 시작하지 않았다.

실제 위험이 있거나 의심되는 18건은 현재 제품 6, 다른 출처 6, 출처 불명 6으로 나눠 관계·경로를 평가한다. GB19–GB24의 미발생·사건 없음 6건은 정상 경로 여부를 평가하되, 자료 속 위험을 실제 주체 추출 성공으로 세지 않는다. 인용 구절의 정확 일치와 의미상 관계 판단도 분리한다.

사전 탈락 조건은 현재 제품 실제 위험의 즉시 조치 6/6 미만, 다른 출처 실제 위험의 일반 접수 6/6 미만, 출처 불명의 안전 확인 6/6 미만, 미발생·사건 없음의 일반 접수 6/6 미만 또는 모델 오류 1건 이상이다. 다른 출처의 거짓 즉시 조치만 0으로 만드는 과잉 보류도 통과시키지 않는다. 이 엄격한 개발 게이트는 작은 표적 집합의 후보 선택용이며, 통과해도 서비스 채택이나 일반화된 성능 증거가 아니다. 결과는 **AI 작성·사용자 검수 탐색 평가**로만 표현한다. 공식 전체 정확도 개선율을 주장하려면 독립된 미노출 평가 설계가 더 필요하다.
