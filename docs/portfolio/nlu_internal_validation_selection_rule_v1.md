# NLU 범위 계약 후보: validation 선택 규칙 V1

> 상태: **모델 호출 전 사전 지정**. 이 규칙은 AI 작성·사용자 검수 validation 32건에서 단일 범위 계약 후보를 고르는 기준이다. 이 결과로 공식 정확도 개선율을 주장하지 않는다.

## 비교 대상과 분모

- 기존 방식은 PR #89 병합 코드의 구조화 NLU 경로, 후보는 16개 업무별 지원 요청·범위 밖 요청을 같은 한 번의 모델 호출에 명시한 경로다. 두 코드 커밋·모델 파일·서버 이미지·요청 설정·평가 자료는 첫 validation 호출 전 프로토콜에 동결한다.
- 같은 32건을 양 조건에 실행한다. 업무마다 업무 안 1건·범위 밖 `unknown` 1건이며 전부 `greeting`이다. 호출 선후는 행동 그룹마다 균형을 맞춘 AB/BA 순서로 고정한다. 원시 응답과 각 시도 결과를 보존하고 독립 재생 검증이 통과해야 비교를 해석한다.
- 주지표는 출력 계약·`intent`·`user_action`·`change_field`·모든 필드가 동시에 맞은 `case_exact_match`의 **짝지은 건수 차이**다. 같은 사례에서 기존만 정답·후보만 정답·둘 다 정답·둘 다 오답을 나눠 보고한다. 한 건 차이는 32건에서 3.125%p이므로 작은 차이를 일반적 우위로 말하지 않는다.

## 후보 선택 관문

다음 조건을 **모두** 충족할 때만 이 후보를 새 test로 가져간다.

1. 후보의 사례 전체 일치 건수가 기존 방식보다 많다. 동률이면 선택하지 않는다.
2. 업무 안 발화를 `unknown`으로 잘못 분류한 건수가 기존 방식보다 늘지 않는다. 범위 밖 개선을 위해 정상 요청을 거절하는 부작용을 막기 위한 관문이다.
3. 최종 출력 계약 실패 건수가 기존 방식보다 늘지 않는다. 계약 실패와 의미 오류를 분리해 보고한다.
4. 기존에 노출된 별도 A/S 직접 위험 개발 사례에서 새 직접 위험 누락이 발견되면 후보를 보류한다. 이 점검은 안전 회귀 관문일 뿐, validation이나 공식 test 정확도 분모에 합치지 않는다.

범위 밖 `unknown` 행동 적중·필드 누락·불필요 값·값 불일치·지연시간은 보조 지표로 분리해 보고한다. 동결된 두 조건에 전송 오류·OOM·예기치 않은 서버 재시작이 있으면 이번 짝 비교 전체를 무효 처리하고, 조건을 바꾼 새 프로토콜로 처음부터 재실행한다.

validation 결과를 본 뒤 이 후보의 문구를 수정해 같은 32건으로 반복 선택하지 않는다. 관문을 통과하지 못하면 해당 후보를 기각하거나, 새 버전의 후보와 별도 새 validation을 사전 동결해 평가한다. test 문장은 후보 선택·코드 동결 **후** 작성한다. 최종 test는 16개 업무 각각 시작 상태 정상/범위 밖과 후속 상태 정상/범위 밖을 가능한 한 교차하고, A/S 위험 사례를 별도 분모로 보고한다.

이 validation은 저장소에 공개된 AI 작성 문장을 사용한다. 후보 구현에는 validation 문장·정답을 참조하지 않는 절차를 적용하지만, 파일 접근 자체를 암호학적으로 막지는 못한다. 최종 주장은 새 미노출 test의 범위와 작성 출처를 그대로 밝힌다.
