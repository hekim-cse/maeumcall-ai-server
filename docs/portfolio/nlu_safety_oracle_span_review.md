# A/S 관계 하위 과제: 원문 구간 주석 검수 기록

아래 `target_mention`과 `hazard_event_mention`은 **AI가 작성하고 사용자가 2026-11-11에 개발 진단용으로 검수한 원문 구간**이다. 사용자는 V03의 대상을 전기포트, V04의 대상을 토스터로 지정했고 나머지 22건과 모든 위험 사건 구간을 표대로 채택했다. RE/V의 기존 발화와 `product_index`·`hazard_index`·`event_status`는 사용자 검수 후 이미 모델에 노출된 [RE 데이터](../../evals/structured_nlu/data/ai_heldout/as-safety-relation-fresh-reviewed.v1.json)와 [V 데이터](../../evals/structured_nlu/data/ai_heldout/as-safety-relation-v2-fresh-reviewed.v1.json)에서 가져왔다. 기존 문장·정답·실행 기록은 바꾸지 않는다. `nonoccurring` 8건을 제외한 발생·불확실 24건만 표시한다.

각 인용은 원문에서 **한 번에 이어지는 부분문자열**이어야 하고, 대상 인용은 gold `product_index` 문장 안에, 위험 인용은 gold `hazard_index` 문장 안에 있어야 한다. 모델에 제공할 때는 원문 전체를 유지하고 두 구간을 판정 대상으로 가리켜야 한다. 위험 인용만 떼어 모델에 주면 V09의 뒤 문장에 있는 출처 불확실성과 V06·V08의 수리 질문 문맥이 사라진다. 여기의 구간은 관계 정답이나 기대 경로를 포함하지 않는다.

## 해석 경계

- V03·V04는 첫 문장이 전기포트와 토스터 **둘 다 접수 대상**으로 읽힐 수 있다. 사용자는 oracle 진단의 대상으로 V03은 **전기포트**, V04는 **토스터**를 지정했다. 따라서 이번 진단에서 V04의 위험 출처 관계는 `current`, 기대 경로는 **즉시 보호**가 된다. 이는 기존 V04 데이터의 `other`·**일반 수집** 정답과 충돌하는 **별도 새 해석**이다. 기존 데이터와 원본 점수는 소급 변경하지 않는다. 진단에서는 V03·V04를 별도 표기하고, 나머지 22건과 합친 집계의 라벨 출처가 서로 다름을 명시해야 한다.
- `target_mention`과 `hazard_event_mention`을 둘 다 oracle로 주면 **gold로 목표와 위험 사건을 찾은 뒤 남는 관계 판단**만 조건부로 시험한다. 실제 서비스에서는 두 구간과 발생 상태를 모른다. 따라서 이 결과를 기준선 32건의 전체 경로 일치율과 대등한 성능 개선율로 비교하면 안 된다.
- 반대로 gold 문장 번호만 주면 V01–V04처럼 한 문장에 제품이 여럿 있고 V06·V08처럼 위험과 수리 질문이 한 문장에 섞인 문제를 모델이 다시 풀어야 한다. 이는 순수 관계 하위 과제가 아니라 **대상·사건 선택을 포함한 결합 과제**다.

이 구간 검수는 이번 개발 진단의 입력 승인이다. 모델 호출 전 입력 형식·누출 방지·분모·오류 처리·중단 규칙을 별도 프로토콜에 고정한다.
