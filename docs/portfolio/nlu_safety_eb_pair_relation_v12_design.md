# A/S E→B 후보별 관계 판단 계약 설계

> 2026-11-22. 실행 **전 설계**다. 사용자 검수·프로토콜 고정·실모델 호출은 아직 하지 않았다. 현재 서비스 경로와 안전 가드를 바꾸지 않는다.

## 이전 결과에서 남은 문제

[v10 후보 ID 진단](nlu_safety_eb_candidate_id_v10_development_result.md)은 출력 계약 2/2를 통과했지만 PC01의 주체 구절 선택과 NC01의 보류에 실패했다. [v11 오프라인 진단](nlu_safety_eb_candidate_evidence_v11_offline_result.md)에서는 오답 후보가 사건 구절 안 또는 경계를 가로지르는 위치에 있음을 확인했다. 위치만으로는 관계를 증명할 수 없고, `nominal_chunk` 일괄 필터는 기노출 26건의 정답 주체 중 2개를 잃는다.

이전 E→B 세 필드 동시 생성에서는 검수 정답이 있는 18건도 모두 보류했다. 주체만 요구한 개발 비교에서도 보류가 풀리지 않아, 근거 구절 동시 생성 **하나**를 전건 보류의 원인으로 단정할 수 없다. 이번 계약은 선택 문제와 관계 판정을 분리해 실패 위치를 확인한다.

## 고정된 후보 한 개에 대한 세 상태

[계약 코드](../../experiments/as_safety_atomic_edges_v12/pair_contract.py)는 기존 `nominal_end` 후보 ID 하나를 입력에 고정한다. 모델에는 원문, 검수된 사건 E, 해당 후보 ID·원문 구절을 보여 준다. B 정답이나 관계 상태 정답, B→A 관계, 최종 안전 경로는 주지 않는다. 응답은 `relation_status` (`supported`·`unsupported`·`insufficient`)와 `evidence_clause_index` 두 필드뿐이다. 앞의 두 상태는 근거 문장 번호가 필수이고, `insufficient`는 불확실성이 명시된 문장이 없으면 `null`을 허용한다.

검증기는 정확한 필드·enum·문장 번호 범위·일관성만 확인한다. **근거 문장 번호의 존재는 그 문장이 E→B 관계를 뒷받침한다는 뜻이 아니다.** 의미 정답은 [사용자 검토표](nlu_safety_eb_pair_relation_v12_review.md)에 따로 둔다. 모델이 관계 상태를 틀리거나 근거 문장을 잘못 고르면 출력 계약이 통과해도 의미 오류다.

세 상태는 실무상 다른 위험을 분리한다. `unsupported`는 제시한 구절이 현상 또는 잘못된 범위인 경우이고, `insufficient`는 가능한 주체가 있어도 출처를 확인하지 못한 경우다. 둘 다 서비스 안전 분기에서 자동으로 `other`나 안전 이상 없음으로 전환해서는 안 된다. 현재 안전 가드를 유지한다.

## 개발 관문과 다음 단계

사용자가 네 쌍의 상태와 근거 문장을 확정하면, 같은 Q5 파일·컨테이너 이미지와 요청 정책을 대상으로 코드·입력·모델 해시, 응답 스키마, 실제 요청 바이트·토큰 수, 호출 순서, 오류 시 중단·재시도 금지, 비공개 원시 응답 위치를 **생성 호출 전 별도 커밋**에 고정한다. 네 쌍은 PC01/P014 → PC01/P016 → NC01/P020 → NC01/P002 순서로 각 1회다. 다음 지표를 따로 보고한다.

| 항목 | 개발 관문 분모 |
| --- | ---: |
| 전송·길이·출력 계약 오류 | 4호출 |
| 정확한 세 상태 분류 | 검수 후 확정한 4쌍 |
| 근거 문장 번호 일치 | 검수 후 확정한 4쌍 중 번호가 있는 쌍 |
| 양성 후보 거절 | `supported` 정답 쌍 |
| 현상 후보 잘못 승인 | `unsupported` 정답 쌍 |
| 출처 불명 후보 잘못 승인 | `insufficient` 정답 쌍 |

관문은 **계약 오류 0건, 네 상태 모두 일치, 비공란 근거 문장 번호 모두 일치**로 제안한다. 실패하면 전체 후보 재순위화나 서비스 연결로 확대하지 않는다. 이 시험은 후보를 **오라클로 고정한** 관계 판단이므로 v10의 후보 선택 점수와 직접 비교하거나 개선율을 계산할 수 없다. 후보별 판단을 거쳐 최종 B를 선택하는 단계도 아직 없다. 개발 관문을 통과해도 모델의 자기 검증 오류와 노출 편향은 남는다. 이후 새 미노출 사례에서 후보 선택·관계 판단·보류를 함께 평가해야 한다. 이슈 #93의 B→A·안전 경로 완료 조건은 별도다. TX·GB는 사용하지 않는다.
