- 2026-11-11, 로컬 Kanana Q5 모델을 고정된 Docker 이미지와 요청 설정으로 실행했다. 실험 전 입력·코드·프로토콜을 커밋 `449101e`에 고정했다.
- 이미 모델에 노출된 AI 작성·사용자 검수 RE/V 사례 중 위험 발생 상태가 `observed` 또는 `uncertain`인 24건만 호출했다. `nonoccurring` 8건은 제외했다.
- 각 요청에 검수된 접수 대상과 위험 사건의 원문 구간, 기존 정답의 문장 번호와 발생 상태를 제공하고, 모델에는 두 구간의 출처 관계 `current`·`other`·`unknown`만 물었다. 실제 서비스에서 이 정답 단서를 얻는 과정은 평가하지 않았다.

- 프로토콜 SHA-256: `a13bd9595144af3df2971e8c703e59f387a893d392a8479c9b77c8ec3050dc92`; 결과 저널 SHA-256: `43a36bb4bc9ec91d5bd6fa488304594be8137e1dfee7bc78cdd97f920714b0e2`. 저널 49행은 헤더 1행과 24건의 시작·종료 기록이다. 프롬프트, 발화, 원문 구간, 모델 응답 본문은 저장하지 않았다.

## 해석과 다음 판단

정답 단서와 원문 구간을 제공해도, 다른 제품·출처 불명 8건의 관계를 모두 `current`로 과잉 선택했다. 그중 발생이 관찰된 6건은 즉시 보호 경로로 오분기했고, 불확실한 2건은 확인 경로로 갔다. 따라서 이 후보를 서비스 안전 경로에 연결할 근거가 없다. 다음 개발은 접수 대상 식별과 위험 사건의 소유·출처 연결을 각각 관찰 가능한 중간 결과로 분리하고, 다른 제품은 일반 경로로, 출처 불명은 확인 경로로 남기는 설계를 비교해야 한다. 새 설계는 개발 사례에서 원인을 확인한 뒤 코드와 기준을 고정하고, 아직 노출되지 않은 사례에서 별도로 검증한다.

이 수치는 **이미 노출된 AI 작성 사례의 정답 단서 제공 진단**이다. 과거 단계별 후보와 입력 조건 및 V04 해석이 달라 직접 비교할 수 없다. 전체 NLU 정확도, 개선율, 실서비스 안전 성능, 통계적 일반화의 근거로 사용하지 않는다.
