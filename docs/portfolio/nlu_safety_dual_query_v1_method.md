# A/S 위험 출처 양방향 질문 개발 진단 설계

> 모델 실행 전 방법 기록. 이미 모델과 개발 과정에 노출된 AI 작성·사용자 검수 ES 자료의 **주체 오라클 진단**이다. 새 일반화 정확도나 서비스 안전성을 측정하지 않는다. TX·GB 봉인 사례와 이미 평가한 IT·SS 사례는 후보 선택·모델 호출에 사용하지 않는다.

## 반증할 가설

기존 관계 전용 진단에서 같은 사건의 관계 답은 정의 순서를 바꾸자 18건 중 12건에서 달라졌다. `current`를 먼저 설명하면 관찰된 현재 제품 위험 8/8을 맞혔지만 다른 출처는 2/9였고, 역순에서는 각각 4/8과 9/9였다. 단일 3지선다의 전체 정답 수만으로 안전 경로를 고르면 한쪽 위험을 가릴 수 있다.

이번에는 검수된 위험 사건 E와 발생 주체 B를 제공한 **같은 사건**에 독립적인 두 질문을 한 번씩 한다. 첫 질문은 B가 접수 대상 A 자체·그 부위·전용 구성품·명확한 지시 대상인지, 둘째는 B가 A와 명시적으로 별개인 물건인지 묻는다. 각 응답은 `yes|no|unknown` 단일 필드 JSON이다. 두 응답은 서로에게 전달하지 않고 정답 관계나 안전 경로도 제공하지 않는다. 이 분해가 선택지 순서 쏠림을 줄이는지, 모순 또는 불확실 답을 안전 확인으로 보낼 때 어느 범주의 직접 위험을 놓치는지 확인한다. 같은 Q5가 두 번 답하므로 질문이 독립적이어도 **오류의 통계적 독립성은 가정하지 않는다.**

| 현재 제품 질문 | 별개 제품 질문 | 합성 관계 |
| --- | --- | --- |
| `yes` | `no` | `current` |
| `no` | `yes` | `other` |
| 그 외 모든 조합 | 그 외 모든 조합 | `unknown` |

계약·전송 오류가 하나라도 나면 해당 사건을 `unknown`으로 처리한다. `unknown`은 안전 상태 확인 경로이지 위험 부재의 확정이 아니다. 이 보류 규칙은 잘못된 직접 경고를 줄일 수 있지만, 실제 현재 제품 위험을 즉시 보호하지 못하게 할 수 있어 **보류율과 직접 위험 누락을 동시에** 평가한다.

## 입력과 실행 경계

- 기존 ES 20사례·22검수 사건 가운데 미발생 3사건과 주체 B가 공란인 ES17의 1사건을 제외한 **18사건/17사례**를 사용한다. 정답 범주는 관찰된 현재 제품 위험 8건, 발생 불확실한 현재 제품 위험 1건, 관찰된 다른 출처 위험 9건이다. 정답 관계는 `current` 9건·`other` 9건이다. 정답 `unknown`이 없으므로 미확정 출처 인식률은 측정하지 못한다.
- 검수된 원문·접수 대상 A·사건 E·주체 B·발생 상태만 두 질문에 제공한다. B 제공은 실제 추출 실패를 제거한 **유리한 오라클 조건**이다. 검수 관계·기대 경로와 이전 모델 출력은 채점에만 사용한다. ES17을 공란 B와 함께 보내면 정답 `unknown`이 입력에서 새어 나올 수 있어 제외한다.
- 사건마다 두 질문을 각각 한 번 호출한다. 사건별 질문 순서를 번갈아 배정해 총 **36회 계획 호출**의 앞뒤 순서를 균형 있게 한다. 한 응답이 실패해도 다른 질문을 한 번 호출하고, 재시도하지 않는다. 정확한 사건·질문 순서는 실행 전 프로토콜에 고정한다.
- 기존 관계 정의 순서 실험과 동일한 로컬 Kanana Q5 파일·llama.cpp 이미지·CPU 2개·메모리 4GiB·컨텍스트 4096·스레드 2개·동시 처리 1개·온도 0·요청 정책을 사용한다. 모델·이미지·코드·입력·저장 정책의 해시와 권한을 모델 호출 전에 고정한다. 실제 비공개 저장 경로는 실행 인수로 지정한다. 공개 저널에는 프롬프트나 원시 응답 본문 대신 해시·길이·유한 오류 코드를 남긴다. 원시 응답은 저장소 밖 소유자 전용 폴더 `0700`, 파일 `0600`으로 보존한다.

## 사전 지표와 안전 문턱

독립 검증기는 고정된 원문·정답과 비공개 원시 응답에서 순서·호출·해시·계약·두 질문의 출력·합성 관계·경로·지연을 재계산한다. 전체 관계 정답뿐 아니라 범주별 **관찰 현재 8건, 불확실 현재 1건, 관찰 다른 출처 9건**, 질문별 `yes/no/unknown` 분포, 모순·보류 사건 수, 관계 확정률과 확정된 관계의 정답률을 함께 보고한다. 확정된 관계의 정답률은 보류 사건을 분모에서 제외한다는 점을 명시하고, 전체 18건 정답과 혼용하지 않는다.

사건별 현재 위험을 `other`나 `unknown`으로 보낸 수, 다른 출처를 `current`로 보낸 수를 별도 집계한다. 검수된 발생 상태와 합성 관계를 사용한 **조건부** 사례 경로를 17사례에서 계산하고, 현재 위험의 안전 우선 누락·현재 위험이 없는 사례의 직접 오경고·ES01/09 및 ES02/11 대비쌍 양쪽 정답을 기록한다. ES06처럼 두 사건이 있는 사례에서는 사건별 오판이 사례 경로 정답에 가려질 수 있으므로 사건 지표를 우선한다. 질문별 호출 지연과 사건당 두 호출의 합계, 사례별 지연의 중앙값·95백분위를 구분한다. 모델 로드 시간과 실제 서비스 종단 간 지연은 포함하지 않는다.

개발 관문은 **관찰 현재 관계 8/8, 불확실 현재 관계 1/1, 관찰 다른 출처 관계 9/9, 모델 관여 사례의 조건부 경로 17/17, 대비쌍 2/2, 계약·전송 오류 0/36**을 모두 요구한다. 보류를 정답처럼 계산하지 않는다. 하나라도 미달하면 후보를 서비스 안전 분기에 연결하지 않는다. 통과하더라도 A/E/B가 정답으로 주어진 기노출 개발 자료이므로 배포 결론을 내리지 않는다.

## 해석과 다음 경계

기존 관계 정의 순서 결과와 같은 ES 사건을 사용하므로 사건별 정오 변화를 **개발용 짝 진단**으로 표기할 수 있다. 그러나 질문 수·프롬프트·출력 계약·보류 규칙이 동시에 달라져 점수 차이를 한 기법의 인과적 개선율이나 공식 정확도 개선율로 쓰지 않는다. 이번 후보가 개발 관문을 통과해야 완전히 새로운 발화와 모든 의미·원문 구간 정답을 사용자 검수·동결하고, 그 뒤 미노출 평가를 한 번 실행한다. 그 평가 전까지 현재 서비스의 안전 가드를 유지한다.
