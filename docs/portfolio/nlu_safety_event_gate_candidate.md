# A/S 안전 근거의 실제 발생 검증 후보

## 설계 근거

Kanana Q5 원문 구간 선택 진단은 출력 계약을 32/32건 통과했지만, 모호한 발화 8건 중 2건과 현재 제품의 위험 진술이 없는 12건 중 6건을 즉시 위험으로 분류했다. 특히 CF26·31·32에서는 모델이 선택한 근거 문장에 실제 위험 현상 자체가 없었다. 따라서 **모델의 즉시 위험 분류만으로 서버 상태를 전이하지 않고, 선택된 원문 문장에서 실제 발생 표현을 다시 확인하는 게이트**를 개발 후보로 만든다.

게이트는 모델이 `safety_action_required`를 반환한 경우에만 작동한다. 서버가 번호를 부여한 원문 구간에서 관찰된 위험 사건을 찾으면 즉시 대응을 유지한다. 질문·가정·명시적 부정·화면 표시만 있으면 일반 수집으로, 불확실한 관찰이나 사건 근거가 부족하면 안전 확인으로 보낸다. 즉시 대응이 아닌 모델 결과는 승격하지 않는다. 이 코드는 서비스 그래프에 연결하지 않았고 추가 모델 호출도 하지 않는다.

## 노출 사례 개발 점검

이 규칙은 개발자가 CF01–CF32와 Q5 결과를 본 뒤 작성했다. 아래 숫자는 **과적합을 확인하는 회귀 점검**이며 새 성능 수치나 공식 정확도 개선율이 아니다.

| 기존 검수 구간 | 원래 Q5 즉시/확인/일반 | 게이트 후 즉시/확인/일반 |
| --- | --- | --- |
| 실제 위험 12건 | 10 / 0 / 2 | 10 / 0 / 2 |
| 위험 여부 모호 8건 | 2 / 4 / 2 | 0 / 6 / 2 |
| 현재 제품 위험 진술 없음 12건 | 6 / 1 / 5 | 0 / 4 / 8 |

즉시 대응이 보류된 8건은 CF14·20·21·23·26·29·31·32다. 위험 진술이 없는 사례 중 네 건은 여전히 확인 질문으로 이어진다. 또한 이 게이트는 **근거 문장에 발생 표현이 있는지**만 확인한다. 그 문장이 현재 A/S 대상 제품에 관한 것인지는 모델의 `target` 판단에 의존하므로, 다른 제품의 실제 위험을 현재 제품의 위험으로 잘못 연결할 가능성이 남는다. 지원하지 않는 표현의 실제 위험은 확인으로 지연될 수 있고, 기존 Q5가 놓친 CF05·08 같은 위험을 새로 찾아내지도 못한다.

## 다음 검증 경계

코드가 고정된 다음, 모델에 아직 실행하지 않은 AI 작성 발화에서 **현재 대상·위험 출처·실제 발생·불확실성·부정/가정**을 사례별로 검수해야 한다. 모델 출력 형식, 즉시 보호, 확인 질문, 일반 진행, 위험 누락, 불필요한 확인을 각각 분모와 함께 보고한다. 새 사례도 AI 작성·1인 검수이므로 표적 탐색 평가로만 표기한다. 특히 다른 제품의 실제 위험이 현재 제품의 위험으로 연결되는지를 별도 실패 조건으로 둔다. 후보가 이 조건을 통과하기 전에는 서비스에 적용하지 않는다.
