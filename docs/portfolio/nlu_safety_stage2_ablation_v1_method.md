# A/S 위험 출처 2단계 조건 분리 개발 진단 설계

> 2026-11-15 모델 실행 전 계획. ES01–ES20은 이미 v4와 위험 사건 오라클 진단에 사용한 AI 작성·사용자 검수 개발 자료다. TX·GB 봉인 자료는 후보 선택과 모델 호출에 사용하지 않는다.

## 질문과 조건

직전 위험 사건 오라클 진단은 검수된 위험 사건·발생 상태를 제공했는데도 출처 관계 7/19, 주체 인용 엄격 일치 0/19, 최종 경로 8/20이었다. 유효 응답 18건 중 7건은 사건과 다른 문장을 주체 근거로 인용했고, 사건 문장을 인용하고도 관계를 틀린 사례가 있었다. 아래 두 조건을 **각각 기존 공동 출력 조건과 비교**해 실패 경계를 분리한다. 두 조건의 결과끼리 우열을 주장하지 않는다.

1. **R: 관계 전용 출력.** 원문, 검수된 접수 대상 A, 검수된 사건 구절·발생 상태는 이전 진단과 같다. 위험 주체 인용 출력 필드만 제거하고 `owner_to_target` 하나를 `current|other|unknown`으로 출력한다. 사전 검수 주체·관계·경로 정답은 전달하지 않는다. `observed|uncertain` 사건 19개를 한 번씩 호출한다. 인용 생성 부담의 제거와 관계 판단 결과가 함께 변하므로 차이를 그 한 요소만의 인과 효과로 단정하지 않는다.
2. **O: 주체 구절 오라클 입력.** 기존 2단계 공동 출력 계약을 유지하고, 위 입력에 검수된 위험 주체의 원문 구절·문장 번호만 추가한다. 관계·경로 코드를 직접 전달하지 않는다. 다만 검수 주체 구절 자체가 관계를 강하게 암시할 수 있으므로 이 조건은 독립적인 관계 성능이 아니다. 주체 구절이 있는 사건 18개를 한 번씩 호출한다. 검수 주체가 공란인 ES17은 `unknown` 정답이 입력 공란으로 누출될 수 있어 호출·관계 점수에서 제외하고, 이 한계를 별도 보고한다. O의 주체 인용 일치는 정답 구절을 입력한 조건의 결과이므로 주체 추출 성능으로 해석하지 않는다.

두 조건 모두 `nonoccurring` 사건 3개는 모델에 보내지 않는다. 요청은 같은 로컬 Kanana Q5 파일·llama.cpp 이미지·CPU 2개·메모리 4GiB·컨텍스트 4096·스레드 2개·동시 처리 1개·온도 0·최대 320토큰·재시도 없음으로 고정한다. R 19회와 O 18회는 순서대로 한 번 실행한다. 오류는 재시도하지 않고 기존 안전 확인 경로로 처리한다. O의 ES17은 모델 판단 경로 점수에서도 제외한다.

## 사전 지표와 판정

R 관계 분모는 관찰된 현재 제품 8, 관찰된 다른 출처 9, 관찰됐으나 출처 불명 1, 발생 불확실한 현재 제품 1로 총 19다. O는 출처 불명 1개를 제외한 18개다. 각 조건에서 전체·범주별 관계, 현재 위험 안전 우선 누락, 다른 출처의 직접 오경고, ES01/09·ES02/11 대비쌍, 계약·전송 오류, 최종 경로를 별도 기록한다. 관계 비교는 **같은 18개 사건의 기존 조건을 다시 집계한 분모**도 제시하고, R에만 포함되는 ES17은 별도 표시한다. R의 모델 관여 경로 분모는 18사례, O는 17사례다. 무호출 사례의 결정적 경로는 모델 성능에서 제외한다. 요청 지연과 사례 지연을 구분해 중앙값과 95백분위를 기록한다.

개발 후보의 안전 문턱은 R에서 현재 위험 8/8, 다른 출처 9/9, 출처 불명 1/1, 불확실 현재 1/1, 모델 관여 경로 18/18, 대비쌍 2/2, 오류 0/19다. O는 공란 제외 세 범주 8/8·9/9·1/1, 모델 관여 경로 17/17, 대비쌍 2/2, 오류 0/18을 요구한다. 대비쌍은 양쪽 모든 호출 대상 관계와 두 경로가 모두 맞을 때 한 쌍으로 센다. 하나라도 미달하면 후보를 서비스 안전 분기에 연결하지 않는다. 문턱을 통과해도 이미 노출된 AI 작성 사례이므로 배포 또는 공식 정확도 근거가 아니다.

## 재현과 경계

코드·검수 입력·직전 진단의 프로토콜·저널·검증 결과·모델·새 검증기를 실행 전 해시로 고정하고, 새 프로토콜을 별도 커밋한 뒤 실행한다. 직전 진단의 저장소 밖 원시 응답은 실행 전 독립 검증기로 파일 목록·해시·권한까지 다시 확인한다. R/O 요청에 직전 모델의 예측 주체·관계·경로가 들어가지 않는지도 테스트한다. 새 원시 응답은 저장소 밖 0700 폴더·0600 파일로 보존한다. 공개 저널에는 원문·프롬프트·원시 본문 대신 해시·길이·구간 위치·관계 코드·유한 오류와 집계만 남기고 독립 검증기가 재계산한다. 두 새 조건의 결과와 기존 결과는 조건부 개발 진단이다. 공식 전체 정확도·일반화 성능·인과적 개선율로 표현하지 않는다. 이후 후보를 고르면 새 발화와 필드 정답을 모델 실행 전에 별도 검수·고정해야 한다.
