# A/S 명시 출처 기준선 대조쌍 결과

[검토표](nlu_safety_explicit_source_pair_review.md)의 EP01–EP08을 사용자 검수로 채택했다. EP05의 지시어는 전원 어댑터, EP06의 작업대와 EP07의 방 안은 관찰 장소로 확정했다. [정답 JSON](../../evals/structured_nlu/data/ai_heldout/as-safety-explicit-source-ep-reviewed.v1.json)과 채점 코드는 평가 전 커밋 `b08c371`에 고정했다. 동일한 발화에서 고정한 사건에 후보 두 개를 대입했다. 정답은 예측 후 채점에만 사용했다.

| 지표 | 결과 |
| --- | ---: |
| 실제 출처 승인 | 3/6 |
| 실제 출처 누락 | 3/6 |
| 근거 없는 후보 오승인 | 2/10 |
| 올바른 보류 | 8/10 |
| 양성·음성을 모두 맞힌 발화 | 3/6 |
| 두 후보 모두 올바르게 보류한 발화 | 1/2 |
| 원문 앵커·기준선 입력 오류 | 0/16 |

- **누락 EP04:** 시간절 뒤의 충전 단자가 출처다. 기준선은 후보가 문장 맨 앞에 있어야 해서 보류했다.
- **누락 EP05:** `그 장치`의 선행사는 전원 어댑터다. 기준선은 다른 문장에 있는 선행사를 보류했다.
- **누락 EP06:** 변화가 일어난 대상은 배터리 팩이다. 후보 구절이 사건 E 내부에 있어 출처 조사 앞에 있는 구절을 찾는 기준에서 보류됐다.
- **오승인 EP06·EP07:** 작업대와 방 안은 관찰 장소다. `장소 + 에서 + 사건` 형태가 맞아 실제 출처로 승인됐다. 특히 EP07은 후속 문장에서 출처 미확인을 명시한다.

기존 두 개발 발화에서는 부정 후보를 모두 보류했지만, 이번 대조쌍에서 **명시 조사만으로는 장소와 물리 출처를 구분할 수 없었다.** 다음 후보를 평가할 때는 사건 술어에서 실제로 변화한 대상과 관찰 장소를 분리하는 판단을 개발 사례에서 먼저 검증한다. 이 묶음은 AI 작성·사용자 검수의 오프라인 표본이며, 사건과 후보를 미리 원문에 연결했다. 이 결과로 서비스 전체 정확도나 안전 경로 개선을 주장할 수 없다.

[결과 JSON](../../evals/structured_nlu/results/as-safety-explicit-source-ep-evaluation.v1.json)은 후보별 판단, 원문 구간과 집계수를 기록한다. 입력 SHA-256은 `46cb2a0aed2e78c0a34b6e89dfadad10341d2e5eee6f460d0c87eb5afa3a4823`이다. Kiwi 라이브러리 0.23.2 및 사전 모델 0.23.0에서 `python -m experiments.as_safety_explicit_source_evaluation`로 재현한다.
