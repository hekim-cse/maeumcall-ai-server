# A/S 위험 사건·출처 v4 개발 실험 설계

> 2026-11-14 평가 전에 작성한 설계 기록이다. 작성 당시 새 사례의 문장과 정답은 검수 전이었고, 2026-11-15 모델 실행 **전에** 사용자가 [문장·방향](nlu_safety_event_source_v4_review.md)과 [전체 필드](nlu_safety_event_source_v4_field_review.md)를 탐색용으로 채택했다. 채택은 모델 결과를 근거로 하지 않는다. 이후 [탐색 평가](nlu_safety_event_source_v4_exploration_result.md)는 사전 게이트에 실패했다. 아래 기준은 결과가 아니다. TX·GB 봉인 자료는 후보 설계와 조정에 사용하지 않는다.

## 왜 사건을 먼저 열거하는가

[v3 조건부 진단](nlu_safety_owner_link_v3_development_result.md)은 같은 1단계 통과 20건에서 관계 일치 6/20→15/20을 기록했지만, 다른 제품 위험 일치는 6/6→2/6으로 악화돼 사전 안전 게이트에 실패했다. RE09·RE10·RE11·V08에서 기존 1단계는 별도 제품 위험보다 접수 제품의 일반 고장·수리 질문을 위험 사건 후보로 골랐다. RE04에서는 연무를 물리적 주체로 골라 앞 문장의 제품 부위와 연결하지 못했다. 이는 기록된 출력의 오류 양상이지 모델 내부 원인의 증명은 아니다. 단일 E/B 후보에 의존하는 2단계만 조정하면 잘못 선택된 입력을 복구하기 어렵다.

## 후보 계약

1. 검수된 접수 대상 A와 원문을 받아 위험 사건을 최대 3개 나열한다. 각 사건은 원문 인용 구간과 발생 상태 `observed`·`uncertain`·`nonoccurring`을 갖는다. 일반 고장·수리 질문은 위험 사건으로 세지 않는다. 3개를 초과하면 임의 절단 대신 `overflow`를 표시해 확인 경로로 보낸다.
2. 관찰되었거나 불확실한 사건마다 원문 전체, A, 해당 사건 하나만 전달해 위험 발생 물건의 인용 구간과 A와의 관계 `current`·`other`·`unknown`을 판단한다. 앞 단계의 주체·소속 대상 후보나 정답 관계를 전달하지 않는다. 인용이 원문에 있는지는 기계적으로 검증하지만, 의미상 올바른지는 검수 정답과 별도로 비교한다.
3. 관찰된 현재 제품 위험이 하나라도 있으면 안전 우선이다. 그 외 출처 불명, 현재 제품에 속할 수 있는 발생 불확실성, 계약·전송 오류 또는 초과가 있으면 안전 상태를 확인한다. 다른 제품에 속한다고 확인된 위험만 남으면 일반 접수로 분기한다. 안전 우선 사건과 오류가 함께 있어도 이미 확인한 위험을 누락하지 않는다.

이 설계는 모델 호출이 사건 수에 따라 늘 수 있다. 따라서 점수와 함께 호출 수, 종단 간 지연 중앙값·95백분위, 계약 오류를 측정한다. 첫 단계 최대 3개가 새 사례에 충분한지는 모델 실행 전에 정적 검수한다.

## 비교 및 실패 기준

기존 RE/V 22건은 개발 진단용이다. 같은 사례에 대해 사건 검출 누락·과검출, 발생 상태, 사건별 출처 관계, 최종 경로, 다른 제품 위험의 잘못된 직접 경고, 현재 제품 위험의 직접 경고 누락을 각각 기록한다. 관계 점수의 분모는 모든 사례와 유효한 단계별 응답을 분리해 제시한다. 기존 v3의 조건부 20건과 새 v4 전체 22건을 같은 분모의 개선율로 비교하지 않는다.

개발용 통과 기준은 현재 제품 관계 15/16 이상, 관찰된 현재 제품 위험 즉시 보호 13/13, 다른 제품 관계 6/6, 사전 정의된 대비쌍 3/3, 계약·전송 오류 0/22이다. 출처 불명은 확인 경로여야 한다. 하나라도 실패하면 실서비스 안전 분기를 바꾸지 않는다. 이 기준은 노출된 개발 사례의 실패를 걸러내는 조건일 뿐 일반화 성능 보증은 아니다.

코드·프롬프트·모델·검증기와 입력 해시를 먼저 고정한다. 그 뒤 사용자 검수 완료된 [새 ES01–ES20](nlu_safety_event_source_v4_review.md)으로 별도 탐색 평가를 한다. 이 자료의 20개 발화·22개 사건과 [전체 필드 정답](nlu_safety_event_source_v4_field_review.md)은 2026-11-15에 탐색용으로 채택됐다. 사전 탐색 게이트는 현재 제품 위험 8/8 안전 우선, 다른 제품 위험 8/8 일반 접수, 출처·발생 불확실 2/2 확인, 위험 미발생 2/2 일반 접수, ES01/09·ES02/11 대비쌍 2/2, 계약·전송 오류 0건이다. 사건 누락·과검출과 사건별 관계는 이 경로 게이트와 별개로 모두 보고한다. 하나라도 실패하면 서비스 안전 분기에 연결하지 않는다. 게이트가 모두 통과해도 AI 작성 사례이므로 공식 전체 정확도 개선율이나 일반화 성능으로 쓰지 않는다. 원시 모델 응답은 저장소 밖에 접근 제한하여 보존하고, 공개 저널에는 해시·길이·유한한 오류 코드와 집계만 남긴다. 독립 검증기가 원시 응답과 원문 구간, 경로를 재계산해야 한다.
