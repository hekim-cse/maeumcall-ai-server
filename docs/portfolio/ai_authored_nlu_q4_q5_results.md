# AI 작성·사람 검수 NLU 32건의 Q4·Q5 비교

## 측정 범위와 결과

발화는 AI가 작성하고 사용자가 문장과 모든 정답 필드를 검수했다. 16개 상세
업무마다 시작 상태(`greeting`)의 정보 제공 1건과 범위 밖 요청 1건을 고정했다.
한 사례의 `intent`, `user_action`, `change_field`, 모든 업무 필드와 라이브
출력 계약이 함께 맞아야 전체 일치 1건이다. 분모 32건은 반복 호출 수가 아니다.

| 지표 | Q4_K_M | Q5_K_M |
| --- | ---: | ---: |
| 전체 일치 | 1/32 (3.125%) | 1/32 (3.125%) |
| 첫 시도 계약 통과 | 17/32 | 23/32 |
| 재시도 후 계약 통과 | 26/32 | 26/32 |
| 재시도한 사례 | 15/32 | 9/32 |
| `intent` 일치 | 26/32 | 26/32 |
| `user_action` 일치 | 16/32 | 16/32 |

전체 일치 차이는 **0.0%p**다. 양쪽 모두 AH27만 전체 일치였으며, Q4만
맞힌 사례와 Q5만 맞힌 사례는 각각 0건이다. 따라서 이 평가에서 Q5의
전체 정확도 개선은 관찰되지 않았다. 첫 시도 계약 통과 차이는 부차 지표이며
재시도 후 계약 통과율과 전체 일치율은 같다.

## 실패 원인

- 정보 제공 16건에서는 두 모델 모두 계약을 통과하고 행동 코드를 맞혔다.
  하지만 전체 일치는 각 1건이었다. 필드 누락·추가, 값 정규화 차이와
  의미 판단 오류가 섞여 있다. 예를 들어 AH11은 정답 시간 `오전`에 대해
  두 모델 모두 근거 없는 구체 시각 `오전 10시`를 냈다. AH13은 이동 기록
  정지와 지연 이유 질문을 놓쳤고, AH15는 새 위치 `회사 후문` 대신 이전
  위치부터 새 위치까지의 문구를 출력했다.
- 범위 밖 요청 16건에서는 두 모델 모두 `unknown` 행동을 한 번도 맞히지
  못했다. 각 모델에서 10건은 계약을 통과했지만 다른 행동을 냈고, 6건은
  재시도 후에도 계약에 실패했다. 이 발화의 자연어 요청 의미는
  [필드 검수표](ai_authored_nlu_field_review.md)에 별도로 기록돼 있다.

필드 존재·값 지표는 계약을 통과한 사례에 대해서만 계산하므로 조건별
분모가 달라질 수 있다. 이 결과만으로 필드 지표의 쌍별 우위를 주장하지 않는다.

  정상 재실행은 두 서버가 끝까지 살아 있었고 두 예측 파일에 전송 오류가
  없었다. 종료 후 두 컨테이너를 중지하고 Docker 한도를 8GB로 복구했다.
  [Q4 예측](../../evals/structured_nlu/results/ai-heldout-q4-v1.json)과
  [Q5 예측](../../evals/structured_nlu/results/ai-heldout-q5-v1.json)은
  정규화된 출력·계약 오류·요청 지연시간을 보존한다.
- 리뷰 이후 채점·실행 코드의 안전 검사를 보강했다. 원래 요청 정책의
  `runner_sha256`과 프롬프트 소스 지문은 변경하지 않았다. 따라서 이 평가를
  재채점할 때는 예측이 커밋된 `16f227f`의 소스와 전체 Git 이력을 사용한다.
  해당 커밋의 별도 작업 폴더에서 다시 채점해 `1/32`, `1/32`, `0.0%p`를 확인했다.
  새 소스에서 같은 노출 기록을 재사용한 실행은 지문 검증에 막힌다. PR은
  입력→동결→노출→예측 커밋 순서를 보존하는 merge commit으로 병합해야 한다.
- 유효한 쌍 평가 실행은 1회다. 실행 간 변동, 토큰 수, 모델 응답 원문은
  측정·보존하지 않았다. 검수자는 포트폴리오 소유자 한 명이다. 발화의
  작성 출처는 검수 이후에도 AI이며, 사람 작성 독립 평가셋의 성적이 아니다.
  16개 업무의 후속 상태와 실제 사용자 발화 분포를 포함하지 않으므로
  서비스 전체 정확도로 일반화할 수 없다.

포트폴리오에는 **“AI 작성·사람 검수 32건 고정 평가에서 Q4와 Q5 모두
전체 일치 1/32(3.125%), 차이 0.0%p. 범위 밖 요청 16건에서 두 모델 모두
`unknown` 0건으로 계약 경계 실패를 확인했다”**라고 적을 수 있다.
정확도 개선 성과로 쓰려면 이 실패 원인을 고친 새 버전을 사전 고정한 독립
평가셋으로 다시 비교해야 한다.
