# A/S 위험 주체 후보 경계 오프라인 감사 방법

> 2026-11-22. 기존 AI 작성·사용자 검수 개발 사례를 재분석한다. 모델 호출, 서비스 코드 변경, 공식 정확도 평가가 아니다.

## 판단 근거와 질문

[v7 개발 진단](nlu_safety_eb_candidate_order_v7_development_result.md)의 PC01에는 정답 원문 구절 `선풍기 모터`(P014)가 있었지만, 모델은 조사 포함 구절 P013과 사건까지 포함한 P022를 각각 선택했다. 따라서 후보 **가용성**과 모델의 **경계 선택**을 분리해 본다. 가장 짧은 후보를 택하면 `선풍기`나 `모터` 같은 다른 오답이 남으므로 길이만으로 자르지 않는다. NC01은 냄새 발생이 관찰됐어도 물리적 출처는 불명이다. 명사 후보가 있다는 사실만으로 출처를 확정해서도 안 된다.

질문은 원문에서만 계산한 형태소 경계가 기존 후보 중 조사·서술어가 섞인 긴 구절을 줄이면서, 이미 검수된 정확한 주체 구절을 얼마나 보존하는가이다. 이 단계는 모델이 남은 후보에서 정답을 선택할지 평가하지 않는다.

## 입력·조건

- 원문과 검수 정답은 기존 PC01·NC01 및 RE/V의 공개 개발 자료를 사용한다. PC/NC는 v5 검수 사례, RE/V 원문은 각각 관계 검수 자료, 주체 구절은 주체 근거 검수 자료에서 읽는다. 원문 파일에는 34건이 있으나 주체 구절 검수 라벨이 있는 **26건만 집계**하며, 나머지 8건에는 정답 포함률을 매기지 않는다. 이 자료는 이미 여러 개발 실험에 노출됐다. TX·GB 봉인 자료는 감사 입력과 집계에서 제외한다.
- 기준선은 현재 `source_lattice.py`의 5토큰·최대 192개 후보 전체다. 형태소 도구는 저장소에 고정된 `kiwipiepy==0.23.2`를 사용한다. Kanana Q5나 외부 서비스는 호출하지 않는다.
- 조건 N은 **후보의 끝**이 원문 위치의 명사류 형태소 끝과 일치하는 후보만 남긴다. 조건 C는 N 중에서 구절 내부가 명사·관형사·소유격 조사처럼 연속 명사구를 만드는 형태소로만 구성된 후보를 남긴다. 두 조건 모두 기존 후보의 ID·원문 위치·문자열을 바꾸지 않는다. PC/NC 원문과 정답은 같은 파일에 있지만 후보 생성 함수에는 원문 문자열만 전달하며, 정답 구절·관계 라벨은 필터에 전달하지 않고 사후 대조에만 사용한다.
- 후보의 종료 위치는 원문 구절 단위로 검증한다. Kiwi 분석이 틀리거나 복합어·대명사·수식절을 다르게 쪼개면 정확한 구절도 빠질 수 있으므로 필터의 탈락 사례를 모두 기록한다.

## 기록과 다음 관문

사례별로 기준선·N·C 후보 수, 정확한 검수 주체 구절의 포함 여부와 ID를 기록한다. 정답이 공란인 NC01·RE07·V09는 별도 집계해 **후보가 남는 것과 보류 성공은 다르다**고 명시한다. 입력 파일 해시·도구 버전과 집계 코드를 함께 남긴다. 기존 정답이 당시 후보에 없던 사례는 필터에 의한 추가 손실과 구분한다.

다음 소규모 실모델 진단의 후보를 고르는 보수적 기준은 다음과 같다. PC01의 P013·P022는 제외되고 P014는 남아야 하며, 기준선이 포함한 다른 양성 검수 구절을 새 필터가 하나라도 잃으면 그 필터를 단독 강제 후보 집합으로 채택하지 않는다. 후보 수 감소는 그 자체로 정확도 향상이 아니다. 조건을 만족해도 새 모델 호출 전 방법·코드·요청·순서·검증 기준을 별도 프로토콜로 고정하고, 출처 불명 보류를 양성과 함께 검사한다. 서비스 연결과 공식 개선율은 별도 미노출 평가 뒤에만 판단한다.
