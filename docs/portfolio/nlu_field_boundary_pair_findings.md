# NLU 필드 경계 후보의 로컬 Q5 탐색 비교

2026-11-05에 이전 탐색에서 실패한 F15·F17·F23·F29와 사용자 검수로
희망 처리 공란을 정한 D05를 다시 실행했다. 모두 모델에 이미 노출된 AI 작성
개발 사례이며, **독립 평가나 공식 정확도 측정이 아니다.** F17은 같은 상품을
다시 받으려는 요청으로, D05는 환불 가능 여부 문의로 구분한 사용자 판단을
유지했다.

변경 전 `26fb642`와 [지시문 후보 패치](../../evals/structured_nlu/candidates/field-boundary-prompt-v1.patch)를
적용한 코드를 같은 로컬 Q5 서버에서 비교했다. 후보는 필드 추출 후 행동 선택,
모든 필드가 공란인 `provide_details`의 모순, 예약일을 정할 수 없는 반복 요일
표현, 재배달 요청과 환불 가능 여부 문의의 구분을 명시했다. 각 조건에서 사례를
두 번 실행했으며 조건 순서는 변경 전→후→후→전, 두 번째 반복의 사례 순서는
역순이었다. 추가로 후보 코드의 배달·시청 네 사례에 `json_object` 출력 스키마
제약을 두 번 실행했다. 요청 설정은 `max_tokens=180`, `temperature=0`,
`repeat_penalty=1.05`, 종료 토큰 `<|eot_id|>`이었다.

| 조건 | 계약 통과 | 행동·모든 필드 초안 일치 |
| --- | ---: | ---: |
| 변경 전, 5건×2회 | 4/10 | 0/10 |
| 지시문 후보, 5건×2회 | 8/10 | 0/10 |
| 지시문 후보+출력 스키마, 업무 4건×2회 | 8/8 | 0/8 |

변경 전 F15·F23은 각각 두 번 모두 `provide_details`를 택하고 필드를 모두
비워 계약에 실패했다. 후보에서는 두 사례가 두 번 모두 계약을 통과했지만
검수한 필드 초안과 달랐다. F17의 `resolution_preference` 누락과 F29의
`date` 불일치는 후보에서도 각각 두 번 모두 남았다. D05는 두 일반 출력 조건에서
계약에 실패했고, 스키마 제약에서는 계약을 통과했지만 `unknown`으로 분류해
검수한 `provide_details` 행동과 달랐다.

원자료는 [실행 보고서](../../evals/structured_nlu/results/exploratory-q5-field-boundary-2026-11-05.json)에
사례 ID별 계약 결과, 불일치 필드 이름, 안전한 출력 형태와 시도별 토큰 수를
저장했다. 발화와 모델 답변 전문은 저장하지 않았다. 실행 당시 스크립트의
[원본 스냅샷](../../evals/structured_nlu/candidates/field-boundary-runner-v1.txt)
SHA-256은 `8f88cd11515ef6c85712c4b9a4dfdfd03c7308f0bde9881a9ca484abf78159e4`다.
[재실행용 스크립트](../../scripts/probe_gguf_field_boundary.py)는 같은 로직을
Ruff 형식으로 정리했다.
F 발화 문서 SHA-256은 `a819c794ba9cc18bb39e722275be0724323268b5c6a7b933fe7cd1a175b9a4d1`,
F 필드 초안은 `4920a9149195022089bc1e2da6e81f00aa3d580a68007e3ab6aee347e84bd0d1`,
D 초안은 `c7151d8051a5fbc857e6246c8e8ea2706314d23ff096ec092d7dc08396948357`다.
변경 전 커밋과 후보 소스 파일의 SHA-256은 보고서에 기록했다. 로컬 모델 파일
`/private/tmp/maeumcall-kanana-q5.gguf`의 SHA-256은 실행 전에
`644b04cde835d486df33c6d4d7552ba367fcb28802fe39b6b4bb9c60b9ab6f3d`로
확인했다. 서버 이미지 digest는
`sha256:17155a3ce4cc906728ec99a2814bf0b4eaffaf3b4872bad8c3affed310cdbc35`다.
서버는 ARM 로컬 Docker에서 CPU 4개·메모리 6GiB·스레드 4개·단일 슬롯·
컨텍스트 4096으로 실행하고 종료했다. 파일 해시 확인과 파일 경로 마운트는
확인했지만, 서버가 실제로 제공한 가중치를 별도 원격 증명하지는 않았다.

**판단:** 계약 통과만 개선됐고 검수한 행동·필드 전체 일치는 개선되지 않았다.
스키마 제약도 D05의 행동을 잘못 바꾸었다. 두 후보 모두 서비스에 적용하지
않고, 지시문 후보는 위 패치로만 보존했다. 다음 실험에서는 필드 값과 발화
근거의 관계를 확인할 수 있는 출력 계약, 특히 날짜의 모호성과 처리 희망의
경계를 다루되, 새 사례로 부작용을 함께 확인해야 한다. 이 다섯 개발 사례의
반복 결과로 일반화·통계적 우월성·운영 성능·정확도 개선율을 주장하지 않는다.
