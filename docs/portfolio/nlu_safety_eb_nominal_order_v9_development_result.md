# A/S 위험 주체 명사 끝 후보·순서 개발 대조 결과

> 2026-11-22. 기노출 PC01·NC01 두 AI 작성·사용자 검수 문장의 소규모 개발 진단이다. [사전 관문](nlu_safety_eb_nominal_order_v9_method.md)은 **실패**했다. 공식 정확도·개선율이나 서비스 안전 성능으로 쓰지 않는다.

## 실행과 검증 범위

- 실행 전 방법·코드·테스트는 커밋 `edfdcd75ecf07d7f8e1417ed9fe111a5fb5c32e9`, [프로토콜](../../evals/structured_nlu/data/ai_heldout/as-safety-eb-nominal-order-v9-development-protocol.json)은 별도 선행 커밋 `42312da`에 고정했다. 프로토콜 SHA-256은 `90dfe37b594e445839a26632ed1a618e1a8dc992ce66c43d1bb5d78074399bf1`이다. PC01 F→N→R, NC01 R→N→F의 여섯 요청을 각 1회 실행했고 재시도하지 않았다.
- F는 v7 전체 후보 원순 요청과 **요청 SHA-256·입력 토큰 수가 모두 일치**했다. PC01은 후보 F 22개, N/R 7개였고 NC01은 F 35개, N/R 4개였다. PC01 정답 P014의 표시 위치는 F 14번째, N 5번째, R 3번째였다. 정답값은 요청·후보 필터에 전달하지 않았다.
- 모델 파일 SHA-256 `644b04cde835d486df33c6d4d7552ba367fcb28802fe39b6b4bb9c60b9ab6f3d`, 서버 이미지 digest `sha256:17155a3ce4cc906728ec99a2814bf0b4eaffaf3b4872bad8c3affed310cdbc35`를 확인했다. 같은 서버의 실제 토크나이저로 계산한 입력은 PC01 F/N/R **686/475/475**, NC01 F/N/R **857/452/452토큰**이었다. 최대 생성 320토큰을 더해도 4,096토큰 문맥 안이다. 출력 토큰 수는 수집하지 않았다.
- [공개 저널](../../evals/structured_nlu/data/ai_heldout/as-safety-eb-nominal-order-v9-development-journal.v1.jsonl)은 헤더 1행·결과 6행으로 원문·프롬프트·원시 응답을 담지 않는다. 실행 후 계산한 SHA-256은 `37d33a6f32ebde421738a3ccdab50c7431d9db1193a0162aba4cef5c5e90b9e9`이며 사전 고정 기대 저널 해시가 아니다. 원시 응답은 저장소 밖 권한 제한 폴더에 보관했다. [독립 재생 결과](../../evals/structured_nlu/data/ai_heldout/as-safety-eb-nominal-order-v9-development-verification.v1.json)는 고정 요청·저널 순서·원시 응답 해시와 권한·출력 계약·검수 정답을 대조한다. 이 결과 파일 SHA-256은 `c7223ecee57f7c586e058f7417d3270384d94be9199691d1a8580f5458148cf2`이고, 실행 전·재생 검증기 SHA-256은 모두 `2933eb3a32c74811a5c0a0ce130408135f707cdfc23ca3b0edc8bee8d55df22e`다.

## 조건별 관찰

| 호출 | 출력 계약 | 주체 B | 종류·보류 | 채점 |
| --- | --- | --- | --- | --- |
| PC01 F 전체 원순 | 통과 | P013 `선풍기 모터에서`(8자), 정답 P014 불일치 | `location` 일치 | B 오답 |
| PC01 N 명사 끝 원순 | 통과 | 원문에 있는 18자 문장 전체, **N 후보 목록에는 없음** | `location` 일치 | B 오답·후보 지시 미준수 |
| PC01 R 명사 끝 역순 | 통과 | 공란 | `unresolved` | 양성 보류 오답 |
| NC01 R 명사 끝 역순 | 통과 | 공란 | `unresolved` | 정당 보류 |
| NC01 N 명사 끝 원순 | 통과 | 공란 | `unresolved` | 정당 보류 |
| NC01 F 전체 원순 | 실패: `quote_not_anchored` | 의미 채점 제외 | 의미 채점 제외 | 출력 계약 오류 |

출력 계약은 **5/6**, 출력 계약 오류 **1/6**, 전송·길이 오류 **0/6**이다. PC01 B 정확 일치는 **0/3**, 종류 일치는 **2/3**이다. NC01은 N/R에서 **2/2** 정당 보류했고 F는 계약 오류여서 보류 성공·실패로 채점하지 않는다. PC01의 F↔N은 둘 다 계약 유효이지만 N이 정답으로 개선되지는 않았다. NC01의 F↔N 의미 점수 짝 비교는 F 계약 오류로 **평가 불가**다. 사전에 정한 N/R 네 호출 관문은 PC01 N·R의 실패로 **통과하지 못했다**. 여섯 호출 지연 합계 35,915.283ms는 로컬 기술 기록이며 속도 개선 근거가 아니다.

PC01 N의 인용은 원문에 존재하므로 두 필드 **형식 계약**은 통과했지만, 프롬프트가 제시한 N 후보에는 없는 구절이었다. 이는 후보를 22개에서 7개로 줄이고 정답을 남겨도 모델이 후보 경계에 맞춰 고르지 않을 수 있음을 보여 준다. R에서는 같은 7개 후보의 표시 순서만 바꿨는데 공란을 반환했다. 각 조건 1회와 순서·입력 길이·정답 표시 위치의 변화가 함께 있어 원인을 하나로 단정하거나 순서 효과 크기를 추정하지 않는다.

## 다음 판단

N/R을 ES 전체로 확대하거나 서비스 안전 분기에 연결하지 않는다. 다음에는 후보 목록 **준수 여부**를 출력 계약과 별도 지표로 검증하고, 출처 불명 보류를 유지하면서 정확한 구절 선택을 가능하게 하는 인터페이스를 다시 설계해야 한다. 단순히 더 짧은 구절을 사후 정답으로 승격하거나 정답 후보를 프롬프트에 주입하지 않는다. 새 방법을 고른 뒤에도 미노출 사례·전체 정답을 별도로 검수·사전 고정해야 공식 개선율을 논할 수 있다. B→A와 최종 안전 경로는 평가하지 않았다. TX·GB는 사용하지 않았으며 GB의 일부는 이전 v8 작업에서 노출돼 미노출 자료로 취급하지 않는다. Q5 컨테이너와 Docker Desktop은 실행 후 종료했고 AWS·KT cloud는 사용하지 않았다.

모델 실행 전 관련 `.venv/bin/python -m pytest tests/test_as_safety_atomic_edge_nominal_order_v9.py tests/test_as_safety_atomic_edge_candidate_order_v7.py tests/test_as_safety_atomic_edge_boundary_audit_v8.py -q`에서 **48개 통과**했다. 같은 새 모듈·테스트 범위의 Ruff check/format도 통과했다. 이는 코드 검증이지 위 실모델 의미 점수가 아니다.
