# A/S 안전 문맥 코드 고정 후 탐색 짝비교

## 평가 경계

안전 경로 후보를 커밋 `24cbf80`에 먼저 고정한 뒤 AI 작성 PF01–PF16 발화를 만들었다. 사용자가 문장·위험 방향과 모든 행동·필드 값·공란을 별도로 채택했다. 독립적인 두 번째 검수자는 없다. 입력과 검수 원장은 `89655e5`, [실행 프로토콜](../../evals/structured_nlu/data/ai_heldout/nlu-safety-postfreeze-graph-pair-protocol.v1.json)은 `8da6de9`에 모델 실행 전에 커밋했다. 이전 SC·CX 사례는 새 평가에 넣지 않았다.

같은 Kanana Q5 파일·요청 정책·서버 이미지에서 이전 코드 `58595de`와 후보 `24cbf80`의 A/S 그래프를 16쌍 실행했다. 실행 순서를 사례마다 번갈아 적용하고 4·8·12쌍 뒤 서버를 재시작했다. 결과에는 최종 상태와 정규화된 출력·요청 횟수·오류 유형·지연 시간만 남겼다. 프롬프트와 모델 응답 전문은 저장하지 않았다. AWS는 사용하지 않았다.

## 확인된 결과

[결과 파일](../../evals/structured_nlu/results/nlu-safety-postfreeze-graph-pair-v1.json)의 32개 그래프 실행을 [독립 검증기](../../scripts/verify_nlu_safety_postfreeze_pair.py)로 재계산했다.

| 지표 | 이전 `58595de` | 후보 `24cbf80` |
| --- | ---: | ---: |
| 실제 위험 8건의 안전 보호 상태 진입 | 2/8 | 2/8 |
| 위험 진술이 없는 8건의 잘못된 진입 | 0/8 | 0/8 |
| 실제 위험 8건 중 모델 호출 없는 보호 경로 | 2/8 | 2/8 |
| 전체 16건의 그래프 오류 | 0/16 | 0/16 |

PF02·PF06만 두 코드에서 안전 상태로 갔다. PF01·PF03·PF04·PF05·PF07·PF08은 두 코드 모두 놓쳤으며, 이 여섯 건에서 모델이 반환한 `safety_status`도 모두 공란이었다. 후보의 SC·CX 개발 사례 통과는 이 새 사례에서의 개선으로 이어지지 않았다. 두 코드의 짝변화가 없으므로 이 표본의 안전 경로 개선 건수는 0이다.

**판단:** 이 후보를 안전 성능 개선으로 소개하거나 바로 배포할 근거가 없다. PF는 코드 고정 후 새로 작성했지만, AI 작성·1인 검수이며 앞선 개발 사례와 같은 위험 유형을 겨냥한 표적 스트레스 세트다. 실제 사용자 발화 분포나 전체 업무 정확도를 추정하지 않는다. PF도 이번 실행 이후 개발·회귀 사례로만 사용한다.

다음 설계는 위험 단어의 존재만 보지 않고, 실제 위험 **현상**, 현재 A/S **대상**, 발화의 **긍정·부정·가정·인용**을 분리해야 한다. 이 설계 역시 PF에 맞춰 개발한 뒤에는 별도의 미노출 사례로 다시 평가해야 한다.

## 결과 확인 뒤의 안전 전용 질문 진단

PF가 이미 모델에 노출된 뒤, [고정한 진단 절차](../../scripts/probe_safety_focus_development.py)로 같은 Q5에 짧은 안전 전용 질문을 한 번씩 보냈다. [개발 결과](../../evals/structured_nlu/results/nlu-safety-focus-exposed-development-v1.json)는 위험 8/8을 `true`로 분류했지만, 비위험 8건은 정답 4건·오탐 1건(PF12의 가정형)·형식 오류 3건(PF10·PF11·PF16)이었다. 요청 지연의 중앙값은 약 0.79초다. 별도 세션의 일반 구조화 요청과 지연을 직접 비교해 속도 개선으로 주장하지 않는다. 원문 프롬프트·응답은 저장하지 않았다.

이 진단은 **노출된 개발 사례**이므로 새 정확도 결과가 아니다. 위험 누락 감소 가능성은 보였지만, 가정형 오탐과 형식 실패가 있어 즉시 안전 상태로 보내는 자동 결정에는 채택하지 않는다. 위험 단서가 있으나 확정되지 않은 경우 사용자의 확인을 받는 상태를 다음 설계 후보로 남긴다. 그 상태의 문구, 사용자 응답 계약, 취소·종료 경로와 추가 지연은 구현·평가 전까지 성과로 말하지 않는다.
