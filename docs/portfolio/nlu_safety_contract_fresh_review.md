# A/S 안전 경로·빈 정보 계약: 새 발화 검수 초안

**현재 상태: AI 작성 문장·의미 방향과 전체 필드 정답을 사용자가 2026-11-06에 채택했고, [SC01–SC20 짝비교](nlu_safety_contract_graph_pair_run_log.md)에 사용돼 모델에 노출됐다.** 아래 평가 설계는 실행 전 기록이다. 데이터·코드·실행 조건을 동결한 뒤 모델에 보냈으며, 기존 RF01–RF12 결과와 합산하지 않는다. SC 사례는 새 평가에 재사용하지 않는다.

## 평가 질문과 범위

- 대상: 고객센터 A/S 접수의 `greeting` 상태. 이전 수집 필드는 전부 공란으로 고정한다.
- 안전: 실제 위험 진술에서 안전 보호 상태로 이동하는 비율과, 부정·질문·가정에서 잘못 이동하는 비율을 각각 센다. 모델의 구조화 정답과 최종 그래프 경로를 별도 지표로 보고한다.
- 계약: 범위 밖 문의에서 모델 요청 횟수, 최종 계약 통과와 `unknown` 행동을 센다. 빈 정보 정규화가 다른 필드를 만들어내지 않는지도 확인한다.
- 비교: 안전 보호 경로와 빈 정보 정규화 전 코드 `ae91656`, 수정 코드 `9eacb92`를 같은 Q5 모델·이미지·요청 정책으로 짝비교한다. 두 변경의 효과를 범주별로 해석하고, 전체 서비스 정확도로 일반화하지 않는다.
- 기존 코드 짝비교 실행기는 구조화 분석기만 호출하므로 안전 보호 경로의 실제 효과를 측정하지 못한다. 새 실행은 A/S 그래프 전체를 호출하고, 모델 요청·재시도와 최종 상태를 함께 기록하는 별도 검증 경로가 필요하다. 안전 가드가 모델을 우회한 경우의 요청 0회를 계약 실패로 세지 않는다.
- 아래 네 안전 범주는 서로 다른 언어 현상을 겨냥한다. 기존 RF의 배터리 팽창·연기·타는 냄새 문장을 바꿔 쓴 점수로 보이지 않도록 제품과 상황을 달리했다. 단, AI 작성 후보이므로 독립적인 실제 사용자 분포 표본은 아니다.

## 정답 확정 전에 남은 판단

1. SC01–SC16의 `product_type`, `symptom`, `safety_status`, `occurred_at`, `service_channel`, `preferred_schedule`, `model_name` 값과 공란을 문장마다 확정한다. 명시하지 않은 모델명·시점·접수 방식은 만들지 않는다.
2. SC13–SC16은 질문·걱정과 실제 위험 진술의 경계를 사용자가 검수한다. 안전 정보 제공의 적절성과 **즉시 사용 중지 상태로 전환할 근거**는 구별한다.
3. 비교 코드는 각 실행 시점의 소스 해시로 고정한다. 동일 모델 파일과 서버 조건을 확인하고, 짝 순서와 재시도 정책을 미리 정한다. 프롬프트·원문 완성문은 결과 파일에 저장하지 않는다.
4. 보고 시 안전 양성 8건의 경로 재현율, 안전 음성 8건의 과잉 차단율, 범위 밖 4건의 계약 통과·행동 일치를 **분모와 함께** 표시한다. 20건의 작은 AI 작성 검수 표본이며, 전체 정확도 개선율이라는 제목을 붙이지 않는다.
