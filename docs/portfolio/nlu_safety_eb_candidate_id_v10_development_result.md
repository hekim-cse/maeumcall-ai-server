# A/S 위험 주체 후보 ID 개발 진단 결과

> 2026-11-22. 기노출 AI 작성·사용자 검수 PC01·NC01 두 사례의 실모델 개발 진단이다. [실행 전 방법](nlu_safety_eb_candidate_id_v10_method.md)의 관문은 **실패**했다. 공식 정확도, 개선율, 서비스 안전 경로 성능으로 사용하지 않는다.

## 실행과 증거

- 방법·코드·테스트를 먼저 `33dc70cbef9ecb88ec9ebf4f26deaa2deef3419f`에, 실제 서버 토큰 수와 요청 바이트를 담은 [프로토콜](../../evals/structured_nlu/data/ai_heldout/as-safety-eb-candidate-id-v10-development-protocol.json)을 별도 선행 커밋 `9e83d92`에 고정했다. 프로토콜 SHA-256은 `4c88aeb3b0bc70d3e50c343edfd377bc977a98e7fa444be194e304aebce89feb`이다.
- 고정 Q5 모델 파일 SHA-256 `644b04cde835d486df33c6d4d7552ba367fcb28802fe39b6b4bb9c60b9ab6f3d`, 서버 이미지 digest `sha256:17155a3ce4cc906728ec99a2814bf0b4eaffaf3b4872bad8c3affed310cdbc35`를 사용했다. 실행기는 컨테이너 생성 전 호스트 파일을 확인하고 읽기 전용 마운트·컨테이너 내부 해시·ID 및 호스트 파일 식별자를 시작 시점과 각 호출 전후에 확인했다. 서버 메모리 안의 가중치 바이트 자체를 독립 검증한 것은 아니다.
- PC01→NC01 순서로 각 1회 요청하고 재시도하지 않았다. 입력 토큰은 실제 서버 토크나이저 기준 각각 426·403이다. 후보는 PC01 7개, NC01 4개였고 검수 정답은 요청·후보 생성에 넣지 않았다.
- [공개 저널](../../evals/structured_nlu/data/ai_heldout/as-safety-eb-candidate-id-v10-development-journal.v1.jsonl)은 헤더 1행·결과 2행이며 SHA-256은 `633bd804ac9f895817e1cf71bb949f826756704dca8d405d3880483174b7f8d1`이다. 원문·프롬프트·원시 응답은 싣지 않았다. 원시 응답은 저장소 밖 권한 제한 폴더에 보관했고, [독립 재생 결과](../../evals/structured_nlu/data/ai_heldout/as-safety-eb-candidate-id-v10-development-verification.v1.json)는 원시 해시·권한, 고정 요청, 출력 계약, 정답을 대조했다. 검증 결과 파일 SHA-256은 `11d39d5432017eef72dcef19b61b2fab567a213fd891cbb03d84f3f3f430182a`다. 공개 파일만으로 원시 응답 내용을 독립 재생할 수는 없다.
- PR 리뷰에서 검증기가 저널을 두 번 읽으면 동시 기록 시 채점과 해시가 다른 상태를 가리킬 수 있다는 지적을 받아, **모델 실행 후** 커밋 `e56d3b1`에서 단일 읽기 방식으로 보강했다. 실행 전 고정 검증기 SHA-256 `41a4c604ded77fa90a4ead003f9cc391fbf3a20250f414ffda23b8f3b4e1e916`과 실행 후 검증기 SHA-256 `9b1fb7de293c2c3a3d4aea58eb0ff7ea3eafbc70e45a5b2094f410277b8cbf4a`를 검증 결과에 별도로 기록했다. 모델 실행 코드·입력·원시 응답·저널은 변경하지 않았다. 같은 원시 응답 재검증에서 점수와 관문 판단은 동일했다. 잘못된 종류·추가 필드·공백 응답 거절 및 첫 호출 전송 오류 시 중단·재실행 거절 테스트를 추가해 관련 **39개 테스트가 통과**했다.

## 사전 관문 채점

| 사례 | 출력 계약 | 모델 선택 | 검수 정답 | 의미 판정 |
| --- | --- | --- | --- | --- |
| PC01 | 통과 | P016 `모터에서 연기`, 종류 `location` | P014 `선풍기 모터`, 종류 `location` | B 불일치, 종류 일치 |
| NC01 | 통과 | P020 `타는 냄새`, 종류 `location` | B 공란, 종류 `unresolved` | 정당 보류 실패 |

전송·길이·출력 계약 오류는 **0/2**, 출력 계약 통과는 **2/2**다. PC01의 B 정확 일치는 **0/1**, 종류 정확 일치는 **1/1**이며, NC01의 정당 보류는 **0/1**이다. 두 선택 ID는 모두 제시한 후보 안에 있다. 따라서 후보 밖 자유 인용은 관찰되지 않았지만, 후보 선택의 의미 정확성과 출처 불명 보류는 개선되지 않았고 사전 관문은 **실패**했다.

PC01의 선택 구절은 주체와 위험 현상을 함께 포함한다. NC01의 선택 구절은 출처가 아니라 현상 자체다. 이는 후보 목록에 잘못 해석될 수 있는 구절이 있고 모델이 사건의 물리적 출처와 현상을 구분하지 못했을 가능성을 보여 준다. 두 기노출 사례의 단회 실행으로 실패 원인이나 일반화 성능을 단정하지 않는다. 요청 지시문·출력 형식·입력 길이도 앞선 v9와 함께 바뀌었으므로 후보 ID 방식 하나의 인과 효과나 속도 개선을 주장하지 않는다. 두 요청 지연 합계 16,899.917ms는 로컬 실행 기록이다.

## 다음 판단

이 계약을 ES 전체나 서비스 안전 경로에 연결하지 않는다. 다음 개발 단계에서는 원문 후보 생성이 위험 현상과 주체를 섞는 경계를 먼저 분석하고, 후보가 있어도 출처가 확인되지 않는 경우의 보류 판단을 따로 검증해야 한다. 새 후보 규칙과 정답을 개발 사례에 맞춰 사후 조정했다면, 그 사례는 다시 독립 평가에 쓰지 않는다. 새 미노출 사례와 전체 정답을 별도 검수·사전 고정한 뒤에야 공식 개선율을 계산할 수 있다. B→A 관계와 최종 안전 경로는 이번에 평가하지 않았고 TX·GB는 사용하지 않았다. AWS·KT cloud는 사용하지 않았다.
