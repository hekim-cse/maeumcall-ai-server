# A/S 위험 근거 그래프 실패 원인 분해

> 2026-11-16. 이미 노출된 AI 작성·사용자 검수 ES 개발 자료 **19개 원시 응답의 사후 오프라인 진단**이다. 새 모델 호출이나 새 정확도 평가는 아니다. 원본 프로토콜·저널·원시 응답과 기존 점수는 변경하지 않았다. TX·GB 봉인 자료는 읽지 않았다.

## 재계산 범위

[분석기](../../experiments/as_safety_evidence_graph_v1/offline_audit.py)는 기존 프로토콜의 입력 해시, [저널](../../evals/structured_nlu/data/ai_heldout/as-safety-evidence-graph-v1-development-journal.v1.jsonl)의 해시와 [독립 검증 기록](../../evals/structured_nlu/data/ai_heldout/as-safety-evidence-graph-v1-development-verification.v1.json)의 집계, 저장소 밖 19개 원시 응답의 크기·SHA-256·파일 권한(0600)·개수를 먼저 대조한다. 원래 검증기는 첫 계약 오류만 기록했으므로 이번에는 각 필드의 원문 위치와 정답 일치를 별도로 읽는다. 공개 [오류 행렬](../../evals/structured_nlu/data/ai_heldout/as-safety-evidence-graph-v1-posthoc-error-audit.v1.json)은 사건 ID·유한한 상태 코드·해시·불리언만 담고 발화·프롬프트·원시 인용을 담지 않는다. 행렬 SHA-256은 `f14930d22dd0702641389f7479fccac471e61349b03ba6287d20aee47dad3745`다.

원시 응답 19개는 임시 실행 위치에서 사용자 홈의 `.local/share/maeumcall-evaluations/as-safety-evidence-graph-v1/raw`로도 복사했다. 보관 폴더는 0700, 파일은 0600이며 보관본으로 분석을 다시 실행해 공개 행렬과 완전히 일치함을 확인했다. 공개 행렬만으로는 원시 응답의 의미 판단을 제3자가 재생할 수 없고, 이 로컬 보관본은 클라우드 백업이 아니다.

절 번호 교정 후보는 ES03·ES10·ES12·ES15·ES17이었다. 인용 문자열·주체 선택·연결 종류·의미 판단은 바꾸지 않았다. ES10·ES12·ES17만 새로 계약을 통과했으며, 셋 모두 `current`로 투영되어 정답 관계와 달랐다. ES03은 다음 E→B 연결 규칙을, ES15는 다른 인용의 원문 위치 검사를 통과하지 못했다. 이는 **인용 형식 오류를 고치는 것만으로 위험 출처 판단이 해결되지 않는다**는 기존 응답에 대한 반증이다. 실제 모델을 수정·재실행한 결과가 아니다.

기존 유효 응답 4개 중 ES06의 첫 사건은 별개 기기의 위험을 현재 제품 위험으로 오판했다. 같은 사례의 두 번째 현재 제품 사건 때문에 사례 안전 경로만 보면 이 오류가 가려진다. 따라서 다음 평가도 사건별 관계와 사례별 경로를 나눠야 한다. 원문에 존재하는 구절이라는 사실만으로 `part_of` 관계가 의미상 참이 되는 것도 아니다.

## 다음 실험 결정

비공란 주체 B를 가진 18사건의 관계 정답은 `current` 9건·`other` 9건이다. 현재 원시 응답의 연결 종류는 모두 `location → part_of`였으며, 단순한 절 번호 오류 제거로 관계는 개선되지 않았다. 따라서 [다음 설계 초안](nlu_safety_relation_oracle_order_v1_method.md)에서는 검수된 A·E·B를 입력으로 주고 관계 세 값만 출력하게 해 **주체 추출·인용 부담을 제거한 상태의 관계 판단**을 먼저 진단한다. 정의 제시 순서 두 조건을 같은 사건에 짝지어 적용하고, 상수 출력 기준선 9/18과 범주별 결과·대비쌍·퇴행을 함께 본다. 이는 주체 오라클을 사용하는 노출 개발 자료 실험이다. 어느 결과도 공식 전체 정확도 개선율이나 배포 안전성으로 표현하지 않는다.
