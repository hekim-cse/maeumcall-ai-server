# A/S 관계 대칭 판단 개발 실험 계획

## 출발점과 가설

[원인 재진단](nlu_safety_grounded_entity_link_cause_result.md)에서 이미 노출된 RE/V 22건에 대해 모델은 `same_or_part`를 22번 모두 선택했다. 15건은 인용 앵커 검증에서 보류로 바뀌었으며, 다른 제품 관계 정답은 0/6이었다. **인용 요건만 완화하면** 이 6건까지 현재 제품 관계로 확정될 수 있어 그 변경은 시험 후보에서 제외한다.

작은 개발 후보로 두 명제를 한 호출에서 대칭적으로 묻는다. A와 B가 같은 물건 또는 소속 부품인지, B가 A와 별개 물건에 속하는지를 각각 `yes|no|uncertain`으로 답하게 한다. `(yes,no)`일 때만 `current`, `(no,yes)`일 때만 `other`로 매핑하고 나머지 7개 조합은 `unknown`으로 보류한다. 두 답은 같은 모델 호출에서 생성되므로 서로 일관되더라도 의미적으로 옳다는 보장은 없다.

## 고정 실행

- 이전에 사용자 검수했고 이미 모델에 노출된 RE/V 22건만 사용한다. 접수 대상·위험 주체 구절과 문장 번호는 입력 오라클이다. 관계 정답과 발생 상태는 모델에 주지 않는다. GB01–GB24는 개발과 오류 분석에서 봉인한다.
- 이전과 같은 Kanana Q5, llama.cpp 이미지, 로컬 자원(2 CPU·4 GiB·4096 context·2 thread·동시 처리 1개), 최대 출력 320토큰·온도 0·재시도 없음, 고정 순서를 사용한다. 프롬프트와 출력 계약이 달라졌으므로 이전 점수와 인과적 개선율을 계산하지 않는다.
- 첫 호출 전에 후보·실행기·검증기·요청 정책·데이터와 실제 프로젝트 내부 import 의존성의 경로·SHA를 프로토콜에 기록하고 커밋한다. 기록이 일부만 남으면 자동 재실행·덮어쓰기를 하지 않는다.
- 저널에는 두 유한 응답, 최종 관계·경로, 오류와 시간만 기록한다. 원문·프롬프트·모델 응답은 저장하지 않는다. 이 선택은 원시 모델 응답을 사후 독립 대조할 수 없다는 한계를 만든다.

## 보고와 중단 기준

독립 검증기는 22건·45행·순서·해시·유한 전이·관계와 경로의 집계·대비쌍을 재검산한다. 결과에는 `current` 16건, 그중 관찰 위험 13건, `other` 6건, 대비쌍 3개, 모든 보류·계약 오류와 잘못된 현재 제품 확정을 함께 적는다.

개발 후보가 다른 제품을 잘못 현재 제품으로 확정하거나 현재 제품 관찰 위험을 보류하면 그 실패를 숨기지 않는다. 사전 안전 게이트는 현재 제품 관계 최소 15/16, 관찰 위험 13/13, 다른 제품 6/6, 대비쌍 3/3, 오류 0/22다. 이 게이트를 통과해도 이미 노출된 사례의 개발 결과이므로 서비스 연결 근거가 아니다. 후보를 고정한 뒤 새 AI 작성·사용자 검수 대비 사례에서 별도 탐색 평가를 해야 한다.
