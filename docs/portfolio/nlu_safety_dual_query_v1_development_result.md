# A/S 위험 출처 양방향 질문 개발 진단 결과

> 2026-11-17. **개발 관문 실패.** 이미 노출된 AI 작성·사용자 검수 ES 사례에서 검수된 접수 대상 A·위험 사건 E·발생 주체 B·발생 상태를 모델에 제공한 관계 하위 과제다. 공식 정확도, 새 사례 일반화 성능 또는 실제 서비스의 종단 간 안전 성능이 아니다.

## 실행과 재검증

- [사전 설계](nlu_safety_dual_query_v1_method.md)와 실행 코드·입력을 커밋 `e0d75db6ec8cfc622a3b484e5063a7968aa23687`에 고정하고, [프로토콜](../../evals/structured_nlu/data/ai_heldout/as-safety-dual-query-v1-development-protocol.v1.json)을 별도 커밋 `ec3a263`에 고정한 뒤 모델을 호출했다. 프로토콜 SHA-256은 `5b97d2882c30067925a41c0421d40c09f170183b44109d2f655093303204e5d5`다. 검증기는 실행 소스 24개, 입력 5개의 해시와 모델 파일 SHA-256 `644b04cde835d486df33c6d4d7552ba367fcb28802fe39b6b4bb9c60b9ab6f3d`를 대조했다.
- 동일한 로컬 Kanana Q5·llama.cpp 이미지에서 CPU 2개, 컨테이너 메모리 4GiB, 컨텍스트 4096, 온도 0, 동시 처리 1개로 실행했다. 이미 노출된 ES 20사례의 검수 사건 중 적격 **18사건/17사례**에 현재 제품 소속 질문과 별개 제품 질문을 각각 한 번씩, 교대 순서로 총 **36회** 호출했다. 재시도와 중단 재개는 없었다. ES17의 주체 공란 사건과 미발생 사건 3개는 호출하지 않았다. 검수 관계·기대 경로는 모델 입력에 제공하지 않았다.
- [74행 공개 저널](../../evals/structured_nlu/data/ai_heldout/as-safety-dual-query-v1-development-journal.v1.jsonl)의 SHA-256은 `93ddf25bc5ca02f259efe5f5c2b33284655918602e52997a6bee5ec8041fb270`이다. 저장소 밖 소유자 전용 폴더 `0700`에 원시 응답 36개를 각각 `0600`으로 보존했다. [독립 검증 결과](../../evals/structured_nlu/data/ai_heldout/as-safety-dual-query-v1-development-verification.v1.json)의 SHA-256은 `a69d504cff728a04baf2df30323a4b7308177c5dd5ed9876beab0f67d27d5a58`이다. 검증기는 원시 파일의 목록·권한·해시와 순서·계약·두 판단·합성 관계·조건부 경로·집계를 독립 재계산했다. 공개 기록에 발화·프롬프트·원시 응답 본문은 없다.

## 결과

| 사전 지표 | 결과 |
| --- | ---: |
| 질문별 JSON 계약·응답 통과 | 36/36 |
| 사건 관계 정답 | **0/18** |
| 관찰된 현재 제품 위험 관계 | 0/8 |
| 발생 불확실한 현재 제품 위험 관계 | 0/1 |
| 관찰된 다른 출처 위험 관계 | 0/9 |
| 두 답이 일관돼 관계를 확정한 사건 | 0/18 |
| 합성 관계 `unknown` | 18/18 |
| 조건부 사례 경로 정답 | 1/17 |
| 관찰된 현재 제품의 즉시 안전 조치 누락 | **8/8사건, 8사례** |
| 다른 출처를 현재 제품 직접 위험으로 오경고 | 0사례 |
| 대비쌍의 관계·경로 모두 정답 | 0/2쌍 |
| 계약·전송 오류 | 0/36 |

현재 제품 질문은 `yes` 17건·`unknown` 1건, 별개 제품 질문도 `yes` 17건·`unknown` 1건이었다. **서로의 답을 전달하지 않은 두 질문의 원시 응답은 같은 사건 18쌍 모두 바이트 단위로 동일**했다. 17쌍은 `yes/yes`로 서로 모순됐고 1쌍은 `unknown/unknown`이었다. 사전 규칙에 따라 18건 모두 `unknown`으로 보류했다. 형식 계약 36/36은 의미 판단 성공을 뜻하지 않는다. 모델이 왜 동일한 값을 반복했는지는 이 기록만으로 확정할 수 없다.

관계가 확정된 사건이 0건이어서 **확정된 관계의 정답률은 분모 0으로 미정의**다. 확정률은 0/18이다. 1/17의 경로 정답은 ES18의 발생이 불확실한 현재 제품 사건이 확인 경로로 간 사례이며, 직접 위험을 제대로 식별한 성공이 아니다. 안전 확인으로 보류한 8건의 관찰된 현재 위험은 즉시 안전 조치를 받지 못한다. 따라서 오경고 0건이나 계약 오류 0건만으로 안전성이 좋아졌다고 해석하지 않는다.

질문별 요청 지연 중앙값·95백분위는 현재 제품 질문 **2,323ms·4,252ms**, 별개 제품 질문 **2,332ms·2,532ms**다. 사건당 두 요청 시간 합계는 **4,671ms·6,783ms**, 사례별 요청 시간 합계는 **4,669ms·9,810ms**다. 모두 밀리초 단위 반올림값이며 모델 로드 시간·실제 사례 벽시계 시간·서비스 종단 간 지연을 포함하지 않는다.

## 판정과 다음 작업

사전 개발 관문인 관찰 현재 8/8, 불확실 현재 1/1, 다른 출처 9/9, 사례 경로 17/17, 대비쌍 2/2, 오류 0/36 중 오류 조건만 충족했다. **두 독립 질문과 보수적 결합은 이 Q5 조건의 서비스 후보가 아니다.** 현재 안전 가드는 그대로 유지한다. 기존 관계 순서 실험과 입력 사례는 같지만 프롬프트·호출 수·출력 계약·보류 규칙이 모두 달라 점수 차이를 인과적 개선율로 계산하지 않는다.

다음에는 같은 Q5의 질문 문구를 반복 조정해 점수를 고르는 대신, 위험 출처 판단을 맡길 모델·방법의 적합성과 비용을 개발 자료에서 비교할 필요가 있다. 새 후보를 고른 뒤에는 모델이 보지 않은 새 발화와 사건·주체·관계·경로 정답을 사용자 검수하고 사전에 고정해 별도 평가한다. TX·GB 봉인 사례와 이미 평가한 IT·SS 사례는 이번 후보 선택에 쓰지 않았다. AWS와 KT cloud도 사용하지 않았다.
