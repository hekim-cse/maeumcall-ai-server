# AI 작성·사람 검수 내부 test 표본 설계 V1

> 상태: test 문장 생성 전, validation 모델 결과 확인 전 설계. 이 문서는 평가 사례나 성능 결과가 아니다. 대상은 구조화 NLU를 쓰는 16개 상세 업무다.

## 질문과 분모

범위 계약 후보가 **처음 보는 발화**에서 사례 전체 일치를 높이면서 업무 안 요청의 오거절과 출력 계약 실패를 늘리지 않는지 같은 사례의 기존·후보 코드로 비교한다. 주지표는 64건의 `case_exact_match_rate`와 짝지은 정답 건수 차이(퍼센트포인트)다. 상대 개선율은 기존 정답이 0건이면 계산하지 않는다.

16개 업무마다 다음 네 조합을 **각 1건** 작성해 전체 64건으로 고정한다.

| 대화 상태 | 업무 안 요청 | 범위 밖 요청 |
| --- | ---: | ---: |
| 시작 `greeting` | 업무당 1건 | 업무당 1건 |
| 실제 후속 상태 | 업무당 1건 | 업무당 1건 |

후속 상태는 해당 업무 그래프에서 실제로 진입할 수 있고 현재까지 수집한 필드·직전 질문이 일치해야 한다. 업무 안/범위 밖의 판단은 정답 코드만으로 증명되지 않으므로, 검수자가 발화와 상태를 함께 읽고 판단한다. 같은 상황을 주어만 바꿔 네 칸에 반복하지 않는다. 모델 입력의 원문·정규화 정확 일치 검사와 가까운 바꿔쓰기 수동 검토를 모두 거친다. AI 작성 출처와 사용자 1인 검수 사실을 명시한다.

## 별도 A/S 안전 표본

64건의 A/S 사례는 네 칸 중 각 1건뿐이므로 일반적인 안전 누락률을 추정하기에 부족하다. 후보를 최종 test에 올리기 전에는 **이미 노출된 PF01–PF16**을 안전 회귀 관문으로 사용한다. 이 16건은 개발용이며 64건 정확도 분모에 합치지 않는다.

최종 test에서 안전 성능을 별도 수치로 제시하려면 새 발화를 추가로 작성·검수하고, 현재 접수 제품의 실제 위험, 발생 여부 불확실, 다른 출처의 위험, 가정·부정 표현을 각각 같은 수로 사전 고정한다. 위험 누락과 비위험 오경고를 각각 원시 건수와 분모로 보고한다. 이 추가 표본이 없거나 검수되지 않으면 안전 성능 수치를 발표하지 않는다.

## 보조 지표와 해석 경계

- 범위 밖 `unknown` 적중과 업무 안 요청의 `unknown` 오거절을 각각 32건으로 보고하고, 같은 사례의 개선·악화를 나눈다.
- 첫 시도·최종 출력 계약 통과, 재시도, 완전 실패를 따로 보고한다. 계약 실패를 의미 오류와 합쳐 원인을 단정하지 않는다.
- 비공란 필드 누락, 공란 필드에 대한 불필요 값 생성, 값 정확 일치는 업무 안/범위 밖과 계약 유효 여부를 구분해 원시 건수·분모를 함께 보고한다. 계약 실패가 있는 조건의 `hallucination_rate`만 단독 비교하지 않는다.
- 전체 사례 일치는 양쪽 정답·기존만 정답·후보만 정답·양쪽 오답의 짝 비교 표로 보인다. 업무별·대화 상태별 결과는 작은 분모를 명시한다.
- 호출 시간·토큰 수는 현재 짝 비교 실행기가 기록하지 않으므로 이 프로토콜의 성능 결과로 주장하지 않는다. 행동 macro F1의 희소 클래스나 `intent_accuracy`를 전체 16업무 자유 분류 성능처럼 설명하지 않는다.

## 발행 조건

validation 32건으로 후보를 선택한 **뒤에** test 문장을 만든다. 문장·상태·행동·모든 필드와 공란·허용 문자열을 사람이 검수해 사례별 원장으로 고정한다. 첫 test 모델 호출 전에 두 코드, 모델, 요청·서버 설정, 순서, 원시 기록 위치와 독립 검증기를 커밋한다. 유효한 양 조건 64건을 원시 응답으로 독립 재생한 경우에만 “AI 작성·사람 검수 내부 공식 표본 평가”의 수치를 발행한다. 짝 비교 95% 구간의 하한이 0을 넘고 새 직접 위험 누락이 없을 때만 **이 내부 표본에서 개선 확인**이라고 표현한다. 그 외에는 관측 차이 또는 후보 기각으로 기록한다.
