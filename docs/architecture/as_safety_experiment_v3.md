# A/S 위험 출처 관계 판단 v3 개발 실험

## 질문과 비교 단위

v2의 유효한 2단계 응답 17건은 모두 `other`였다. 1단계에서 통과한 20건의 `owner_kind`도 전부 `explicit`이었다. 이 실험은 1단계 추출을 새로 실행하지 않고 당시 원시 응답을 검증해 재사용한다. 접수 대상 A와 1단계 위험 사건 E·주체 B는 유지하고, 2단계 프롬프트에서 소속 대상 C와 `owner_kind` 후보를 제외한다. 그러면 2단계에 제공한 C 후보가 `other` 쏠림에 기여했는지 조건부로 비교할 수 있다. 다른 프롬프트·출력 계약도 함께 바뀌므로 특정 문구 하나의 인과 효과를 단정하지 않는다.

새 2단계는 위험이 발생한 물건의 원문 구절과 그 물건이 접수 대상 A와 맺는 관계를 `same`, `part_of`, `coreference`, `distinct`, `unclear`에서 고른다. 앞의 세 값은 `current`, `distinct`는 `other`, `unclear`는 `unknown`으로 사전 정의해 변환한다. 원문 구절의 위치 검증은 **인용이 존재함**만 증명한다. 실제 위험 사건 선택과 제품 간 의미 관계는 별도의 검수 대상이다.

## 데이터와 게이트

- 대상은 이미 모델에 노출된 AI 작성·사용자 검수 RE/V 22건이다. 새 후보 선택을 위한 **개발 진단**이며 독립 평가나 공식 전체 정확도가 아니다.
- v2 1단계가 통과한 20건에만 새 2단계를 한 번 실행한다. 실패한 2건은 그대로 `skipped`로 남겨 전체 22건 분모에서 숨기지 않는다.
- v2와 v3의 관계 판단은 동일한 1단계 통과 20건에서 짝지어 비교한다. 전체 22건 결과도 따로 보고하며, 조건부 수치를 전체 안전 성능으로 바꾸지 않는다.
- 조건부 2단계 사전 게이트는 계약 오류 0/20, 현재 제품 14/14, 관찰된 현재 제품 위험 12/12, 다른 제품 6/6, 기존 대비쌍 3/3이다. 1단계 오류 2건이 고정되어 있으므로 이 실험만으로 원래의 전체 22건 안전 게이트를 통과할 수 없다.
- TX01–TX16과 GB01–GB24는 후보 선택 및 프롬프트 수정에 사용하지 않는다. 결과가 좋아도 실서비스의 안전 분기를 이 실험만으로 교체하지 않는다.

## 재현과 감사

모델 호출 전에 코드·입력·기준 저널·Q5 모델 해시·실행 조건·프로토콜을 커밋한다. 실행기는 고정된 Git 객체와 현재 파일 바이트를 비교하고, v2 1단계 원시 응답의 해시·길이·검증 결과가 공개 저널과 일치하는지 확인한다. 각 호출 시작과 결과를 디스크에 즉시 기록하고 재시도하지 않는다. 원시 응답은 저장소 밖 소유자 전용 디렉터리에, 공개 저널에는 해시·길이·오류 코드·원문 구간 위치만 저장한다.

독립 검증기는 후보의 판단 함수를 가져오지 않고 원시 응답·저널·고정 소스를 별도로 대조한다. `current`의 누락, `other`의 오분기, `unknown`, 계약 오류, 호출 지연과 대비쌍을 함께 보고한다. 중단된 기록은 자동으로 이어서 실행하거나 성공 사례로 세지 않는다.

이 설계는 v2의 `other` 쏠림과 직접 연결된 입력을 제거해 원인을 좁힌다. 이전 타입 관계 후보는 계약 오류가 많았고 대칭 질문 후보는 반대 방향으로 치우쳤으므로, 출력 항목을 늘리거나 다수결을 하는 방법보다 이 조건부 짝비교를 먼저 수행한다.
