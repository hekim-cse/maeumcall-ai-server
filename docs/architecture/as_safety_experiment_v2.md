# A/S 위험 출처 실험 코드 경계

## 확인한 구조

실서비스의 A/S 계약은 `services/flow/support/contracts.py`, 상태 분석·그래프 노드·안전 가드는 `services/flow/service_workflow/`에 있다. 최근 위험 출처 관계 후보는 `scripts/`에만 있으며 서비스가 가져오지 않는다. 구조가 복잡해 보이는 주된 이유는 실패 후보를 버리지 않고 재현 가능한 개발 기록으로 남기면서 실험별 실행기와 독립 검증기를 복제한 데 있다. 이번 점검 시 A/S 관련 스크립트는 61개, 약 13,621줄이고 최신 v1 검증기는 783줄이다.

## 변경 원칙

1. 이미 실행한 v1의 후보·실행기·검증기·프로토콜·입력·저널은 옮기거나 수정하지 않는다. v1 검증기는 현재 체크아웃의 파일을 고정 해시 및 커밋과 비교하므로, 과거 재검증은 해당 커밋의 별도 작업 트리에서 한다.
2. 다음 후보는 `experiments/as_safety_v2/`에 둔다. 원문 분리·인용 앵커·엄격한 JSON 파싱처럼 의미 판단과 독립적인 작은 계약만 공통화한다. 이 모듈은 과거 실험 실행기를 import하지 않는다.
3. 모델 프롬프트와 판단 규칙은 후보 모듈에, 로컬 호출·저널·프로토콜은 실행 모듈에, 정답과 점수 재계산은 독립 검증기에 둔다. 독립 검증기가 후보의 판단 함수를 호출하면 같은 오류를 공유하므로 금지한다.
4. 사용자 검수 발화는 개발 참조 데이터로만 사용한다. 모델 입력에는 접수 대상 A만 제공하고 E/B/C 참조값은 평가에만 사용한다. 원문 인용의 존재, E/B/C 의미 적중, 최종 관계, 안전 경로를 별도로 보고한다.
5. 계약 오류는 단계·필드·유한 코드로 기록한다. 접근 제한된 원시 응답을 보존할 경우 공개 저널에는 원문 대신 해시·길이만 기록하고, 이 방식을 실행 전에 프로토콜에 고정한다.

경로 계산에는 검수된 사건 발생 상태(`event_status`)를 사용한다. 따라서 경로 결과는 **발생 상태를 이미 안다는 조건의 진단값**이며 실제 서비스의 종단 간 안전 판정 점수로 제시하지 않는다. 원문 인용 일치도 의미 정답과 따로 집계한다.

## 새 모듈의 책임

| 위치 | 책임 |
| --- | --- |
| `cases.py` | 기존 사용자 검수 자료의 출처와 22건의 개발 참조값 확인 |
| `quotes.py`, `json_contract.py` | 원문 구간 앵커와 엄격한 JSON 계약 |
| `extraction.py`, `candidate_ids.py`, `relation.py` | 짧은 인용과 원문 생성 후보 ID 추출, 관계 후보. 참조 정답은 입력하지 않음 |
| `transport.py`, `probe.py`, `run.py` | 두 출력 방식 소표본 비교, 로컬 모델 요청, 실행 환경 확인, 중단을 식별할 수 있는 저널과 비공개 원시 응답 저장 |
| `verify*.py` | 고정 커밋의 입력·코드와 원시 응답을 독립 검증하고 분모·오류·관계·경로를 집계 |

이 분리는 새 실험의 탐색 비용을 낮추기 위한 것이다. 과거 스크립트 61개를 즉시 옮기거나 줄이지는 않으므로 저장소 전체 파일 수나 총 줄 수가 줄었다는 주장은 하지 않는다.

## 원시 응답과 선택 절차

소표본 비교는 기존 노출 자료 RE03·RE06·RE09·V01·V04·V07을 두 방식으로 한 번씩 실행한다. 후보 ID는 발화 원문에서만 생성하며, 검수 E/B/C는 후보 생성에 쓰지 않고 후보 재현율을 별도 계산한다. 계약 통과, E/B/C 참조 일치, 후보 재현율, 지연 순으로 살펴본 뒤 전체 22건에 적용할 방식을 선택한다. 이 여섯 건은 후보 선택에 쓰인 개발 자료이므로 전체 실행 결과를 독립 평가로 부르지 않는다.

모델 원시 응답은 저장소 바깥의 소유자 전용 디렉터리(0700)와 파일(0600)에 저장한다. 공개 저널에는 응답 본문 대신 해시·바이트 수와 유한 상태만 둔다. 원시 응답은 결과 감사가 끝날 때까지 로컬에 보존하고, 그 이후 삭제 여부를 사용자가 결정한다. 원시 파일이 없으면 독립 검증기는 해시와 저널 상태만 검증했다고 명시한다.

## 현재 적용 범위

이번 구조 정리는 #78의 새 v2 추출 계약과 개발 참조 데이터부터 적용한다. 기존 결과를 더 좋게 보이도록 재계산하거나 실서비스 안전 가드를 교체하는 작업은 포함하지 않는다. 다른 제품의 위험 문구에도 현재 안전 가드가 반응하는 것은 확인된 동작이지만, 출처 관계를 구분하는 후보가 안전 게이트를 통과하기 전에는 운영 경로를 바꾸지 않는다.
