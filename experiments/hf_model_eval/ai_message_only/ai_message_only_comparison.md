# 4차 ai_message 전용 재테스트

## 1. 재테스트 목적

기존 4차 ai_message 전용 테스트에서는 LLM에게 완성 JSON을 생성하게 하지 않고, 병원 접수 직원의 자연어 응답인 `ai_message`만 생성하도록 했다.

그 결과 출력 안정성과 응답 속도는 크게 개선되었지만, 두 모델 모두 예약 가능 여부를 확정하는 표현이 포함되었다.

```text
Kanana 1.5:
"내일 오후에는 진료 예약이 가능합니다."

EXAONE:
"네, 가능합니다!"
```

따라서 재테스트에서는 예약 가능 여부를 확정하지 않도록 프롬프트를 강화했다.

---

## 2. 재테스트 프롬프트 개선 방향

이번 재테스트에서는 다음 조건을 강화했다.

```text
- 병원의 실제 예약 가능 여부는 아직 조회되지 않았다고 명시
- "가능합니다", "예약 가능합니다", "예약해드리겠습니다" 같은 표현 금지
- "확인해드리겠습니다", "원하시는 진료과", "알려주시면 확인해드리겠습니다" 중심으로 응답 유도
- JSON이 아니라 병원 접수 직원의 자연어 응답 문장만 출력
```

## 5. 모델별 재테스트 결과

### ① Kanana 1.5 2.1B Instruct

#### Generated Output

```text
네, 내일 오후에 진료 예약을 원하시는군요. 원하시는 진료과를 알려주시면 바로 확인해드리겠습니다.
```

#### Latency

```text
1.80s
```

#### 평가

| 항목 | 점수 | 메모 |
|---|---:|---|
| 예약 확정 방지 | 5/5 | 예약 가능 여부를 확정하지 않고 확인 흐름으로 응답함 |
| 병원 접수 말투 | 5/5 | 자연스럽고 공손한 접수 직원 말투에 가까움 |
| 다음 정보 요청 | 5/5 | 필요한 정보인 진료과를 자연스럽게 요청함 |
| 전화 공포증 배려 | 5/5 | 사용자의 요청을 먼저 받아주고 부드럽게 다음 정보를 요청함 |
| 응답 속도 | 5/5 | 1.80초로 충분히 빠름 |
| 출력 안정성 | 5/5 | JSON, markdown, 역할 이름 없이 자연어 응답만 출력함 |

#### 해석

Kanana 1.5 2.1B Instruct는 재테스트에서 가장 안정적인 결과를 보였다.

기존 테스트에서는 `"내일 오후에는 진료 예약이 가능합니다"`처럼 예약 가능 여부를 확정하는 표현이 있었지만, 개선 프롬프트에서는 이를 피하고 `"원하시는 진료과를 알려주시면 바로 확인해드리겠습니다"`라는 확인 중심 표현을 생성했다.

또한 사용자의 요청을 먼저 받아준 뒤 필요한 정보를 묻는 흐름이 자연스럽다.

#### 판단

```text
- Main ai_message candidate
- Best Korean phone response quality
- Suitable for FastAPI response assembly structure
```

### ② EXAONE-4.0-1.2B

#### Generated Output

```text
"확인해드리겠습니다. 어떤 진료과를 원하시는지 말씀해주시겠어요?"
```

#### Latency

```text
1.22s
```

#### 평가

| 항목 | 점수 | 메모 |
|---|---:|---|
| 예약 확정 방지 | 5/5 | 예약 가능 여부를 확정하지 않음 |
| 병원 접수 말투 | 4/5 | 의미는 자연스럽지만 Kanana보다 조금 덜 부드러움 |
| 다음 정보 요청 | 5/5 | 필요한 정보인 진료과를 정확히 요청함 |
| 전화 공포증 배려 | 4/5 | 짧고 명확하지만 Kanana보다 정서적 완충은 약함 |
| 응답 속도 | 5/5 | 1.22초로 매우 빠름 |
| 출력 안정성 | 4/5 | 자연어 응답만 출력했으나 앞뒤 따옴표가 포함됨 |

#### 해석

EXAONE-4.0-1.2B는 재테스트에서 예약 가능 여부를 확정하지 않고, 진료과를 묻는 방향으로 안정적인 응답을 생성했다.

응답 시간은 1.22초로 매우 빠르며, 속도 측면에서는 여전히 가장 강한 후보이다.

다만 출력에 따옴표가 포함되었고, 말투의 부드러움은 Kanana보다 약간 낮다. 따옴표는 서버 후처리로 쉽게 제거할 수 있다.

```python
ai_message = ai_message.strip().strip('"')
```

#### 판단

```text
- Keep as speed baseline
- Useful latency reference
- Needs simple post-processing for quotes
```

## 6. 4차 재테스트 결론

```text
4차 ai_message 전용 재테스트 결과, 예약 가능 여부 확정 표현을 금지하고 "확인해드리겠습니다" 중심으로 프롬프트를 조정하자 두 모델 모두 이전보다 안정적인 응답을 생성했다.

Kanana 1.5 2.1B Instruct는 병원 접수 직원 말투가 가장 자연스럽고, 전화 공포증 사용자를 배려하는 부드러운 흐름을 보였다.

EXAONE-4.0-1.2B는 응답 시간이 1.22초로 매우 빠르고 필요한 정보를 정확히 요청했지만, 출력에 따옴표가 포함되고 말투가 Kanana보다 조금 덜 부드러웠다.

따라서 이 실험에서는 Kanana 1.5를 생성 품질 후보로 평가하고, EXAONE은 속도 비교 기준으로 기록한다. 현재 운영 구조는 이 실험 이후 구조화 NLU와 도메인 응답 정책으로 변경되었다.
```

## 7. 최종 구조 판단

```text
LLM에게 완성 JSON 전체를 직접 생성하게 하는 방식보다,
LLM은 ai_message만 생성하고 FastAPI 서버가 최종 JSON을 조립하는 방식이 더 안정적이다.

최종 구조:
1. LangGraph 또는 서버 상태 머신이 conversation_state를 결정한다.
2. LLM은 현재 상태에 맞는 ai_message만 생성한다.
3. recommended_replies는 상태별 템플릿 또는 별도 추천 로직으로 생성한다.
4. should_end_call은 서버 로직으로 결정한다.
5. FastAPI가 최종 JSON을 조립한다.
```
